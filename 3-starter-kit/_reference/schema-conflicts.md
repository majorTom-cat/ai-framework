# 스키마·마이그레이션 = 동시 편집 충돌 자산 (왜·실측)

> 자동 로드 ❌. 참조 사슬: CLAUDE.md '스키마·데이터' 절 → `rules/migrations.md`(규칙 정본) → 이 파일. 규칙 명령문은 그쪽에, 근거는 여기.

## 마이그레이션은 전역 직렬 자산
모듈 소유로 못 막는다. 두 사람이 각자 브랜치에서 마이그레이션을 *동시에 생성*하면 나중 것이 앞 것을 몰라 스키마가 깨진다(벤더 공식 경고). → 만들 카드는 착수 전 팀 채팅 한 줄 공지(shared 변경 규칙과 동일), 머지는 생성 순서대로 직렬. 내 브랜치가 main보다 뒤처졌는데 새 마이그레이션이 main에 들어왔으면 내 마이그레이션을 최신 뒤로 재생성한다.

## 선언형 스키마 파일 (Prisma `schema.prisma`·Drizzle 등)
한 파일에 여러 모듈 정의가 모이는 ORM에서, 그 파일은 package-lock처럼 여러 사람이 동시에 고치는 공유 충돌 자산이다(2026-07 실측: 두 개발자가 각자 모델 추가 → git 충돌). → 일반 코드 충돌처럼 양쪽 정의를 합친 뒤 그 도구의 검증(`prisma validate`)으로 확인, 충돌이 잦으면 도구가 지원할 때 모듈별 스키마 파일로 분리.

- 반면 마이그레이션 *파일*은 날짜별 별도 파일이라 서로 안 겹친다(위 규칙과 구분).
- 충돌 뒤 DB가 어긋나 도구가 리셋을 요구하면 그건 되돌리기 어려운 파괴적 작업 = **사람이 실행**(AI 대행 금지 — 일부 도구는 AI 실행을 아예 차단).
