- «형식은 도구 기본과 맞춰라»: 규칙 형식(`YYYYMMDD_HHMMSS_`)과 Prisma 기본(`YYYYMMDDHHMMSS_`)이 달라 정렬이 깨진 사고가 bnsone #64·#65·#84 로 세 번 났다. 파일럿은 도구 기본을 채택해 무사고였다.
- «뽑아내는 명령의 함정 3개»(섀도 DB·빈 폴더·UTC): 2026-08-25 bnsone 실측.
- «`npx` 말고 로컬 바이너리»: 새 워크트리에서 `npx` 가 최신 RC 를 받거나 전역 CLI 가 가로채 «No command registered for …» 오류가 두 번 났다(2026-09-29 배포처 #365·#394).
- «불변 파일엔 카드 번호»: 병행 브랜치가 같은 ADR 번호(0076)를 잡아 나중 것이 옮기면서 인용 15곳을 함께 고쳐야 했다(2026-09-23 배포처 #311).
- «`.env` 를 못 읽으면 컨테이너에 물어라»: 짐작한 DB명으로 조회해 «빈 결과»를 «미적용»으로 읽을 뻔했다(2026-09-02 bnsone).
- «로컬 재적용까지가 한 작업»: /done 리뷰에서 이미 적용된 마이그레이션에 백필을 추가했더니 다음 카드에서 Prisma 가 reset 을 요구했다. 로컬만 깨지고 main 은 정상이라 원인 찾는 데 시간이 걸렸다(2026-08-28).
- «리셋 요구 전에 실제 차이를 재라»: 남이 머지 전에 주석 한 줄만 고친 파일을 옛 판으로 먼저 적용해 둔 경우가 같은 파일로 두 번 있었다(2026-09-09 #134 · 2026-09-10 #246). 체크섬만 맞추는 절차는 2026-08-14 bnsone 전례. `--exit-code` 의 0/2/1 의미는 Prisma 6.19 `--help` 로 확인했다.
- «현지 시각으로 자르기»: 같은 UTC 날짜 버그가 TS·SQL 두 층에서 따로 났다(2026-08-24 bnsone).
- «제약 재생성을 함께 써라»: bnsone 예약 테이블에서 EXCLUDE 제약이 재생성에서 빠져 DB 보장이 사라졌는데 앱은 멀쩡해 보였다.
- «착수 공지 = 조건부»: 옛 규칙은 착수 전 팀 채팅 공지를 무조건 요구했으나, 오너가 세 번 연달아 공지 없이 진행하기를 택했다. 규칙과 실행이 갈린 채 두지 않으려고 2026-08-31 오너 결정으로 «충돌을 직접 확인 → 깨끗하면 공지 생략 + 카드 기록»으로 바꿨다.
- «포매터가 선언형 자산을 재정렬»: `prisma format` 뒤 남의 모듈 3개가 diff 에 올라왔다(2026-09-01 bnsone).
- «표본 데이터는 게이트 변수 뒤에»: 로컬은 통과했는데 머지 CI 의 게이트 검사 잡에서 실패했다(bnsone #69).

## gitlab-cli.md
- 제목: 첫 사고는 bnsone #6(PowerShell 여러 줄 본문 인자 쪼개짐).
- «`</dev/null` 로 stdin 닫기»: Windows 에서 glab 이 출력 없이 8분 넘게 멈춘 일이 두 번 있었다(2026-07-29).
- «mac 엔 `timeout` 이 없다»: `command not found`(2026-09-01 bnsone).
- «루프 안에도 `</dev/null`»: 루프에서 빠뜨린 `glab mr create` 2건이 무음 실패했다(2026-08-04).
- «description 갱신엔 안 통한다»: `glab api --field "description=…"` 가 카드 본문을 빈 값으로 덮어써 복구했다(2026-09-01 bnsone).
- «워크트리·격리 세션에선 안전 패턴이 거부된다»: 2026-09-09 bnsone #235·#237 에서 두 번. 정본이 시키는 형태가 그 자리에선 못 쓰였다.
- «새 형식(`note create`)을 따르지 마라»: 2026-08-31 bnsone.
- «파이프·`;` 도 격리 안»: 2026-09-09 에는 첫 낱말이 `glab` 이면 통과했으나, 2026-09-28 킷 세션에서 `glab api user` 한 줄은 통과하고 `| head`·`> /dev/null; echo` 를 붙이면 둘 다 `OSStatus -26276` 이었다. 같은 날 스킬 머리 `!` 조회도 파이프 없이 같은 오류였고, 처음엔 VPN 탓으로 오진했다.
- «Monitor 안에서 glab 안 됨»: 같은 조회가 Monitor 안에서는 «조회실패», 한 줄로는 통과했다. 스크립트 파일 + 백그라운드 Bash 는 통과했다(2026-09-23).
- «`bash -c` 로 감싸지 마라»: `settings.local.json` 에 «파이프라인 4195»·«MR 424» 처럼 번호가 박힌 일회용 허용 줄 7개가 쌓여 있었다 — 그때그때 사람이 눌렀다는 흔적이다.
- «한 Bash 호출에 명령을 여러 개 잇지 마라»: 2026-09-10 배포처 세션 483개·Bash 14,857건을 재 보니 13,809건(93%)이 뭉치였고, 쓰였는데 허용 목록에 없는 낱말이 73개였다(`cut` 964 · `export` 758 · `sleep` 488 · `tr` 371 · `printf` 255 · `cp` 248 · `xargs` 105 · `ps` 59 …). 오너가 보낸 확인 창 사진 하나가 `… | cut -c1-140` 이었다.
- «장치가 되돌려 보낸다»(`bundle-guard.cjs`): 글로만 둔 이 규칙을 킷 세션이 하루 12번 어겨 2026-09-10 에 훅으로 바꿨다.
- «AI 는 자기 허가를 못 넓힌다»: 2026-09-10 오너가 허락했는데도 Bash·Edit 두 경로 다 판정기가 막았다.
