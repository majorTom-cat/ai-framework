# 킷동기 — 킷의 변경을 배포처로 옮기는 순서 (정본)

> 누가: 킷 세션이 보통 하고, 배포처 세션이 할 때도 있다. **어느 쪽이 하든 이 순서다.**
> 왜 이 문서가 생겼나: 동기 요령이 게이트(`/done` `함정.md` §2)·동기 검사기 머리·세션 메모에 흩어져 있어, 배포처가 같은 자리에서 두 번 헤맸다(2026-09-23 배포처 friction — `--3way` 전멸 · 이미 들어온 커밋 재적용).

## 1. 보낼 목록을 센다 — 두 번, 양쪽에서
- 킷에서 `bash 3-starter-kit/scripts/check-kit-sync.sh <배포처 경로>` — 배포처 `킷동기: <해시>` 뒤로 프레임워크 파일을 바꾼 킷 커밋 목록. 종료 2 = 판정 불능(«깨끗» 아님).
- ★**그 목록은 «후보»다 — 배포처에서 다시 세라**: `git -C <배포처> log origin/main --oneline --grep='킷동기'`. 킷이 준 4건 중 3건이 이미 배포처 main 에 있던 적이 있다(2026-09-23). 그대로 믿으면 들어온 것을 또 얹는다.
- ★**배포처 판을 킷으로 가져온 커밋**도 목록에 뜬다 — 두 파일의 `shasum` 이 같으면 보낼 것 없음(2026-09-28).
- 고치기 전에 **배포처가 같은 것을 이미 고쳤나** 먼저 본다 — 같은 날 두 번 중복 수리한 적이 있다(2026-09-28).

## 2. 자리 — 배포처의 «새 워크트리»에서
- 남의 클론의 HEAD 를 옮기지 마라(`CLAUDE.md` '세션 규칙'). `git -C <배포처> worktree add -b <브랜치> <새 폴더> origin/main`.
- 워크트리 추가·삭제, `push`·`fetch` 는 울타리 밖에서만 된다(`_reference/worktree.md`).

## 3. 붙이기 — 파일마다 셋 중 하나
| 배포처 판이… | 하는 일 |
|---|---|
| 지난 기준점의 킷 판과 같다 | **통째 복사**(순수 프레임워크 파일 — skills·rules·hooks·workflows·scripts·_reference) |
| 킷보다 앞서 있거나 현지화가 있다 | **킷 diff 만 얹는다**: `git -C <킷> diff <기준>..<새> -- 3-starter-kit/<파일> > 패치` → 배포처 워크트리에서 `git apply -p2 --reject 패치` → `.rej` 의 «킷이 더한 줄»만 손으로 얹고 `.rej` 삭제. **통째 복사 금지**(배포처 것이 사라진다) |
| `CLAUDE.md`·`.gitlab-ci.yml`·가이드 | 로직·구조만 맞추고 **그 repo 가 채운 값은 보존** |

- ★**`git apply --3way` 쓰지 마라** — 킷 커밋의 기준 blob 이 배포처 저장소에 없어서 파일이 통째로 «repository lacks the necessary blob» 으로 죽는다(2026-09-23: 19파일 전멸).
- ★**붙인 뒤 `bash scripts/check-skill-size.sh` 를 먼저 돌려라** — 킷 기준으로는 한도(5,376자) 안인데 배포처가 다른 줄을 현지화해 둬서 같은 변경이 더 길어진다(2026-10-07 bnsone: `/dev` 가 21자 초과). 넘으면 «새 줄»을 줄이지 말고 **그 줄 곁의 군더더기 괄호를 걷어** 맞춘다(킷이 fa86e2a 에서 그렇게 했다). `.rej` 는 현지화된 줄에서 나는 게 정상이다(같은 날 8파일 중 6곳).
- ★**누적 파일(`docs/friction.md` 류) 충돌은 정상이다**(양쪽이 맨 위에 더한다) — 합친 뒤 `python3 scripts/check-append-only.py <main 판 파일> docs/friction.md` 로 유실 0 을 확인하라(`_reference/append-only.md`). 배포처 `archive-friction.py` 는 동기 MR 에서 돌리지 마라 — 닫힘 표시만.

## 4. 커밋·MR
- 커밋 첫 줄 = `킷동기: <킷 해시>`(여러 개면 `·` 로 잇는다) — 동기 검사기의 기준점이다. 카드 면제(`CLAUDE.md` '작업 절차').
- ★**배포처에만 있는 게이트를 먼저 본다** — 그 repo `.gitlab-ci.yml` 잡 목록. bnsone 은 `change-summary` 가 **마지막 커밋**에 `달라지는 것:` 블록을 요구한다(불릿 한 줄씩 · 올리기 전 `bash scripts/extract-change-summary.sh < 메시지파일`). 빠졌으면 **새 커밋 하나 추가**(force push 금지).
- `.claude/**`·`CLAUDE.md` 를 건드리면 `셀프승인` 라벨을 **MR 생성 인자**로 넣는다(라벨은 파이프라인 «생성» 시점에 읽힌다 — `/done` `함정.md` §2). 스킬을 옮기면 `skill-size` 한도도 같이 돈다.
- 머지 뒤 1절의 검사기를 다시 돌려 남은 것이 «의도한 것»뿐인지 본다. 워크트리는 지운다.
