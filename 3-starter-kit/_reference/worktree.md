# 동시 두 이슈 = 이슈별 워크트리 — 레시피·주의

> 자동 로드 ❌. CLAUDE.md '세션 규칙'이 가리킨다. 원칙(같은 클론에 세션 둘 금지, 트리마다 자기 포트·DB)은 CLAUDE.md에, 절차는 여기.

## 레시피 — ★네 걸음을 다 밟아야 «따로 도는 트리»가 된다
1. `git worktree add ../issue-13 -b feature/13-슬러그 origin/main` (본 클론의 HEAD 를 안 건드리려면 base 를 `origin/main` 으로 명시)
2. **의존성은 그 트리에 «설치»한다 — 링크하지 마라**(아래 주의). 설치 뒤 ORM 생성물 재생성(`npx prisma generate` 류). 대략 1~2분.
   - ★`npm ci` 는 **캐시 경로를 고정해서** 줘라(`--cache ~/.npm-cache-worktree` 류) — 공유 캐시가 root 소유라 죽고, 안내가 권하는 `sudo chown` 은 AI 가 못 친다. `$TMPDIR` 은 호출마다 바뀌어 **매번 빈 캐시**가 된다. 생성 명령이 `EPERM … .cache/…` 로 죽으면 **그 명령만** 울타리를 풀어라.
3. **전용 DB — 이 걸음을 빠뜨리면 남의 데이터를 지운다.** 세 곳을 다 바꿔야 한다:
   - `.env` 의 **포트와 접속 URL 둘 다**(둘 중 하나만 고치면 URL 쪽이 이겨서 공용 DB 를 가리킨다)
   - 컨테이너도 **다른 이름으로** 띄운다(`docker compose -p issue-13 up -d db` 류) — 안 그러면 같은 컨테이너를 공유한다
   - 그 DB 에 **마이그레이션 적용**(`npx prisma migrate deploy` 류). 새 DB 는 비어 있다
   - 정한 포트·DB명을 `CLAUDE.local.md` 에 적어 둔다(다음 트리가 같은 번호를 안 쓰도록)
   ⚠️**왜 이렇게까지 하나**: 테스트 준비 단계가 흔히 «시험용 DB 를 지우고 다시 만든다»로 시작한다 — 공용 DB 를 가리킨 채 돌리면 **다른 세션의 시험용 DB 가 통째로 사라진다**(2026-09-10 실측).
4. 그 폴더에서 `claude -n issue-13` → 끝나면 **링크를 먼저 지우고**(`rm node_modules`) `git worktree remove ../issue-13`. 순서를 바꾸면 **링크 대상(본 클론 의존성)까지 지워질 수 있다**(아래 Windows 주의).

★**본 클론을 다른 세션이 쓰는 중이면 «pull 로 따라잡기»가 아니라 이 레시피가 정답이다.** 맨 `git pull`·`git merge` 는 병합 커밋을 만들 수 있어 남의 발밑에서 HEAD 를 옮긴다 — 훅이 확인 창을 세운다. 따라잡기만 필요하면 **`git pull --ff-only origin main`**(그러면 훅이 무음이다).

## 주의
- ★★★**워크트리 세션에서는 `cd` 를 쓰지 마라 — 절대경로로 지목하라.** 워크트리 «밖» 폴더(임시 폴더 등)로 `cd` 했다가 나오면 **작업 폴더가 본 클론으로 되돌아온다**(하네스가 「더 이상 워크트리가 아니다」로 알려 주지만, 그 뒤 상대경로 명령은 **남의 트리를 친다**). 2026-09-09 실측(bnsone #244): 알림을 받고도 경로 앞부분을 그대로 써서 **본 클론 파일을 편집**했다 — 조회로 발견해 `git checkout -- <파일>` 로 원복했다. 「워크트리로 나눠 서로 안 부딪히게 한다」는 규칙이 이 한 수에 통째로 무너진다.
- ★★**의존성 폴더(`node_modules` 등)를 본 클론에서 «링크»할지는 «모르면 링크하지 마라»** — 자기 것을 깔아라. 「스키마를 안 건드리는 트리면 링크해도 된다」로 갈라 놓으면 **그 판단이 너무 이르다**: 스키마를 바꿀지는 `/dev`·`/fix` 1단계에서 카드를 읽어야 나오고, 인계가 틀릴 수도 있다(2026-09-09 실측: 「DB 변경 불필요」라는 인계를 믿고 링크했는데 칸 추가가 필요했다). **링크한 채 코드 생성 명령(`prisma generate` 류)을 누르면 본 클론이 조용히 오염된다** — 그 클론에서 다른 세션이 돌고 있으면 그대로 남의 작업을 깬다. **왜 오염되나**: 스키마에 `output` 지정이 없으면 생성물이 `node_modules` 안으로 들어가 **본 클론의 클라이언트를 내 브랜치 것으로 덮어쓴다.** 뒤늦게 드러나면 **생성 «전»에 링크부터 끊어라** — 확인법은 `grep -c {새칸이름} {본클론}/node_modules/.prisma/client/index.d.ts`(그 repo 의 생성물 경로).
- **Windows는 최신 Claude Code 필수** — 구버전은 워크트리 삭제 시 링크 대상이 지워지는 버그. ⚠️**`ln -s` 도 Windows cmd/PowerShell 엔 없다** — 거기선 링크를 쓰지 말고 `npm ci` 로 자기 의존성을 깔아라.
- ★**`.env` 를 복사해 둬도 테스트 실행기가 그것을 안 읽을 수 있다**(vitest 실측: `DATABASE_URL 이 없다` 로 죽는다) — 접속을 **명령에 직접** 주되 **반드시 이 트리의 DB 를 가리켜라.** 준비 0단계가 그 서버의 시험용 DB 를 전부 DROP 하므로, **본 클론 포트를 복붙하면 옆 세션의 실행이 깨진다.** 형태의 정본 = 그 repo `CLAUDE.md` '실행·테스트'.
- 새 워크트리는 별도 폴더라 `/todo`·`/dev`·`/fix` 등 스킬이 그 폴더에서 **최초 1회 신뢰 확인**을 물을 수 있다 — "don't ask again for … in {폴더}"를 고르면 그 트리에선 다시 안 묻는다(정상 동작, 막힌 것 아님).
