# 동시 두 이슈 = 이슈별 워크트리 — 레시피·주의

> 자동 로드 ❌. CLAUDE.md '세션 규칙'이 가리킨다. 원칙(같은 클론에 세션 둘 금지, 트리마다 자기 포트·DB)은 CLAUDE.md에, 절차는 여기.

## 레시피
1. `git worktree add ../issue-13 -b feature/13-슬러그`
2. 그 폴더에서 `claude -n issue-13`
3. `CLAUDE.local.md`에 이 트리 전용 포트·DB명 기록 (안 그러면 두 세션이 같은 포트·DB를 무음으로 덮어쓴다)
4. 끝나면 `git worktree remove ../issue-13`

## 주의
- ★★★**워크트리 세션에서는 `cd` 를 쓰지 마라 — 절대경로로 지목하라.** 워크트리 «밖» 폴더(임시 폴더 등)로 `cd` 했다가 나오면 **작업 폴더가 본 클론으로 되돌아온다**(하네스가 「더 이상 워크트리가 아니다」로 알려 주지만, 그 뒤 상대경로 명령은 **남의 트리를 친다**). 2026-09-09 실측(bnsone #244): 알림을 받고도 경로 앞부분을 그대로 써서 **본 클론 파일을 편집**했다 — 조회로 발견해 `git checkout -- <파일>` 로 원복했다. 「워크트리로 나눠 서로 안 부딪히게 한다」는 규칙이 이 한 수에 통째로 무너진다.
- ★★**의존성 폴더(`node_modules` 등)를 본 클론에서 «링크»할지는 «모르면 링크하지 마라»** — 자기 것을 깔아라. 「스키마를 안 건드리는 트리면 링크해도 된다」로 갈라 놓으면 **그 판단이 너무 이르다**: 스키마를 바꿀지는 `/dev`·`/fix` 1단계에서 카드를 읽어야 나오고, 인계가 틀릴 수도 있다(2026-09-09 실측: 「DB 변경 불필요」라는 인계를 믿고 링크했는데 칸 추가가 필요했다). **링크한 채 코드 생성 명령(`prisma generate` 류)을 누르면 본 클론이 조용히 오염된다** — 그 클론에서 다른 세션이 돌고 있으면 그대로 남의 작업을 깬다. 뒤늦게 드러나면 **생성 «전»에 링크부터 끊어라.**
- **Windows는 최신 Claude Code 필수** — 구버전은 워크트리 삭제 시 링크 대상이 지워지는 버그.
- 새 워크트리는 별도 폴더라 `/todo`·`/dev`·`/fix` 등 스킬이 그 폴더에서 **최초 1회 신뢰 확인**을 물을 수 있다 — "don't ask again for … in {폴더}"를 고르면 그 트리에선 다시 안 묻는다(정상 동작, 막힌 것 아님).
