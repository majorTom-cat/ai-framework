# 스킬 effort·model 배정 기준 (2026-08-08)

> 자동 로드 ❌. 스킬 frontmatter의 `effort:`·`model:` 주석이 이 파일을 가리킨다. 목적: **누가 어떤 세션 설정으로 돌리든 위험 스킬은 같은 품질 바닥을 갖게** — 스킬 턴 동안만 적용되고 다음 턴에 세션 값으로 원복된다(공식: code.claude.com/docs/en/skills.md).

## 배정 원칙 3줄
1. **결과 게이트(CI·테스트·승인·증적)가 품질의 정본**이다 — effort/model은 "시도의 바닥"을 올리는 보조 수단. 게이트 없는 품질을 이걸로 대신하려 하지 마라.
2. **실패 비용 × 판단 밀도**로 등급을 정한다. 절차 나열·조회형은 올려봤자 비용만 든다.
3. `model:`은 **fail-soft**(조직 allowlist에 없으면 무시 → 세션 모델 유지)라 안전하지만, 그래서 **산문 소프트 플로어("경량이면 멈춰라")가 백스톱으로 반드시 동반**돼야 한다. 모델명 대신 별칭(opus)만 쓴다 — 전체 ID는 썩는다.

## 배정표
| 등급 | 스킬 | 근거 |
|---|---|---|
| `model: opus` + `effort: xhigh` | design | 되돌리기 가장 어려운 결정(스택·ERD·모듈 경계) |
| `model: opus` + `effort: high` | scaffold | 이후 전부의 토대 — 골격 실수는 전면 재작업 |
| `effort: high` | done | 머지·게이트 판단·수용기준 1:1 대조 — 실수=사고 |
| `effort: high` | adr · change | 비가역 결정 기록 · 요구 변경 영향 분석 |
| `effort: high` | ui | 시안 다양성·완성도(창의 판단 밀도) |
| `effort: high` | overhaul | 전 문서 횡단 판정 — 놓친 드리프트가 다음 세션의 정본이 된다. **model 미강제는 의도**(상위 모델 세션을 끌어내리지 않기 위해) — 본문 소프트 플로어가 백스톱 |
| (미지정 = 세션 값) | dev · fix · module · docs · inspect · card · setup-gitlab · metrics · start · todo | 게이트가 백스톱이거나 절차·조회형. **todo는 low 금지** — 고위험 승인 대행 경로가 있다 |
| `effort: low` | log · assign-module | 조회 요약·표 갱신 — 판단 밀도 낮음, 비용 절감 |

## 병렬·독립성은 여기 아니라 본문 조건으로
"에이전트 N명" 같은 수 지정은 환경(한도·러너)에 따라 못 지킨다 — 대신 **성립 조건**을 본문에 박는다(이미 있음): /done "리뷰는 fresh context 필수", 고위험 "작성자 아닌 눈"+증적 3종, /ui "시안 2~3안". 새 스킬도 같은 방식으로.

## 바꿀 때
등급 변경은 이 표와 frontmatter를 **같은 커밋**에서 — 표만 고치면 frontmatter가 정본 행세를 한다. 3배포처(킷·파일럿·bnsone) 동일 유지(스킬 sync 규칙).
