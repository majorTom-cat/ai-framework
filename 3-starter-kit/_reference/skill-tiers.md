# 스킬 effort·model 배정 기준 (2026-08-08 · 2026-09-08 개정)

> 자동 로드 ❌. 스킬 frontmatter의 `effort:`·`model:` 주석이 이 파일을 가리킨다. 목적: **누가 어떤 세션 설정으로 돌리든 위험 스킬은 같은 품질 바닥을 갖게** — 스킬 턴 동안만 적용되고 다음 턴에 세션 값으로 원복된다(공식: code.claude.com/docs/en/skills).

## 배정 원칙 4줄
1. **결과 게이트(CI·테스트·승인·증적)가 품질의 정본**이다 — effort/model은 "시도의 바닥"을 올리는 보조 수단. 게이트 없는 품질을 이걸로 대신하려 하지 마라.
2. **실패 비용 × 판단 밀도**로 등급을 정한다. 절차 나열·조회형은 올려봤자 비용만 든다.
3. `model:`은 **fail-soft**(조직 allowlist에 없으면 무시 → 세션 모델 유지)라 안전하지만, 그래서 **산문 소프트 플로어("경량이면 멈춰라")가 백스톱으로 반드시 동반**돼야 한다 — 정본은 CLAUDE.md '모델·effort 소프트 플로어' 한 곳(스킬 본문에 재서술 금지. 플로어가 더 높은 `/overhaul`만 예외로 그 스킬에 한 줄). 모델명 대신 별칭(opus)만 쓴다 — 전체 ID는 썩는다.
4. ★**`effort:`도 «최소»가 아니라 «덮어쓰기»다 — 3번과 같은 함정**(공식 문구: "Overrides the session effort level"). 그래서 **핀은 «기본값과 다른 값을 일부러 쓸 때»만 박는다.** 바닥을 올리는 일은 핀이 아니라 산문 플로어가 한다.

## 왜 `effort: high` 핀을 다 뺐나 (2026-09-08)
- **API·세션 기본값이 `high`다.** 그래서 `high` 핀은 **기본 세션에 아무 효과가 없다** — 6개 스킬(scaffold·done·adr·change·ui·overhaul)에 박혀 있었지만 값을 바꾸는 일이 없었다.
- **효과가 나는 유일한 경우가 «끌어내리는» 쪽이었다.** 어려운 카드라 세션을 `xhigh`로 올려 두면, 그 스킬에 들어가는 순간 `high`로 **도로 내려간다.** 킷은 `model:`에 대해 바로 이 이유로 핀을 안 박기로 했는데(DD-05 "「최소」가 아니라 「고정」"), `effort:`에는 같은 논리를 적용하지 않고 있었다.
- **바닥이 필요 없어진 게 아니다** — 옮겼을 뿐이다. CLAUDE.md '모델·effort 소프트 플로어'가 `medium` 이하 세션을 시작 전에 세운다. 이 방식은 낮은 세션은 올리면서 높은 세션은 안 건드린다.
- **같은 개정에서 `/dev`·`/fix`가 플로어 안으로 들어왔다.** 종전엔 "게이트가 백스톱"이라며 빠져 있었는데, 게이트는 «통과했나»를 볼 뿐 «코드가 좋은가»를 보지 않는다. 공식 권고도 effort를 올릴 값어치가 가장 큰 곳으로 «까다로운 코딩·에이전트 작업»을 꼽는다(Opus 5 기준).

## 배정표
| 등급 | 스킬 | 근거 |
|---|---|---|
| `model: opus` + `effort: xhigh` | design | 되돌리기 가장 어려운 결정(스택·ERD·모듈 경계). **기본값보다 올리는 핀** — 저빈도(프로젝트당 1~3회)라 비용이 문제되지 않는다 |
| `model: opus` | scaffold | 이후 전부의 토대 — 골격 실수는 전면 재작업. effort는 산문 플로어에 맡긴다 |
| `effort: low` | log · assign-module | 조회 요약·표 갱신 — 판단 밀도 낮음. **기본값보다 내리는 핀**(비용 절감) |
| (핀 없음 = 세션 값 + 산문 플로어) | dev · fix · done · scaffold · adr · change · ui · overhaul | 판단이 무겁다 — 세션 effort가 `medium` 이하면 시작 전에 멈추고 `/effort high` 안내(정본 = CLAUDE.md). `/overhaul`은 모델 플로어가 더 높아 본문에 한 줄 추가 |
| (핀 없음 = 세션 값) | module · docs · inspect · card · setup-gitlab · metrics · start · todo | 게이트가 백스톱이거나 절차·조회형. **todo는 low 금지** — 고위험 승인 대행 경로가 있다 |

## 병렬·독립성은 여기 아니라 본문 조건으로
"에이전트 N명" 같은 수 지정은 환경(한도·러너)에 따라 못 지킨다 — 대신 **성립 조건**을 본문에 박는다(이미 있음): /done "리뷰는 fresh context 필수", 고위험 "작성자 아닌 눈"+증적 3종, /ui "시안 2~3안". 새 스킬도 같은 방식으로.

## 바꿀 때
등급 변경은 이 표와 frontmatter를 **같은 커밋**에서 — 표만 고치면 frontmatter가 정본 행세를 한다. 3배포처(킷·파일럿·bnsone) 동일 유지(스킬 sync 규칙).
★**핀을 새로 박기 전에 «기본값과 다른가»를 먼저 물어라** — 같으면 그 핀은 무효거나 남을 끌어내리기만 한다.
