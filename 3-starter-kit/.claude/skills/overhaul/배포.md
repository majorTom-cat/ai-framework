# /overhaul 갈래 C — 배포·서버 실물 감사 (0단계에서 "배포"를 고른 뒤 읽는다)

> **정본**: 저장소의 매니페스트·CI 정의·인프라 문서가 기준이고, **서버 실물은 대조 대상**이다. 어긋나면 어느 쪽이 사실인지 표에 적는다.
> ⚠️⚠️ **조회 전용 갈래다.** `apply`·`patch`·`delete`·`scale`·`restart`·시크릿 변경 등 **상태를 바꾸는 명령은 어떤 이유로도 실행하지 마라** — 관리자(사람) 몫이고, 감사 세션이 고치면 아무도 모르는 변경이 된다. 산출물은 진단표와 **카드**뿐.
> 전제: 사내 서버는 VPN 선행(`vpnon`) — 안 되면 그 자리에서 멈추고 보고. 클러스터 조회는 `ssh <서버> kubectl get ...` 형태(로컬에 kubectl이 없어도 된다).

## 대조 4쌍 — 묶음마다 fresh-context 서브에이전트 1개(병렬)
1. **매니페스트 ↔ 실물 리소스**: repo의 `k8s/`(또는 배포 디렉터리)에 정의된 Deployment·CronJob·Service·Ingress·ConfigMap·Secret **이름과 개수**를 뽑아, 실물 `kubectl get -o name`(네임스페이스별)과 대조. **정의에만 있는 것**(배포 안 됨)과 **실물에만 있는 것**(손으로 만든 유령)을 양방향으로 찾는다.
2. **CI 권한(ci-rbac) ↔ 매니페스트가 요구하는 리소스 유형**: 새 리소스 유형이 추가됐는데 배포 잡의 권한(Role/RoleBinding)이 그 유형을 못 다루면 **배포가 연쇄 실패한다**(2026-08-13 실사고 — CronJob 추가·권한 누락). 매니페스트의 `kind` 집합 ⊆ rbac의 `resources` 인지 확인.
3. **파이프라인 정의 ↔ 최근 실행 사실**: `glab api "projects/:id/pipelines?ref=main"` 최근 20건에서 **실패·취소·건너뜀이 반복되는 잡**을 찾는다. `allow_failure` 로 초록 뒤에 숨은 실패, 오래 `manual` 로 방치된 잡, 아무도 안 보는 스케줄 파이프라인이 표적이다.
4. **문서 서술 ↔ 실물**: 가이드·HANDOFF·README가 말하는 도메인·URL·계정·경로·**토큰 만료일**이 지금도 사실인지(예: 게이트 토큰 만료 → 방치하면 게이트가 조용히 fail-open). 응답 코드까지 확인(`curl -sI`), 추측 금지.

각 발견에 **증거(명령 + 출력 요지 한 줄)** 필수. "일치함"도 **대조한 항목 목록**과 함께 보고한다(0건 ≠ 안 봄).

## 종합표 → ⏸ 게이트 → 카드
| 대조쌍 | 진단(증거) | 어느 쪽이 사실인가 | 제안 | 사람 손 필요? |
- **사람 손이 필요한 항목**(관리자 `apply`·시크릿 교체·토큰 재발급·권한 부여)은 별도 묶음으로 모아 **무엇을·어디서·어떤 명령으로** 인지 그대로 적는다 — 그게 이 감사의 실제 산출물이다.
- 항목별 OK 후 `/card` 발행(인프라 카드는 화면이 없으니 **셀프 완료 경로** — `/done` 8단계). 토큰 만료처럼 **기한이 있는 것은 카드 제목에 날짜**를 넣는다.
