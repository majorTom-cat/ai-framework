# /overhaul 갈래 B — 코드 감사 (0단계에서 "코드"를 고른 뒤 읽는다)

> **정본**: 판정 기준은 이 repo의 `docs/`(요구·설계)·`docs/adr/`·`rules/module-*.md`(소유·경계)·`CLAUDE.md`다. 코드가 아니라 **문서가 기준**이다 — 어긋나면 어느 쪽이 틀렸는지도 함께 판정한다.
> ⚠️ **이 갈래는 코드를 고치지 않는다.** 산출물은 진단표와 **카드**다(수리는 `/fix`·`/dev`가 카드를 받아서). 감사 세션이 바로 고치면 카드 없는 코드 변경 = 규율 위반이고, 감사 범위가 수리 범위로 조용히 번진다.

## 1. 지도 먼저
- `git ls-files`로 대상을 **모듈 단위로 묶는다**(`src/modules/*` + `shared`/공통 + 설정·인프라 파일). 묶음마다 **"이 모듈의 정본 문서가 무엇인지" 한 줄**(요구 문서 절·ADR 번호·소유자)을 적는다 — 정본을 모르면 어긋남을 판정할 수 없다.
- 모듈 지도가 있으면 먼저 만들어 에이전트에 함께 준다: `node scripts/check-boundaries.cjs --map` → `src/modules/_MODULE_MAP.md`(공개 함수·의존·사용처·소유 DB 모델). 없으면 생략하고 진행.

## 2. 병렬 감사 — 묶음마다 fresh-context 서브에이전트 1개
각 에이전트에 같은 서식으로 지시한다. **배정 파일을 전부 실제로 열고**(요약·목차 스킵 금지) 5종만 수거, 각 발견에 **파일:줄 증거** 필수:
1. **문서↔구현 어긋남** — 요구 문서·ADR·설계와 실제 동작이 다른 것(수용 기준이 코드로 지켜지지 않는 것 포함). 어느 쪽이 낡았는지 의견 한 줄.
2. **죽은 것** — 쓰이지 않는 export·라우트·플래그·env·마이그레이션 잔재.
3. **중복** — 같은 로직이 두 모듈에 (=`shared` 승격 후보). 복붙 흔적은 파일:줄 두 곳을 나란히.
4. **경계 위반** — 모듈 간 직접 import·타 모듈 DB 모델 접근·`shared`가 모듈을 역참조.
5. **위험 지점** — 입력 검증 없는 경계·권한 검사 누락·트랜잭션 없는 다중 쓰기. (보안 전수 점검은 이 스킬 밖 — `/security-review`로 안내)

★**판정 함정**: `grep` 0건은 "안 쓰인다"의 증거가 아니다(동적 호출·문자열 키·설정 파일 참조) — **죽음 판정은 호출부 전수 grep + 라우트·설정·CI까지 확인한 뒤에만**. 확신이 없으면 "의심"으로 올린다. "문제 없음"도 **연 파일 목록**과 함께 보고한다(0건 ≠ 안 봄).

## 3. 종합표
| 파일:줄 | 진단(증거) | 유형(어긋남·죽음·중복·경계·위험) | 제안 | 위험도·근거 |
- 겹치는 발견은 합치고, **파괴적 제안(삭제·이동·통합)은 본 세션이 그 파일을 직접 열어 재확인한 뒤에만** 표에 올린다 — 에이전트 요약은 증거가 아니다.
- **문서 쪽이 낡은 것**으로 판정된 항목은 갈래 A(문서)나 `▶ /change`(요구 변경)·`/adr`(결정 대체)로 넘긴다 — 코드를 문서에 맞춰 고치는 게 항상 정답은 아니다.

## 4. ⏸ 게이트 — 항목별 OK (본문 4단계와 동일)

## 5. 실행 = 카드 발행
- OK 받은 항목만 `/card` 규약대로 발행한다: 제목·현상·증거(파일:줄)·수용 기준, **모듈 라벨**, 고위험 유형이면 `고위험`. 카드 하나에 한 덩이 — "감사 지적 12건" 같은 뭉텅이 카드는 만들지 마라(담당·검수가 갈린다).
- 한 줄짜리 사소한 것들만 **한 카드로 묶어 `/fix`** 로 넘길 수 있다(묶음 사유를 카드에 적는다).
- 보고에 **발행한 카드 번호 목록**과 발행하지 않기로 한 항목(사유)을 함께 남긴다.
