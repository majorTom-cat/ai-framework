# /overhaul 갈래 B — 코드 감사 (0단계에서 "코드"를 고른 뒤 읽는다)

> **정본**: 판정 기준은 이 repo의 `docs/`(요구·설계)·`docs/adr/`·`rules/module-*.md`(소유·경계)·`CLAUDE.md`다. 코드가 아니라 **문서가 기준**이다 — 어긋나면 어느 쪽이 틀렸는지도 함께 판정한다.
> ⚠️ **이 갈래는 코드를 고치지 않는다.** 산출물은 진단표와 **카드**다(수리는 `/fix`·`/dev`가 카드를 받아서). 감사 세션이 바로 고치면 카드 없는 코드 변경 = 규율 위반이고, 감사 범위가 수리 범위로 조용히 번진다.
> ★**절차 근거는 실측이다** — 2026-08-19 bnsone 첫 전수 감사(에이전트 7 병렬, 발견 40여 건 → 추적 카드 3장 #120·#121·#122)에서 통한 것만 아래에 남겼다.

## 1. 기계 검사부터 — 사람 판단은 그 뒤
`npm run typecheck`·테스트·`npm run boundaries`·시크릿 스캔 등 **이 repo가 이미 가진 검사를 먼저 돌려 초록/빨강을 확보**한다(초록이면 "품질이 좋다"가 아니라 **"기계가 볼 수 있는 층은 깨끗하다"**로만 적어라 — 8-19 감사의 결론 1번이 정확히 그 형태였다). 모듈 지도가 있으면 함께 만든다: `npm run boundaries -- --map` → `src/modules/_MODULE_MAP.md`(스테일이면 그 사실 자체가 발견 1건).

## 2. 병렬 감사 — 축을 둘로 섞는다(모듈 + 횡단)
묶음마다 fresh-context 서브에이전트 1개. **모듈 축만으로 나누면 인증·스키마 같은 횡단 결함을 아무도 안 본다**(8-19 실측: 심각도 상위 발견 3건이 전부 횡단 축에서 나왔다).
- **모듈 축**: `src/modules/*` + `shared` — 모듈당 1명(작은 모듈은 묶어도 된다).
- **횡단 축(고정 4)**: ①**인증·인가**(세션·권한 가드·차단·비밀번호 정책) ②**스키마·마이그레이션**(선언형 스키마 ↔ 마이그레이션 누적 상태 기계 대조·불변 규칙·인덱스·시드 멱등성)
  ③**규칙↔실측**(CLAUDE.md·rules·훅·CI가 말하는 것이 실제와 같은가 — 아래 고정 대조 3종) ④**ADR·설계↔코드**(채택된 결정이 코드에 있는가, 폐기된 것이 살아 있는가).

각 에이전트에 같은 서식으로 지시한다. **배정 파일을 전부 실제로 열고**(요약·목차 스킵 금지) 5종만 수거, 각 발견에 **파일:줄 증거** 필수:
1. **문서↔구현 어긋남** — 요구·ADR·설계와 실제 동작이 다른 것(수용 기준이 코드로 안 지켜진 것 포함). 어느 쪽이 낡았는지 의견 한 줄.
2. **죽은 것** — 쓰이지 않는 export·라우트·플래그·env·마이그레이션 잔재.
3. **중복** — 같은 로직이 두 모듈에(=`shared` 승격 후보). 파일:줄 두 곳을 나란히.
4. **경계 위반** — 모듈 간 직접 import·타 모듈 DB 모델 접근·`shared`가 모듈을 역참조.
5. **위험 지점** — 권한 검사 누락·입력 검증 없는 경계·트랜잭션 없는 다중 쓰기·**말없이 잘리는 상한**(목록 `take`·페이징 없음 — 8-19에 3건 나왔다). 인증·인가 축이 이 5번을 정면으로 맡는다(`/security-review`는 diff 기준이라 전수를 대신하지 못한다).

★**규칙↔실측 축의 고정 대조 3종**(전부 2026-08-19 실측에서 어긋난 적이 있다):
- **훅 ↔ CI ↔ 회귀 테스트 경로 = 한 몸** — `check-push.sh`의 `HITS` · `.gitlab-ci.yml` `high-risk-gate`의 `changes:` · 회귀 테스트의 `CHECKER`는 **셋이 1:1이어야 한다**(정본 선언은 훅 주석). 셋 중 하나만 고치면 게이트가 조용히 헛돈다 — CI에만 경로를 추가하면 이중화의 앞단이 비고, 검사기 이름만 바꾸면 훅·테스트가 없는 파일을 가리킨다.
  (짓거나 이름을 바꾸는 **그 순간**의 지침은 `/scaffold` 4단계. 여기는 **정기 대조** 몫이다.)
- **모듈 소유 3자** — CLAUDE.md 소유 표의 행 ↔ `.claude/rules/module-*.md` 실물 ↔ GitLab 모듈 라벨. 표엔 있는데 규칙 파일이 0개면 `/start`·`/assign-module`·`/dev`가 없는 파일을 읽으라고 지시하는 상태다(`/module`로 생성).
- **문서가 열거한 CI 초록불 목록 ↔ `.gitlab-ci.yml` 실물** — 잡을 추가·개명하고 문서를 안 고치면 "무엇이 통과해야 하는지"의 정본이 둘로 갈린다.
  ★**MR에서 도는 잡만 세라** — `rules:`가 `main` 전용인 배포 잡을 '차단 잡'으로 세면 없는 결함을 만든다(2026-08-26 시험 운전에서 오탐 직전까지 갔다).

★**판정 함정**: `grep` 0건은 "안 쓰인다"의 증거가 아니다(동적 호출·문자열 키·설정 파일 참조) — **죽음 판정은 호출부 전수 grep + 라우트·설정·CI까지 확인한 뒤에만**. 확신 없으면 "의심"으로 올린다. "문제 없음"도 **연 파일 목록과 함께** 보고한다(0건 ≠ 안 봄).

## 3. 진척 현황도 함께 센다 — "있는 것의 결함"만 보면 절반이다
숫자로 표를 만든다: 모듈별 **코드량 ↔ 사용자 화면 수**(화면 0인 모듈이 진짜 위험) · 1차 요구 목록 대비 **카드조차 없는 요구**(추정임을 명시) · 열린 카드의 담당자 배분.
★**세는 법을 먼저 실물로 확인하라** — 확장자(.ts/.js)와 화면 위치(App Router `page.tsx`·별도 서버·템플릿)는 스택마다 다르다. 가정하고 세면 전 모듈 0줄 같은 숫자가 나온다(2026-08-26 시험 운전 실측). 8-19 감사의 결론 2번("만든 것이 규칙·데이터에 몰려 있고 화면이 거의 없다")은 이 표에서만 나온다.

## 4. 종합표
| 파일:줄 | 진단(증거) | 유형(어긋남·죽음·중복·경계·위험) | 제안 | 위험도·근거 |
- 겹치는 발견은 합치고, **파괴적 제안(삭제·이동·통합)은 본 세션이 그 파일을 직접 열어 재확인한 뒤에만** 표에 올린다 — 에이전트 요약은 증거가 아니다.
- **문서 쪽이 낡은 것**은 갈래 A(문서)나 `▶ /change`·`/adr`로 넘긴다 — 코드를 문서에 맞춰 고치는 게 항상 정답은 아니다.
- 보고 서식: **①결론 3줄 ②지금 막고 있는 것(검수·보안) ③모듈별 상세 ④0건 증명**. 오너는 ①②만 읽어도 결정할 수 있어야 한다.
- ★**비밀값 원문을 보고서·카드에 옮기지 마라** — 위치와 조치만(`glab api ... variables`에서 마스킹 꺼짐 등). 감사 산출물이 새 유출 경로가 된다.

## 5. ⏸ 게이트 — 항목별 OK (본문 4단계와 동일)

## 6. 실행 = 카드 발행
- **발견이 10건을 넘으면 영역별 "추적 카드"**로 묶는다(8-19 실측 형태): 영역당 1장, 발견마다 **체크박스 한 줄 + 파일:줄 증거를 카드 본문에 옮겨 적어** 원 보고서 없이도 착수 가능하게. 카드 머리에 "각 항목은 처리하거나 별도 카드로 쪼개고, 결과를 댓글로 남긴 뒤 닫는다"를 명시.
- 큰 항목(화면 신설·설계 변경)은 처음부터 **독립 카드**로. 고위험 유형이면 `고위험`, 모듈 라벨은 항상.
- 보고에 **발행한 카드 번호**와 발행하지 않기로 한 항목(사유)을 남긴다. 긴 원 보고서는 repo 밖 로컬 파일로 두고 카드에서 경로를 가리킨다(민감정보가 섞이므로 커밋하지 않는다).
