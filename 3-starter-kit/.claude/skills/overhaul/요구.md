# /overhaul ④요구 갈래 — «1차 요구 ↔ 카드·코드» 전수 대조

> **언제**: 차수(1차·2차) 마감 전 · 한 달에 한 번 · 기획 개정이 크게 들어온 뒤. **산출물 = 대조표 + 카드**(코드 갈래와 같다 — 여기서 고치지 않는다).

**왜 이 갈래가 생겼나**: 2026-09-17 bnsone 에서 1차 요구를 처음으로 전수 대조했더니, 그때까지 **어떤 절차에도 없던 구멍 6종**이 한꺼번에 드러났다 — 예고만 되고 안 생긴 카드 11건 · 분해안 미발행 5건 · «범위 밖»으로 뺀 1차 기능 3개(사원 일괄등록·조직 삭제·결재 첨부) 추적 0 · 카드 댓글에만 남은 스펙 이탈 결정 · ADR 을 뒤집은 새 기획 문서 · 이미 풀린 것을 «미정»으로 든 digest 약 25곳. **카드 하나하나의 절차(`/done`)는 «넣은 것»만 보고, «요구 전체에서 빠진 것»은 아무 절차도 안 봤다.**

## 1. 기계로 먼저 센다 (본 세션이 직접 — 가볍다)
- `bash scripts/check-deferred.sh --all` — 우리 문서에 남은 **번호 없는 미룸** 전부(옛 부채 포함).
- `bash scripts/collect-planner-questions.sh --stale` — digest 가 들고 있는 **이미 풀렸을 질문** 후보.
- `bash scripts/collect-planner-questions.sh` — 안 풀린 **기획 질문 수**(묶음을 오너에게 건넬지 함께 묻는다).
- 셋 다 종료 코드와 «몇 건 검사»줄을 함께 적는다 — 0건이 «못 봤다»와 같은 모양이면 안 된다(`rules/verify.md` §1).

## 2. 요구 목록을 뽑는다
- 정본 = `docs/03_Requirement/` 의 요구 ID 표(없으면 그 STEP `_digest.md` «확정된 것»). **그 차수에 속한 ID 만** — 차수 표기가 없으면 멈추고 사용자에게 묻는다(짐작 금지).
- 요구 ID 가 많으면 **영역별로 묶어** 묶음마다 fresh-context 에이전트 1개(`/audit-sweep` 와 같은 방식 — 본 세션이 전부 읽지 마라).

## 3. 요구마다 세 칸을 채운다 (에이전트 지시 — 동일 서식)
| 칸 | 찾는 법 | 증거 |
| --- | --- | --- |
| 카드 | `glab api "projects/:id/issues?search=<ID>&state=all&per_page=100"` + 요구 이름 낱말로 한 번 더(한국어는 부분일치가 약하다 — `/change` 1번) | 카드 번호·상태 |
| 코드 | `grep -rn "<ID>\|<핵심 낱말>" src` · 라우트 목록 | 파일:줄 |
| 문서 | 그 요구가 digest·ADR 에서 «범위 밖·후속·미정»으로 적혔나 | 파일:줄 + **원문 인용** |

판정은 넷 중 하나: **구현됨**(코드 증거) · **카드만**(열린 카드 있음, 코드 없음) · **추적 0**(카드도 코드도 없음) · **의도적 제외**(뺀 결정과 그 근거·결정자가 digest/ADR 에 있음). ⚠️«범위 밖»이라고만 적혀 있고 **누가 언제 왜 뺐는지 없으면 «추적 0»** 이다.

## 4. 표 → 게이트 → 카드
- 대조표 `| 요구 ID | 요구 | 카드 | 코드 | 판정 | 증거 |` 를 **«추적 0»·«카드만(담당 없음)» 먼저** 정렬해 보인다.
- 항목별 OK 후 카드로 — **새 카드가 기본이 아니다**(본문 0단계: 담당자의 열린 목록 카드에 항목으로). «추적 0» 인 1차 요구는 **기획자 확인이 먼저**일 수 있다 — 그러면 카드가 아니라 digest «미해결·질문»에 한 줄(질문 묶음에 실린다).
- 1단계에서 나온 번호 없는 미룸·풀린 질문은 **문서 정리**라 이 갈래에서 바로 고쳐도 된다(항목별 OK 후) — 코드는 건드리지 않는다.
