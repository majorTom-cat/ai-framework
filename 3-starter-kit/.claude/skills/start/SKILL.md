# /start — 일 시작 길잡이

> **계약** · 입력: 없음(또는 자연어 질문) · 산출물: 상황 브리핑 5부(어떤 프로젝트냐→지금 상황→쓸 만한 스킬→해볼 만한 것→▶ 다음 하나) — 진단표는 이상 있을 때만 축약 첨부 · 부작용: **내 PC 로컬 셋업만**(앱 기동·의존성 설치·`CLAUDE.local.md` 생성 — 커밋·GitLab 산출물 없음) · 검증: 조회·안내형 — 별도 없음

> **예시**: `/start` · `/start 뭐부터 하지?` (막막할 때 자연어로 물어도 됨)

> **/todo와의 경계**: 오늘 **내 카드·멘션 브리핑**이 목적이면 `/todo`. 이 스킬은 **환경·단계 진단**이다 — 첫날, 새 팀원, 뭔가 깨졌을 때, 구축 중 "지금 어디까지 왔지" 확인용.

**너의 역할**: 친절한 선배. 한 번에 **다음 한 걸음만** 알려주고, 그 걸음이 끝난 걸 확인한 뒤 다음으로. 전문용어는 쉬운 말로 풀어서 (예: "머지 = 내 작업을 팀 공용 코드에 합치기"). 목록을 쏟아붓지 마라 — 막막한 사람에게 목록은 벽이다.

**막막형 입력이면 역질문 먼저**: 인자가 구체 대상 없는 질문("뭐부터 하지?" 류)이면 진단을 쏟기 전에 **딱 하나만** 물어라 — "①환경(셋업이 안 되는 것 같다) ②다음 할 일 ③개념 질문 — 어느 쪽이 막히세요?" ①이면 아래 진단 경로, ②면 `/todo`, ③이면 쉬운 비유로 짧게 답하고 진행으로 복귀. **답한 갈래만** 안내한다.

## 0. 역할 먼저 (모르면 물어라 — 딱 한 번)

CLAUDE.md 모듈 표·`git config user.name` 으로 짐작하되, 확신 없으면: "①개발자 ②공통 개발자 ③기획/검수 — 어느 쪽이세요?"

- **개발자** → 아래 1~4 그대로
- **공통 개발자** → 아래 5 (구축 진단)
- **기획/검수(문서 담당)** → 당신은 **문서(`docs/`)만** 다룹니다(코드는 개발자 몫). 두 길 중 지금 쓰는 걸로 안내하라:
  - **브라우저만** 원하면: "GitLab 실전 가이드의 **0-1절 '30분 따라하기'**부터요" (원하면 다섯 걸음을 이 대화에서 클릭 단위로 불러줘도 된다).
  - **Claude Code로 하는 중이면**(지금 이 대화가 그 증거): 쓸 스킬은 **`/docs`**(문서 정리·업로드)·**`/card`**(할 일·요구 등록) 둘이면 충분 — `/dev`·`/fix`·`/done`·`/module`·`/ui`는 개발자용이니 쓰지 말라고 안심시켜라. 자세한 건 `docs/00_Guide/AI_Working_Framework_Guide_ClaudeCode.md`. **지금 뭘 하고 싶은지 한 가지 물어** 한 걸음씩 안내하라.

## 1. 조용히 진단부터 (사용자에게 묻기 전에 직접 확인)

- repo 루트인가: `git rev-parse --show-toplevel`
- GitLab 연결: `glab auth status`
- 의존성이 깔렸나: 락파일(`package-lock.json` 등)이 있는데 `node_modules`가 없으면 설치(`npm install` — 이때 husky 같은 팀 훅이 함께 깔린다. 안 깔린 채로 일하면 안전장치가 조용히 빠진다). 스택마다 설치 명령이 다르니 특정 도구를 가정하지 마라
- 개인 환경 파일이 있나: `.env.example`이 있는데 `.env`가 없으면 복사 생성(`cp .env.example .env` — 커밋 안 되는 개인 파일). 없으면 `npm run dev` 류 직접 기동이 조용히 막힌다(docker 경로만 쓰면 안 드러나는 함정 — bnsone 실측 2026-07-29)
- 앱이 뜨나: CLAUDE.md '실행·테스트' 절의 `<기동명령>` 기준으로 확인 (특정 도구를 가정하지 마라). 안 떠 있으면 띄운다(실행 주체는 §2 ★원칙 — 전부 네 일이다):
  - 개발용 상시 서버는 **백그라운드로**(`docker compose up -d` 류) 띄운 채 두고 확인 URL을 알려준다.
  - 진단만을 위한 임시 기동이면 확인 후 **네가 종료한다**(CLAUDE.md "네가 띄운 로컬 서버·백그라운드 프로세스는 작업 종료 전 종료" — 고아 프로세스가 다음 사람의 포트를 잠근다)
- 내 카드가 있나: `glab issue list --assignee=@me`
- 내 모듈이 있나: CLAUDE.md 모듈 소유 표·`.claude/rules/module-*.md` 와 `git config user.name` 대조
  — 표엔 있는데 `module-*.md`가 없으면 **골격이 폴더를 선생성한 모듈**이다(2026-08-25) — `/assign-module {모듈} {소유자}`로 보충하라고 안내(그 스킬이 템플릿에서 만든다)
- 내 로컬 설정이 있나: repo 루트에 `CLAUDE.local.md` 존재 여부 (개발자·공통 개발자 공통 — 없으면 아래 1-1. 공통 개발자도 개발한다)

### 1-1. `CLAUDE.local.md`가 없으면 — 네가 물어보고 만들어줘라 (첫날 셋업 6번)

**딱 2가지만 묻는다**: ①내 로컬 포트(예: 3001 — 팀원끼리 겹치지 않게) ②내 로컬 DB명(예: `app_dev_이름`). 답을 받으면 이 양식으로 생성:

```markdown
# 내 로컬 설정 — 커밋되지 않는다 (내 PC 전용)
- 로컬 포트: {포트}
- 로컬 DB명: {DB명}
- 메모: (개인 참고만 — 팀 규칙은 여기 아님)
```

생성 후 **구별을 한 줄로 안내하라**: "`CLAUDE.md`는 **팀 전원 공통 규칙**(커밋됨 — 고치려면 공지·카드), `CLAUDE.local.md`는 **나만의 값**(포트·DB·메모 — 커밋 안 됨, 내 PC 전용)입니다. 팀에 적용됐으면 하는 규칙은 여기 말고 카드로 제안하세요."
- `.gitignore`에 `CLAUDE.local.md`가 있는지도 확인(킷 기본엔 있다 — 없으면 공통 개발자에게 알림).
- DB·마이그레이션 없는 스택이면 DB명 질문은 생략.

## 2. 진단 결과에 따라 하나의 길로 안내

| 상태 | 안내 |
| --- | --- |
| 셋업이 안 됨 (인증 실패·앱 안 뜸 등) | **첫날 셋업**을 이어서 — 안 된 것 **하나**를 **네가 직접 실행해 고치고 결과를 보고**한다(예: 앱 기동 = `docker compose up -d`로 백그라운드 기동 후 "브라우저에서 http://localhost:{포트} 열어 확인하세요") → 확인 → 다음 하나. 전체 목록은 docs/00_Guide/ONBOARDING.md에 있다고만 언급 |
| 셋업 OK + 내 모듈 없음 | 전체 흐름 그림(아래 3)을 먼저 → 본보기 모듈 훑어보기 권유 → "`/module 내모듈이름` 으로 시작하세요" |
| 셋업 OK + 내 카드 있음 | "**`/todo`** 를 실행하면 지금 할 일을 번호로 보여드려요" — 원하면 네가 바로 /todo 실행 |
| 셋업 OK + 보드가 빔 | 카드가 연료다 — 기획자·공통 개발자와 docs/ 요구사항에서 카드를 뽑자고 안내: "`/card docs/03_Requirement/{문서} 분해` 로 제가 카드 초안을 만들어드려요" |

★**셋업 명령은 네가 대신 실행한다 — 사용자에게 명령을 치게 하지 마라**(위 표·§1 진단 공통). 이 팀의 개발자는 전원 Claude Code로 일한다: 의존성 설치·앱 기동·설정 파일 생성은 **네 일**이다. **예외는 둘뿐**:
- ①**GUI로만 되는 것**(Docker Desktop·에디터 설치, 시스템 환경변수 창) ②**계정 로그인**(`glab auth login` 등 대화형 인증).
- 이때도 무엇을 클릭·입력할지 **정확히 짚어주고**, 사용자가 끝냈다고 하면 **네가 이어서 확인**한다.

## 3. 처음인 사람에게는 전체 그림을 4줄로 (그 이상 길게 말하지 마라)

> 일은 **카드**(보드의 할 일 딱지)로 움직입니다. ①`/todo`로 내 카드를 고르고 → ②`/dev`(개발)나 `/fix`(작은 수정)로 AI와 만들고 → ③`/done`이면 자동으로 검사·합치기·배포까지 → ④**카드에 지정된 검수 담당**(비면 담당자 본인 — 개발자든 비개발자든)이 화면을 보고 카드를 닫습니다. 당신이 외울 건 없습니다 — 매 단계 끝에서 제가 다음 명령을 알려드립니다.

## 4. 마무리 규칙

- 항상 **다음 명령 딱 하나**로 끝내라 (`▶ 다음: /todo`).
- 사용자가 중간에 개념을 물으면(브랜치가 뭐예요?) 쉬운 비유로 짧게 답하고 다시 진행으로 복귀.
- **상태를 바꾸는 스킬(/dev·/done·/module 등)은 네가 대신 시작하지 마라** — 그건 사용자가 입력해야 하는 명령이고, 카드·MR·커밋처럼 **바깥에 남는 산출물은 /start의 일이 아니다**(대신 하는 범위의 정의는 맨 위 계약 줄 — 내 PC 로컬까지).

## 5. 공통 개발자 경로

역할이 공통 개발자면 **지금 `공통개발자.md`를 읽고 그대로 진행하라** — 구축 Day 판정표·브리핑 5부 양식·골든 샘플이 전부 거기 있다(기억으로 진행 금지).
