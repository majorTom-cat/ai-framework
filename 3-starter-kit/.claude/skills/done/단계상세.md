# /done 단계 상세 — 본문이 가리킬 때 그 절만 읽어라

> `SKILL.md` 본문은 «무엇을 하는 단계인가 + 반드시 지킬 것»만 담는다. 이 파일은 그 단계의 **실행 순서와 실측 경위**다.
> **왜 뺐나**: 컴팩션은 스킬마다 **«앞 5,000토큰만 남기고 뒤를 자른다»**(공식). 7~10단계와 «금지» 절은 그 밖이라
> 대화가 길어지면 **통째로 안 읽혔다.** 보조 파일은 그 예산에 안 든다(읽을 때만 로드) — **잘려서 안 읽히느니 포인터로 읽히는 편이 낫다.**
> ※ **실측된 예외·우회**는 이 파일이 아니라 `함정.md` 다. 여기는 «정상 경로의 상세»다.

## §0 1·2단계 경위 — 왜 다시 조회하고, 왜 리셋하면 안 되나

**1단계 «세션 시작 이후 남이 한 일»을 다시 보는 이유**: 2026-08-31 실측 — 두 사람이 같은 시간대에 나란히 일했는데, 시작 스냅숏만 본 세션은 상대가 그 뒤 올린 MR·카드·머지를 **끝까지 못 봤다**(오너가 물어야 드러났다). **조회 한 번이 이 구멍을 닫는다.**

**2단계 `P3009` 상세**: ★**`P3009` 가 나오면 리셋이 아니라 `migrate resolve --applied <이름>` 이다** — 컨테이너 기동이 마이그레이션을 자동 실행하는 스택에서 호스트에서도 동시에 돌리면 한쪽이 `42P07 … already exists` 로 죽고 **실패 기록만 남아 그 뒤가 전부 막힌다.** DB 는 멀쩡하고 **기록만 어긋난** 상태라 `migrate deploy` 를 다시 돌려도 안 풀린다. ⚠️**먼저 CLAUDE.md '실행·테스트' 를 보고 컨테이너가 이미 돌리는지 확인하라 — 그러면 2단계를 건너뛴다**(2026-09-07 bnsone 실측: 2건이 며칠째 안 들어간 채였고 남의 모듈 테스트가 빨개져서야 드러났다).

## §1 리뷰 반영 수정은 커밋한 뒤에 재검증한다 (4단계)

★**리뷰 반영 수정은 «커밋한 뒤에» 재검증·돌연변이를 돌려라** — 이 단계는 본질적으로 «미커밋 수정이 쌓인 상태»라 복원 명령이 그 수정을 통째로 지운다(2026-08-25·08-26·09-03 실측 **3회**). 복원 확인도 `git diff --quiet`(커밋 상태와 같아지면 «OK»로 보인다)가 아니라 **「내 수정이 아직 있나」를 grep 으로** 하라. 스크립트로 짤 땐 **/dev 6단계가 가리키는 dev `함정.md` §6 의 첫 줄 게이트**를 박아라(6단계 본문엔 그 한 줄이 없다).

## §2 수용 기준 대조 — 「검수 방법」이 실물로 성립하는지까지 (6단계)

★**수용 기준만 보지 말고 카드의 「검수 방법」 문구에 적힌 화면·계정·양식이 실물로 존재하고 그 조합이 성립하는지 확인하라 — 라우트(`nav`)와 시드를 직접 열어라.** 2026-09-03 실측: 「근태 화면에서 확인」이라 안내했는데 **그 화면이 없었고**(`nav: []`), 안내한 계정 조합도 시드상 성립하지 않아(결재선 1단계라 상신 즉시 전결) 검수자가 절차를 따르다 두 번 막혔다.

- ★**「MR !번호」처럼 «아직 없는 값»이 필요한 갱신은 7단계(MR 생성) 뒤에 한다** — 이 단계에서 관례대로 번호를 적으려다 **짐작으로 채우게 된다**(2026-09-04 bnsone 실측: 맞았지만 위험한 패턴). 체크박스·진행 표기는 지금 하고, 번호가 들어가는 줄만 뒤로 미뤄라.
- ★**대조 결과를 카드 본문 체크박스에 반영한다**(`- [ ]` → `- [x]`, `glab issue update $0 -d`로 본문 갱신) — 증거 댓글만으론 목록에 `0/N`으로 남아 완료 판별 불가(bnsone #6·#16·#17·#18 — `함정.md` §8). 못 채운 항목은 `[ ]`로 두고 사유를 댓글에. ※갱신 방법의 함정은 **`함정.md` §3** — 갱신 전에 읽는다.

## §3 7단계 상세 — 묶음 승인·MR 생성·머지

**⏸ 묶음 승인 — 여기서 딱 한 번 선다.**

- ★**한 화면 5줄 이내로** 「①(공통 영역이면) 팀 채팅 공지했나 ②올라갈 내용이 무엇인가 ③이대로 머지 예정」을 보여주고 **OK 하나**를 받는다. 표·파일 목록 금지(근거는 카드에 — CLAUDE.md '남기기 전 미리보기').
  사람에게 이 셋은 **"이대로 main에 넣을까?" 한 질문**이다. 따로 물으면 정보량 0인 정지가 늘고, 잦은 정지는 요약을 길게 만들어 **아무도 안 읽는 도장찍기**가 된다(2026-08-28 실측: 한 카드 8회 정지 중 결과를 바꾼 답은 2회. 오너 결정 "1").
- **이 묶음은 셀프승인 레인 한정.** 동료 승인 레인이거나 파이프라인이 빨간불이면 **지금까지대로 다시 선다.** 머지 후 파이프라인 결과는 사후 보고.
- ★**남은 미커밋이 있으면 경로 지목 add — `git add -A`·`add .` 금지**(bnsone 15c882c — 상세 /dev 7단계).
- **이번 diff가 새 필수 환경변수를 도입했으면** 로컬 기동 3경로(`docker-compose*`·`.env.example`·엔트리포인트)를 **같은 MR에서** 채웠는지 확인(하나만 빠져도 남의 로컬 기동이 통째로 죽는다 — bnsone #63 실측).

**MR 생성 — `glab mr create --remove-source-branch` (설명에 "관련: #$0").**

- ★**브랜치 삭제는 세 경로 «전부» 명령에 박아라 — 프로젝트 설정에 맡기지 마라**: 생성 `--remove-source-branch` · 일반 머지 `glab mr merge -d` · raw API 우회 `-f should_remove_source_branch=true`. 한 곳만 넣으면 auto-merge 실패 → 우회로 빠지는 갈래에서 샌다. **머지를 확인한 뒤 로컬도** `git branch -d {브랜치} && git fetch --prune`(§4). GitLab 설정이 켜져 있어도 glab 경유 MR 은 `force_remove_source_branch=false` 로 남는다(2026-09-07 bnsone 실측: 서버 브랜치 68개 중 **65개가 머지 후 껍데기**, 로컬 86개 중 58개가 `[gone]` 유령 — 작성자 세 사람 전원이라 습관이 아니라 절차 누락이었다).
- ★**MR 본문에 `Closes #N`(`Fixes`·`Resolves` 포함) 금지 — `관련: #$0` 링크만**: 머지 순간 카드가 자동으로 닫힌다(`함정.md` §8). **예외 없다** — 셀프완료·`/ui`도 §4 절차로만 명시적으로 닫는다.
- **MR 본문도 여러 줄이다** — 작성·재조회 규칙 정본 = `rules/gitlab-cli.md`(상시 로드). 루프 다중 MR에서 특히 무음 실패한다 — 생성 후 `glab mr list` 재조회.

**머지.**

- ★**auto-merge는 파이프라인이 running/pending일 때만 건다.** 이미 종결(success)이면 걸지 말고 **즉시 일반 머지**(`glab mr merge -d` — `-d` 를 빼면 브랜치가 남는다) — 끝난 파이프라인 위에 걸면 발동할 이벤트가 없어 **영구 대기**한다(파일럿 #14 실측).
- **status `manual`(blocked)은 실패도 진행도 아니다 — 게이트 승인 대기**: auto-merge 말고 아래 고위험 절차부터. 판정은 `node scripts/pipeline-verdict.cjs <PID>` 1행 토큰으로(status 한 값 판정 금지).
- ★**auto-merge 설정이 실패하거나("requires a passing pipeline"·"Not Allowed") 안 걸리면 `함정.md` §1을 읽고 처리하라** — 실측된 우회가 있다. 포기 전에 반드시.
- ★**고위험 카드면**(`고위험` 라벨 또는 CLAUDE.md '머지 등급'의 고위험 유형) **판정한 즉시 `함정.md` §2를 읽고 그대로 실행하라**(§2-a 동료=선택/§2-b 셀프=표준/§2-c 잡 없음 — 레인·티어·상황마다 실행법이 다르다. 늦게 읽으면 승인 단계에서 되돌아온다). **게이트 잡이 실제 생성됐는지 잡 목록으로 확인하기 전엔 auto-merge·셀프 머지 금지**(라벨 선행·확인 명령 = §2).

## §4 8단계 상세 — 머지 확인·로컬 정리·배포 화면

**머지 완료 확인 = `glab mr view <MR iid>` 로 `state`=`merged`를 눈으로 본다**(추정 금지 — auto-merge 설정·파이프라인 초록은 확인이 아니다). `merged`가 아니면 화면 확인·§5로 가지 말고 상태를 그대로 보고 후 `함정.md` §4·§1 경로로.

- ★**`merged` 를 본 그 자리에서 로컬도 정리한다**: `git checkout main && git pull && git branch -d {작업브랜치} && git fetch --prune`. 안 지우면 upstream 이 사라진 «유령» 브랜치가 쌓인다(2026-09-07 bnsone 실측: 로컬 86개 중 84개가 이미 main 에 포함, 그중 **58개가 `[gone]`**).
- ★**이번 diff에 설정·매니페스트 파일이 있으면**(`k8s/*.yaml`·configmap·env 류) **지금 `함정.md` §7을 읽어라** — "머지=반영"이 성립하지 않는 유형이다.
- 머지가 확인되면 **배포 화면 먼저 확인**: 사용자에게 "검수 서버에서 1분 직접 확인" 안내(부재 시 **`/inspect $0` 절차**로 렌더·클릭 왕복·이상 입력 확인+증거) — **화면 확인 전 검수요청 전환 금지**
- ★**파이프라인이 `success`여도 경고를 확인해 보고하라**(실패한 잡 이름 + 로그 요약 한 줄) — `allow_failure` 잡은 실패해도 `success`로 보인다. **조회법·근거는 `함정.md` §6.**
- auto-merge 대기 중인데 세션을 끝내야 하면(또는 파이프라인이 failed면): **끝내기 전에 `함정.md` §4를 읽어라** — 그대로 끝내면 안 되는 조건이 있다.
- **화면 없는 카드**(인프라·docs·API 노출)는 이 단계·검수요청 없이 상태 전이표의 **셀프 완료** 경로다 — **`함정.md` §9를 읽고 그대로 실행하라**(체크박스·라벨 순서를 틀리면 조용히 샌다).

## §5 9단계 상세 — 라벨 전환·멘션

**`진행중` 제거 + `검수요청` 추가(둘 다 명시적으로**, 예: `--unlabel 진행중 --label 검수요청`**)** + 댓글 — 라벨 add/remove는 별개다. `진행중` 잔존 시 /metrics 리드타임에서 경고 없이 빠진다(파일럿 #14).

- ★**라벨 먼저 → 댓글 나중** — 알림은 **댓글 시점의 라벨**로 걸러지고 라벨 부착은 알림 사건이 아니다(bnsone 2026-08-13 — `함정.md` §8). 늦게 달았으면 재알림 댓글 하나 더.
- ★**부탁 댓글만 그렇다 — 완료·기록 댓글은 반대로 라벨을 뗀 뒤에 단다**(안 그러면 끝난 일이 초인종을 울린다. 검수 완료 = /todo `검수.md` §2, 승인 완료 = `함정.md` §2-a).
- **전환 후 `glab issue view $0`로 라벨이 실제 바뀌었는지 재조회한다**(명령 성공 출력≠반영 — 재조회가 확인이다)
- `"머지됨. 검수 서버에서 확인 가능. @{검수자}"` — **작성자≠검수자면 둘 다 멘션**(`@{작성자}` 추가) (스펙 차이 요약이 있으면 함께)
  ({검수자} = 카드 "검수" 필드 → 비면 {카드담당자}(assignee) → 없으면 {카드작성자} — 모두 실행 시점에 `glab issue view $0`에서 읽는다. 전담 검수자는 없다)
- 검수가 막는 것은 **"사람이 안 본 것"뿐이다**(CLAUDE.md 상태 전이표) — **검수자가 구현자 본인이어도 멈추지 마라.** 다른 눈을 붙일 수 있으면 "검수" 필드에 지정해 멘션(**권장이지 조건 아님**).
- **이 카드를 의존(선행)으로 가진 열린 카드가 있으면 그 담당자들에게** `"#$0 머지됨 — 착수 가능"` 멘션 (기다리는 사람이 보드를 새로고침하고 있지 않다)

## §9 리뷰 수준 — 왜 xhigh 고정인가 (2026-09-08)
- 본문 4단계에 「기본 수준: /fix 커밋은 가볍게, /dev 커밋은 보통」이라고만 적혀 있었다(킷 첫 커밋부터, 설계 결정 기록 없음). AI 는 그 부사를 `low`·`medium` 으로 옮겼다 — bnsone 세션 기록 실측: `/code-review` 스킬 호출 70건 중 **low 20 · medium 20 · high 17 · 수준 없음 13 · xhigh 이상 0**. 수준을 안 적은 13건도 공식 문서상 «마지막에 친 수준을 재사용»이라 대개 low·medium 이었다.
- 공식 문서: low·medium 은 「가장 확신하는 발견만 보고해 오탐이 적은 대신 놓친다」, high~max 는 「넓게, 덜 확실한 것도 포함」. 오너 체감(「하나 고치면 다음 카드에서 또 거기서 수정사항이 나온다」)과 맞는다.
- 그래서 **effort 를 AI 가 고르게 두지 않는다** — 값을 문장에 박는다. 리뷰는 `/merge-review` 워크플로(렌즈 4개 + 반박 3표), 없으면 `/code-review xhigh`. `ultra` 는 사용량 크레딧 과금(회당 5~25달러)이라 금지(오너 결정 2026-09-08).
- ★**그런데 «얼마나 걸리나»가 안 쌓인다 — 그래서 끝나면 한 줄을 남긴다**(2026-09-09 추가). 실측: 설정 3줄 + 테스트 93줄짜리 카드에서 리뷰가 **10분 35초**(23:04:53 띄움 → 23:15:28 도착). 워크플로가 아니라 `/code-review xhigh` 단일 에이전트였는데도 그랬다. ⚠️**«백그라운드로 도니까 괜찮다»는 성립하지 않았다** — 세션은 17초 만에 다른 일로 갔지만 그 «다른 일»이 30초치뿐이라 **나머지 10분은 순수 대기**였다(리뷰가 마지막 단계라 겹칠 일이 없다).
- ⚠️**그렇다고 수준을 낮추는 쪽으로 가지 마라 — 그 리뷰가 진짜 회귀를 잡았다**(설정 한 줄이 `--testTimeout` 명령줄 옵션을 무력화했고, 세션이 직접 재현해 확인했다). 손볼 곳은 «수준»이 아니라 «탐색 범위»다: 이 워크플로의 렌즈 프롬프트는 «필요하면 파일을 열어 주변 코드를 확인하라»로 **한계가 없다.**
- **그래서 먼저 재라**: 반환값 `checked_files` 의 개수와 걸린 시간을 카드 증적에 한 줄로 남긴다. **«바뀐 파일과 그 호출부까지만»으로 범위를 좁히는 건 이 값이 몇 번 쌓인 뒤에 정한다** — 2026-09-09 시점엔 44회 조회가 무엇이었는지 셀 수 없었다(그 세션이 끝났고 서브에이전트 기록은 로컬에 안 남는다 — bnsone 관련 475파일 전수에서 0건).


## §10 커밋 메시지 검사를 5단계에서 다시 보는 이유 (2026-09-09)

- ★**1단계에서 판정한 «커밋 메시지 검사»(bnsone `change-summary`)를 5단계에서 다시 확인한다.** 4단계 리뷰 반영으로 규칙·절차 문서(`docs/00_Guide/**` 등)를 **추가로** 건드렸으면 1단계에서 안 걸리던 경로가 새로 걸린다. **공통 영역 목록엔 그 경로가 없다** — 5번 줄만 보면 몰라서 지나간다.
- 이미 머지 직전에 걸렸으면 **새 커밋 하나를 더한다**(force push 불요).
- 이 절은 원래 `SKILL.md` 5단계 본문에 있었는데 **스킬이 컴팩션 한도(5,376자)를 넘기지 않도록** 여기로 옮겼다(2026-09-09 저녁3). 넘으면 스킬 뒤쪽이 통째로 안 읽힌다 — 이제 차단형 `skill-size` 잡이 막는다.
