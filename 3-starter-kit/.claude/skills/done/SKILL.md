# /done — 이슈 #$0 마무리

> **★번호가 안 왔으면 여기서 멈춘다** — 위 제목의 `#$0`이 숫자가 아니면(치환 안 됨) 번호를 문맥으로 추측하지 마라. 이 스킬은 **머지까지 한다** — 틀린 번호면 엉뚱한 카드가 닫히고 남의 MR이 머지된다. `/done {번호}` 로 다시 부르라고 안내하고 종료.

> **계약** · 입력: 이슈번호 · 산출물: 테스트→리뷰→머지(=배포)→라벨 검수요청+검수자 멘션 · 검증: 파이프라인 success+배포 화면 (카드 Close는 사람)

> **예시**: `/done 12`

> ★**모델 확인(소프트 플로어)**: 이 스킬은 머지까지 간다 — 현재 세션이 경량 모델(haiku급)이면 **시작 전에 멈추고** "/model로 올린 뒤 다시 `/done`"을 안내하라. (frontmatter `effort`는 모델을 못 바꾼다 — 경량 모델+high effort는 여전히 경량이다.)

순서대로 실행하고, **실패하면 그 단계에서 멈추고 보고**하라.
(명령이 이 문서와 repo CLAUDE.md '실행·테스트' 절이 다르면 **CLAUDE.md가 정본**이다.)
★**게이트·확인 질문은 텍스트 선택지로 물어라 — 선택 폼(AskUserQuestion) 금지**: 이 환경에선 오케스트레이터가 폼을 못 읽어 답이 안 돌아오고 세션이 설 뻔했다(파일럿 2026-07-29 실측 · /done 7단계 고위험 선택지). 번호 붙인 선택지를 **응답 본문에 적고** 답을 기다려라.
★CLAUDE.md **'남기기 전 미리보기'** 공통 규칙 적용 — 7단계 MR 생성·auto-merge/머지, 9단계 카드 댓글·라벨 전환 등 바깥 산출물은 각각 **실행 직전 요약을 보여주고 사용자 OK 후** 진행한다.

1. `git pull origin main` 후 현재 브랜치에 main 병합 — 충돌 시 **종류별 규칙대로 해결**(CLAUDE.md '작업 절차'의 pull·merge 충돌 규칙: 코드=해결안 제시+확인 / lock·schema 파일·마이그레이션=전용 규칙 / DB 리셋=사람) 후 진행
2. (마이그레이션 도구 있는 스택만) 새로 받은 마이그레이션을 로컬 DB에 적용 — 명령은 CLAUDE.md '실행·테스트' 절. **★1번 pull에서 main에 내 것보다 나중 타임스탬프의 새 마이그레이션이 들어왔으면 내 마이그레이션을 최신 뒤로 재생성**한다(전역 직렬 자산 — 순서가 꼬이면 스키마가 깨진다).
3. `npm test` — **red면 여기서 멈추고 고친다. green까지.** 변경에 `.gitlab-ci.yml`이 있으면 **`glab ci lint`도**(무효 CI는 테스트가 못 잡는다 — 잡 0개 파이프라인 실측 #72)
   — ★**`needs`·`rules:changes`·배포 잡을 건드렸으면 lint 통과는 안전의 근거가 못 된다** — 비교할 diff가 없으면 `changes:`가 참으로 계산돼 **원리상 안 잡힌다**(실사고 8회, 잡 0개 파이프라인). **먼저 `_reference/ci-needs.md`를 읽어라.**
     그 문서의 확인 방법: 머지 후 **문서만 바꾼 커밋을 main에 한 번 올려** 파이프라인이 잡 0개가 아닌지 본다(새 브랜치 첫 푸시·빈 커밋은 항상 초록이라 근거가 안 된다). 확인 전엔 "CI 정상"이라고 보고하지 마라
   ★**테스트 변조 자가 점검**: 이번 diff가 *소스와 테스트(또는 CI 임계값)를 동시에* 고쳤다면, 테스트를 통과시키려고 테스트를 약하게 만든 게 아닌지 한 줄로 확인·소명하라(green은 스스로 무력화 가능하다). 실패하는 테스트를 삭제·skip으로 넘긴 흔적이 있으면 되돌린다.
4. `/code-review` 로 diff 리뷰 — **반드시 새 세션/서브에이전트 등 fresh context로**(방금 구현한 그 컨텍스트가 자기 결과를 리뷰하면 편향된다). 기본 수준: /fix 커밋은 가볍게, /dev 커밋은 보통 — Important 이상 발견은 고치고 **테스트 단계부터** 다시.
   diff가 **새 외부 입력 표면을 추가**했으면(신규 엔드포인트·파일 업로드·인증·비밀값 취급) `/security-review` 도 실행 — 매 카드 상시 실행이 아니다(기존 화면의 필드 수정 정도는 code-review가 커버). (CI에 보안·중복 스캔 잡이 있으면 그게 백스톱 — 공통 개발자 가이드 Day 2)
   발견·수리 요약을 카드 댓글 1줄로 남겨라 (증적)
5. 변경 파일에 공통 영역(src/shared·공용 테이블·CLAUDE.md·package.json)이 포함되면:
   **"팀 채팅에 공지했나요?"를 사용자에게 확인** (push 훅도 확인을 요구한다)
6. **수용 기준 1:1 대조**: 카드의 수용 기준 각 항목 ↔ 구현 증거(테스트·화면)를 하나씩 짝지어 확인 —
   diff 리뷰는 *넣은 것의 결함*만 잡고 *빠뜨린 것*은 못 잡는다. 〔검수확인〕 항목이 **브라우저만으로 재연
   가능한지**도 확인하고, 안 되면 카드의 "검수 방법"을 보강하라.
   구현이 docs 스펙과 달라졌다면: docs 수정이 이 브랜치에 포함됐는지 확인 + **카드에 "스펙과 달라진 점 + 이유" 댓글을 남긴다**(/dev가 준비해 둔 차이 요약이 있으면 그것으로) + @<기획자아이디> 멘션
   — ★**대조 결과를 카드 본문 체크박스에 반영한다**(`- [ ]` → `- [x]`, `glab issue update $0 -d`로 본문 갱신). 증거 댓글만 남기면 **카드 목록엔 `0/N`으로 보여 완료를 판별할 수 없다**(bnsone 실측: #6·#16·#17·#18이 0/N인 채 닫혀 소급 수정). 아직 못 채운 항목은 [ ]로 두고 왜인지 댓글에 적어라. ※갱신 방법의 함정(일괄 치환 사고)은 **`함정.md` §3** — 갱신 전에 읽는다.
7. push → `glab mr create` (설명에 "관련: #$0") → **머지**:
   — ★**MR 본문에 `Closes #N`(`Fixes`·`Resolves` 포함)을 쓰지 마라 — `관련: #$0`으로 링크만 건다**: 머지되는 순간 GitLab이 그 카드를 **자동으로 닫는다**(수용 기준이 남은 카드가 머지와 동시에 닫혀 되돌린 사고 — bnsone 2026-08-05). 카드를 닫는 건 검수 담당(사람)의 일이다.
     **예외 없다 — 셀프완료도 마찬가지.** `Closes`로 닫으면 머지 순간 닫히는데 `진행중` 라벨 제거는 9단계라, 8단계의 "`진행중`이 달린 채 닫지 마라"를 구조적으로 어긴다(파일럿 #14 실측 재생산). 셀프완료는 **라벨 정리 후 `glab issue close`로 명시적으로** 닫는다 — `/ui`도 같은 방식이다.
   — **MR 본문도 여러 줄이다**: `-d`에 직접 넘기지 말고 파일로 쓴 뒤 `-d "$(cat 파일)"` + **`</dev/null`**(`rules/gitlab-cli.md`). **여러 MR을 루프로 만들 때 특히 빠뜨린다** — 파일럿 2026-08-04 실측: 루프에서 `</dev/null`이 빠진 `glab mr create` 2건이 **출력 한 줄 없이 무음 실패**(브랜치만 올라가고 MR 없음). 생성 후 `glab mr list`로 실제로 생겼는지 재조회해 확인하라
   — ★**auto-merge를 걸기 전에 head 파이프라인 상태를 먼저 본다** — **이미 종결(success)됐으면 auto-merge를 걸지 말고 즉시 일반 머지**(`glab mr merge`)한다.
   — auto-merge는 "**진행 중인** 파이프라인이 통과하는 순간"에만 발동하므로, 이미 끝난 파이프라인 위에 걸면 발동할 이벤트가 없어 **영구 대기**한다(파일럿 #14 실측 — 커밋 push 후 재파이프라인이 안 붙어 auto-merge가 안 닫힘).
   — 파이프라인이 **running/pending일 때만 auto-merge**를 건다.
   — **status `manual`(blocked)은 실패도 진행도 아니다 — 게이트 승인 대기**: auto-merge를 걸지 말고 아래 고위험 승인 절차부터(게이트 잡이 남아 있는 한 발동할 이벤트가 없다). 판정은 `node scripts/pipeline-verdict.cjs <PID>`로(1행 토큰 — status 한 값으로 실패/종결 판정 금지).
   — ★**auto-merge 설정이 실패하거나("requires a passing pipeline"·"Not Allowed" 등) 안 걸리면 이 스킬 폴더의 `함정.md` §1을 읽고 처리하라** — 전부 실측된 우회가 있다. 포기 전에 반드시 읽는다
   — ★**고위험 카드면**(인증·인가·세션·비밀값·결제성·DB 마이그레이션·shared 승격·핫스팟 파일, 또는 `고위험` 라벨): **"머지할까요?"로 뭉뚱그리지 마라 — 아래 선택지를 그대로 제시하고 답을 받은 뒤 진행한다**
     (뭉뚱그리면 셀프가 기본값이 되고 동료 승인은 대화에 등장조차 못 해 증발한다 — 2026-07-30 실측. 이 게이트의 본질은 "사람이 봤나"가 아니라 **"작성자 아닌 눈이 봤나"**다):
     — ★**①·② 공통 선행: MR 생성 시 `--label 고위험`을 반드시 붙인다** — 게이트 잡을 만드는 건 이 라벨이다(`high-risk-label-gate`). 경로 기반 잡(`high-risk-gate`)은 MR 도중 유발 파일을 되돌리면 소멸한다(!113 실측). 라벨 없이 이미 만들었으면 `glab mr update <iid> --label 고위험` 후 **새 파이프라인**(라벨은 파이프라인 생성 시점에 읽힌다 — 빈 커밋 push 또는 Run pipeline).
       라벨을 붙였어도 **게이트 잡이 실제 생성됐는지 잡 목록으로 확인하라**(`glab api "projects/:id/pipelines/{PID}/jobs"` — 한글 라벨의 CI 매칭은 실 파이프라인 실측 0회다). 안 생겼으면 아래 "잡 없음" 경로로.
     **① 동료 승인 — 동료가 있으면 이쪽을 먼저 권한다.** `glab mr create --reviewer <아이디>` + 카드에 요청 댓글: `"@아무개 고위험 리뷰 부탁 — {유형 한 줄}. 자기 Claude 세션에서 /todo 열면 뜹니다 — '승인' 한마디면 끝(웹 안 열어도 됨). 웹이 편하면 ▶ 1클릭: {잡URL}"`
       — ★**잡 실행(▶)은 동료 세션의 몫이다 — 작성자인 네가 API로 눌러도 게이트가 거부한다.** 게이트 잡은 실행자=MR 작성자면 exit 1이다(`.gitlab-ci.yml` `.peer-approval-gate` — 네 glab 토큰으로 play하면 실행자가 너로 찍힌다).
         동료의 Claude 세션이 `/todo`에서 play 절차를 안내받으니, 위 카드 댓글 요청이 곧 실행 요청이다. 동료의 play 후 파이프라인 초록 확인 → 머지는 네가 이어서 한다.
         채팅으로 승인 확답만 오고 동료가 잡을 실행해 줄 수 없는 상황이면: **②로 전환**하고 카드에 "동료 {아이디} 채팅 승인 — 잡 실행 불가로 셀프승인 전환" 사유 댓글을 남긴 뒤 ②의 라벨 절차를 따른다.
         ("승인 확답을 받았으면 네가 직접 play하라"던 옛 지시(2026-08-06)는 판정 없는 옛 CI 기준 — 판정 잡 도입으로 폐기. 확답을 받았어도 작성자 play는 실패한다.)
       — **CLI 승인이 기본, 잡 URL은 부가다**(이 팀은 GitLab 웹을 안 연다 — 실측. 잡 URL 조회: `glab api "projects/{ID}/pipelines/{PID}/jobs?scope[]=manual"` → `high-risk-gate`의 `web_url`).
       — 승인자 조건: 구현 미참여자 · 개발자(코드를 읽는 사람) · 자기 MR 자기 승인 금지.
     **② 셀프 승인 — 폴백이지 기본값이 아니다.** CLAUDE.md '머지 등급'의 **증적 3종**(fresh-context AI 리뷰 · 본인 diff 직접 확인 · 카드에 "셀프 승인"+사유+리뷰 결과+확인 범위)을 전부 남긴 뒤에만 진행. 사유 없는 ②는 셀프 승인이 아니라 무승인이다.
       — ★**증적 3종 뒤 MR에 `셀프승인` 라벨을 붙인다 — 이 라벨이 동일인 통과의 유일한 열쇠다**(게이트 잡이 라벨을 보고 exit 0): `glab mr update <iid> --label 셀프승인`
         → **새 파이프라인을 돌린 뒤**(라벨은 파이프라인 생성 시점에 읽힌다 — 빈 커밋 push 또는 Run pipeline) 게이트 잡은 네가 play해도 통과한다.
         라벨이 프로젝트 세트에 없으면 `glab label create --name 셀프승인 --color "#dbdbdb" --description "고위험 게이트 셀프 승인 표식 — 증적 3종 필수"` 1회 생성 후 진행.
     — ★**고위험 카드로 판정한 즉시 `함정.md` §2를 읽어라**(승인의 실제 실행 방법이 티어·상황마다 다르다 — 티어별·골격 주간·승인자 부재. 늦게 읽으면 승인 단계에서 되돌아온다).
     — ★**파이프라인에 게이트 잡(`high-risk-gate`·`high-risk-label-gate`)이 하나도 없으면**(`--label 고위험`을 빠뜨렸거나, 붙였는데도 잡이 안 생긴 경우 — 한글 라벨 매칭 미실측): auto-merge·셀프 머지를 **하지 마라**. 라벨 누락이면 위 공통 선행대로 라벨+새 파이프라인부터.
       동료가 diff를 확인하고 **직접 머지**(또는 승인 댓글 후 네가 머지)하게 하고, 카드에 "게이트 잡 없음 — 사람 승인으로 대체" 한 줄.
       **`고위험` 라벨이 CI 경로매칭보다 정본** — 라벨 달린 카드는 사람 승인 없이 절대 머지하지 마라.
8. **머지 완료 확인 = `glab mr view <MR iid>` 로 `state`가 `merged`인지 눈으로 본다**(추정 금지 — "auto-merge 걸었으니 됐겠지"·"파이프라인 초록이니 머지됐겠지"는 확인이 아니다. 안 닫힌 MR 위에 검수요청 라벨·멘션이 붙으면 검수자가 없는 화면을 보러 간다). `merged`가 아니면 8·9단계로 가지 말고 상태(`opened`/`merge_when_pipeline_succeeds`)를 그대로 보고하고 §4·§1 경로로 처리한다.
   머지가 확인되면 **배포된 화면을 먼저 확인한다**: 사용자에게 "검수 서버에서 1분 직접 확인하세요" 안내
   (사용자가 없으면 **`/inspect $0` 절차로** 렌더·클릭 왕복·이상 입력까지 확인하고 그 증거를 남겨라) — **화면 확인 전에는 검수요청 전환으로 못 간다**
   — ★**파이프라인이 `success`여도 경고를 확인해 보고하라** — 경고면 **실패한 잡 이름 + 로그 요약 한 줄**을 최종 보고에 넣는다. 이 팀은 GitLab 웹을 안 여니 **네가 말하지 않으면 아무도 모른다**.
     `allow_failure: true` 잡(`density-check`·`tamper-check`·`ai-connectivity`)은 실패해도 `status`가 `success`로 남고, 경고는 `detailed_status.label`("passed with warnings")에만 뜬다(파일럿 2863 실측 2026-08-06). 조회: `glab api "projects/:id/pipelines/{PID}"`.
   — auto-merge 대기 중인데 세션을 끝내야 하면(또는 파이프라인이 failed면): **끝내기 전에 `함정.md` §4를 읽어라** — 그대로 끝내면 안 되는 조건이 있다.
   — **화면 없는 카드**(인프라·docs·API 노출)는 이 단계·검수요청 없이 상태 전이표의 **셀프 완료** 경로로: **수용 기준 체크박스 `[x]` 갱신** + 증거 댓글(`셀프완료` 표식 포함) + **라벨 전환 `--unlabel 진행중 --label 셀프완료`** 후 `glab issue view $0`로 라벨이 실제 바뀌었는지 재조회 + 완료 처리(작성자가 남이면 통보 멘션).
     (`셀프완료` 라벨이 프로젝트 세트에 없으면 `glab label create` 1회 후 진행 — 세트에 없는 이름은 조용히 실패한다(bnsone 실측). "라벨 없이 댓글 표식만"이던 옛 규칙이 셀프완료 카드를 라벨 무기록으로 만들어 /metrics 라벨 커버리지를 9.5%로 무너뜨린 주범이다 — 댓글은 증거, **라벨이 기록의 정본**.)
     **체크박스가 0/N인 채로 닫지 마라. `진행중`이 달린 채 닫지도 마라**
9. **카드 라벨 전환 — `진행중` 제거 + `검수요청` 추가(둘 다 명시적으로**, 예: `--unlabel 진행중 --label 검수요청`**)** + 댓글 — GitLab 라벨은 add/remove가 별개라 "변경"으로 알아서 되지 않는다. `진행중`을 안 지우면 그 카드는 /metrics 리드타임 계산에서 경고 없이 통째로 빠진다(파일럿 #14 실측 — `진행중` 단 채 닫힘).
   **전환 후 `glab issue view $0`로 라벨이 실제 바뀌었는지 재조회한다**(명령 성공 출력≠반영 — 재조회가 확인이다)
   `"머지됨. 검수 서버에서 확인 가능. @{검수자}"` — **작성자≠검수자면 둘 다 멘션**(`@{작성자}` 추가 — 올린 사람이 처리 사실을 즉시 알게) (스펙 차이 요약이 있으면 함께)
   ({검수자} = 카드의 "검수" 필드에 지정된 사람. 비어 있으면 {카드작성자}. 둘 다 실행 시점 값 — `glab issue view $0`에서 읽는다. 전담 검수자는 없다)
   — ★**검수 공란인데 작성자=이번 구현자면 멈춰라**(그대로 두면 자기 검수가 된다) — 카드에 다른 검수자 1명을 지정해 달라고 요청한 뒤 그 사람을 멘션
   + **이 카드를 의존(선행)으로 가진 열린 카드가 있으면 그 담당자들에게** `"#$0 머지됨 — 착수 가능"` 멘션 (기다리는 사람이 보드를 새로고침하고 있지 않다)
10. **이 세션에서 띄운 서버·백그라운드 프로세스 전부 종료 + 포트 비점유 확인** — 반드시 **PID 기준**으로:
    Windows `Get-NetTCPConnection -LocalPort {내포트} | ForEach-Object { Stop-Process -Id $_.OwningProcess }` 후 같은 명령이 빈 결과인지.
    **이름 기반 일괄 종료(`taskkill /IM node.exe` 류) 금지** — 동료·IDE의 프로세스까지 죽인다 (실사고 사례)
    → `/todo` 실행해 다음 작업 선택지 제시

## 완료 보고 증거

최종 보고에는 **직접 확인한 증거**만 담아라: `npm test` 결과 요약 · MR !번호 + 파이프라인 상태 · 카드에 남긴 댓글.
확인 못 한 단계가 있으면 "완료" 대신 **어디까지 확인했는지**를 보고하라.

## ❌ 금지 — 그 순간 드는 핑계와 반박까지

- main 직접 push · **카드를 Close(완료)하지 마라** — 구현 세션의 close는 금지다. 완료 처리는 검수 담당(비면 작성자)의 확답을 받은 **담당 본인 세션**이 /todo 검수 경로로 대행한다(전이표 — 계정 대조·증적 댓글·라벨 해제 포함)
  (구현 세션의 유일 예외: 화면 없는 카드의 **셀프 완료** — 상태 전이표 규정대로 증거+표식을 남기고 AI가 대행 가능)

| 하고 싶어지는 말 (핑계) | 반박 |
| --- | --- |
| "red지만 이 테스트는 원래 불안정하니 push하자" | 불안정 테스트는 push의 예외 사유가 아니라 **즉시 격리+수리 카드 대상**이다 |
| "코드 안 바꿨는데 한 번 더 돌리면 통과할지도" | 같은 명령 재실행은 아무것도 증명하지 않는다 — 바뀐 게 없으면 결과도 같아야 정상 |
| "리뷰 발견은 사소하니 그냥 머지" | Important 이상은 고치고 3번부터 재검증 — 순서 생략이 사고의 시작 |
| "공지는 머지되고 나서 하자" | 공지는 사전이다 — 사후 공지는 알림이 아니라 통보다 |
