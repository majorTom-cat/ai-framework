# /done — 이슈 #$0 마무리

> ★★**곁에 두 파일이 있다 — 해당 단계에 오면 반드시 읽어라**: `단계상세.md`(§0 1·2단계 경위 · §1~§2 4·6단계 상세 · §3~§6 7~10단계 실행 순서 · §7 완료 보고 · §8 ❌금지) · `함정.md`(실측된 예외·우회 §1~§9). **이 안내를 여기 둔 이유**: 컴팩션은 스킬마다 **앞 5,000토큰만 남기고 뒤를 자르므로**(공식), 본문 뒤쪽에 있는 포인터는 대화가 길어지면 **포인터째로 사라진다.** 이 줄은 앞쪽이라 살아남는다.
> ★★**잘려도 이 셋은 지켜라** — ①**카드를 Close(완료) 하지 마라**(완료 처리는 확답 받은 담당 본인 세션이 `/todo` 검수 경로로 대행한다. 구현 세션의 유일 예외 = 화면 없는 카드의 **셀프 완료**, `단계상세.md` §4) ②**red 인 채 머지 금지** — 「원래 불안정한 테스트」는 예외 사유가 아니라 **격리+수리 카드** 대상이고, 재실행은 증명이 아니다 ③**공지는 사전이다**(사후 공지는 통보). 나머지는 `단계상세.md` §8.

> **★번호가 안 왔으면 여기서 멈춘다** — `#$0`이 숫자가 아니면 문맥으로 추측하지 마라(틀린 번호 = 엉뚱한 카드 닫힘·남의 MR 머지). `/done {번호}` 재호출을 안내하고 종료.

> **계약** · 입력: 이슈번호 · 산출물: 테스트→리뷰→머지(=배포)→라벨 검수요청+검수자 멘션 · 검증: 파이프라인 success+배포 화면 (카드 Close는 사람)

> **예시**: `/done 12`

순서대로 실행하고, **실패하면 그 단계에서 멈추고 보고**하라.
(명령이 이 문서와 repo CLAUDE.md '실행·테스트' 절이 다르면 **CLAUDE.md가 정본**이다.)

1. `git fetch origin` 후 **작업 브랜치에** `git merge origin/main`(왜 병합인가 = `단계상세.md` §0) — 충돌 시 **종류별 규칙대로 해결**(정본 = CLAUDE.md '작업 절차'의 pull·merge 충돌 규칙) 후 진행
   - ★**여기서 «세션 시작 이후 남이 한 일»을 다시 본다** — `/todo` 브리핑은 **세션 시작 시점의 스냅숏**이고, 세션이 길수록 낡는다. `glab mr list` (열린 MR)와 **내 카드가 의존·인접한 카드**를 재조회하라. 겹치는 게 있으면 머지 순서·중복 구현을 **머지 전에** 정리한다(2026-08-31 실측: 시작 스냅숏만 본 세션은 상대가 그 뒤 올린 MR·카드·머지를 끝까지 못 봤다).
2. (마이그레이션 도구 있는 스택만) 새로 받은 마이그레이션을 로컬 DB에 적용 — 명령은 CLAUDE.md '실행·테스트' 절. **★1번에서 main에 내 것보다 나중 타임스탬프의 새 마이그레이션이 들어왔으면 내 마이그레이션을 최신 뒤로 재생성**한다(전역 직렬 자산 — 순서가 꼬이면 스키마가 깨진다).
   - ⚠️**먼저 CLAUDE.md '실행·테스트' 를 보고 컨테이너가 이미 돌리는지 확인하라 — 그러면 이 단계를 건너뛴다.** 호스트에서도 동시에 돌리면 한쪽이 `42P07 … already exists` 로 죽고 **실패 기록만 남아 그 뒤가 전부 막힌다.** 그때는 리셋이 아니라 **`migrate resolve --applied <이름>`** 이다(`P3009` — DB 는 멀쩡하고 기록만 어긋난 상태라 `migrate deploy` 재실행으로는 안 풀린다. 2026-09-07 bnsone 실측).
3. `npm test` — **red면 여기서 멈추고 고친다. green까지.** 변경에 `.gitlab-ci.yml`이 있으면 **`glab ci lint`도**(무효 CI는 테스트가 못 잡는다 — #72)
   — ★**먼저 DB·외부 의존 기동 확인**(/dev 6단계와 동일 — 내려가 있으면 실패가 코드 결함처럼 보인다. 명령은 CLAUDE.md '실행·테스트').
   — ★**`needs`·`rules:changes`·배포 잡을 건드렸으면 `함정.md` §5를 지금 읽어라** — lint 통과가 안전의 근거가 못 되는 유형이다(실사고 8회).
   ★**테스트 변조 자가 점검**: 이번 diff가 *소스와 테스트(또는 CI 임계값)를 동시에* 고쳤다면, 테스트를 통과시키려고 테스트를 약하게 만든 게 아닌지 한 줄로 확인·소명하라(green은 스스로 무력화 가능하다). 실패하는 테스트를 삭제·skip으로 넘긴 흔적이 있으면 되돌린다.
4. **리뷰 = 저장 워크플로 `/merge-review`**(Workflow 도구, 이름 `merge-review`, args `{base, card, externalSurface, level}` — 렌즈 3개 병렬(+ `externalSurface` 면 보안 렌즈 1개 더) + 발견마다 반박 3표, 살아남은 것만 보고). 워크플로가 꺼졌으면 **`/code-review {level}`** — 어느 쪽이든 fresh context(자기 결과 리뷰는 편향). ★**`{level}` 은 짐작 말고 diff 가 정한다**(표 = `단계상세.md` §9): `고위험`·`k8s/**`·인증·권한·결제·마이그레이션이면 `xhigh` · `*.md` 만이면 `medium` · 그 밖은 **`high`**. **`ultra` 는 유료라 금지.** ★**끝나면 «몇 분·읽은 파일 수·발견 수»를 카드 증적에 한 줄로.** Important 이상 발견은 고치고 **테스트 단계부터** 다시.
   diff가 **새 외부 입력 표면을 추가**했으면(신규 엔드포인트·업로드·인증·비밀값) `/security-review` 도 실행 — 매 카드 상시가 아니다(필드 수정 정도는 code-review가 커버. CI 스캔 잡이 있으면 백스톱).
   리뷰 렌즈에 **과잉설계**도 포함(하나뿐인 구현의 추상화·stdlib 재발명·불필요한 신규 의존성) — 발견은 "위치·뭘 지우나·뭘로 대체" 1줄식.
   발견·수리 요약을 카드 댓글 1줄로 남겨라 (증적)
   — ★**리뷰 반영 수정은 «커밋한 뒤에» 재검증하라 — 미커밋 상태에서 복원 명령을 돌리면 그 수정이 통째로 지워진다**(실측 3회). 방법은 **`단계상세.md` §1.**
5. 변경 파일에 공통 영역(src/shared·공용 테이블·CLAUDE.md·package.json)이 포함되면 **여기서 묻지 말고 사실만 챙긴다** — 공지 여부는 7단계 묶음 승인에서 한 번에 확인한다(따로 물으면 같은 결정에 세 번 선다).
  - ★**1단계의 «커밋 메시지 검사» 판정을 여기서 다시 확인한다**(리뷰 반영으로 규칙·절차 문서를 더 건드렸으면 경로가 새로 걸린다) — 경위·푸는 법 = `단계상세.md` §10.
6. **수용 기준 1:1 대조**: 카드의 수용 기준 각 항목 ↔ 구현 증거(테스트·화면)를 하나씩 짝지어 확인 —
   diff 리뷰는 *넣은 것의 결함*만 잡고 *빠뜨린 것*은 못 잡는다. 〔검수확인〕 항목이 **브라우저만으로 재연 가능한지**도 확인하고, 안 되면 카드의 "검수 방법"을 보강하라.
   구현이 docs 스펙과 달라졌다면: `_digest.md` 수정이 포함됐나 확인 + **카드에 "스펙과 달라진 점 + 이유" 댓글을 남긴다**(/dev가 준비한 차이 요약이 있으면 그것으로) + @{기획자} 멘션({기획자}는 실행 시점에 CLAUDE.md 스펙 차이 절에서 읽는다 — 아이디 박제 금지)
   — ★**「검수 방법」에 적힌 화면·계정·양식이 실물로 성립하는지까지 확인하고, 대조 결과를 카드 본문 체크박스에 반영하라**(댓글만으론 `0/N` 으로 남아 완료 판별 불가). 절차·함정은 **`단계상세.md` §2 를 지금 읽어라.**
7. ⏸ **묶음 승인 — 여기서 딱 한 번 선다** → push → `glab mr create --remove-source-branch` (설명에 "관련: #$0") → **머지**.
   **이 단계는 `단계상세.md` §3 을 열어 그대로 실행하라** — 승인 화면 5줄 서식 · 브랜치 삭제 3경로 · auto-merge 조건 · 고위험 레인이 거기 있다.
   — ★**잘려도 지킬 것**: 승인은 **한 화면 5줄·OK 하나**(표·파일 목록 금지) · **셀프승인 레인 한정**(동료 레인·빨간불이면 다시 선다) · **MR 본문에 `Closes`·`Fixes`·`Resolves` 금지**(`관련: #$0` 링크만 — 머지 순간 카드가 자동으로 닫힌다) · **`git add -A`·`add .` 금지**(경로 지목).
   — ★**auto-merge 가 안 걸리거나 실패하면 `함정.md` §1**, **고위험 카드면 `함정.md` §2** 를 읽고 처리하라. 포기·강행 전에 반드시.
8. **머지 완료 확인 — `glab mr view <MR iid>` 로 `state`=`merged` 를 눈으로 본다**(추정 금지). 확인되면 **로컬 브랜치 정리 + 배포 화면 확인**까지가 이 단계다. **절차는 `단계상세.md` §4.**
   — ★**화면 없는 카드**(인프라·docs·API 노출)는 검수요청 없이 **셀프 완료** 경로다 — `함정.md` §9 를 읽고 그대로.
9. **카드 라벨 전환 — `진행중` 제거 + `검수요청` 추가(둘 다 명시적으로)** + 검수자 멘션 댓글. **라벨 먼저 → 부탁 댓글 나중**(알림은 댓글 시점의 라벨로 걸러진다). **절차·멘션 대상 판정은 `단계상세.md` §5.**
10. **이 세션에서 띄운 서버·백그라운드 프로세스 전부 종료 + 포트 비점유 확인** — **PID 기준으로만**, 이름 기반 일괄 종료(`taskkill /IM node.exe` 류) **금지**(동료·IDE 프로세스까지 죽인다). **명령은 `단계상세.md` §6.**
    → `/todo` 실행해 다음 작업 선택지 제시

**완료 보고 증거**(§7)와 **❌ 금지 절**(§8)은 `단계상세.md` 에 있다 — 보고 직전에 §7 을 읽어라.
