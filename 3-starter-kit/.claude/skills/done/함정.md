# /done 함정 목록 — 실측 예외 모음 (본문이 가리킬 때 읽는다)

> 여기 있는 것은 전부 **실제로 겪은 실패와 그 우회**다. 본문 절차가 "실패하면 함정.md §N"이라고 가리키면 해당 절만 읽어라.

## §1 auto-merge가 안 걸리거나 실패할 때

- **`requires a passing pipeline`으로 실패하면**(MR 생성 직후엔 파이프라인이 아직 "생성 중"이라 auto-merge를 못 건다 — 파일럿 실측): MR 파이프라인이 **시작(running)될 때까지 수 초 기다렸다 재시도**하거나, 이미 통과(success)했으면 **일반 머지**(`glab mr merge`)로 진행한다. "설정 실패=끝"이 아니다.
- **이미 종결(success)된 파이프라인 위에 auto-merge를 걸면 영구 대기**한다 — 발동할 이벤트가 없다(파일럿 #14 실측 — 커밋 push 후 재파이프라인이 안 붙어 auto-merge가 안 닫힘). 그래서 본문 규칙이 "running/pending일 때만 auto-merge"다.
- **status가 `manual`(blocked)이면** auto-merge 대상이 아니다 — 실패도 아니고 게이트 승인 대기다. `node scripts/pipeline-verdict.cjs <PID>`로 판정하고(1행 토큰: 실패|진행중|게이트대기|종결초록 — 남은 게이트 잡 ID까지 출력) `게이트대기`면 §2 승인 절차로 처리한다(status 한 값 판정 금지).
- **그래도 `glab mr merge --auto-merge`가 "Not Allowed"로 실패하면 raw API로 우회하라**(bnsone !31 실측: 파이프라인이 running인데도 래퍼가 2회 실패, 아래 API는 성공):
  `glab api --method PUT "projects/:id/merge_requests/:iid/merge" -f merge_when_pipeline_succeeds=true`
  래퍼의 사전검사가 서버 상태와 어긋나는 경우다 — **서버가 거부한 게 아니므로 포기하지 마라.** 설정 후 MR 상태를 재조회해 `merge_when_pipeline_succeeds: true`를 확인한다.

## §2 고위험 "승인"의 실제 행동 — 상황별

- **티어마다 다르다**(파일럿 실측): **무료 티어**는 MR 필수 승인이 없으므로, 승인자가 **그 MR 파이프라인의 `high-risk-gate` manual 잡을 실행(Play)** 하는 것이 곧 승인이다 — 그래야 파이프라인이 success가 되고 "Pipelines must succeed"가 풀려 머지된다. **Premium+ 티어**면 MR approve로 강제. 승인(잡 실행 또는 approve)이 붙은 뒤 머지.
- **골격 주간(팀 합류 전·공통 개발자 혼자)이고 이 카드가 최초 구축(#1)이면**: 승인할 동료가 아직 없다 — CLAUDE.md 금지의 **'카드 #1 최초 구축' 예외**로 **공통 개발자가 직접 머지**한다. ★단 게이트 잡은 **실행자=작성자면 exit 1**이므로 자기 MR의 ▶를 그냥 누르면 거부된다 — **MR에 `셀프승인` 라벨을 붙이고 새 파이프라인을 돌린 뒤** 잡을 실행하라(증적 3종은 /done 7단계 ②와 동일). "승인 대기"로 무한정 멈추지 마라. 동료 승인 레인은 팀 합류 후부터. (공통 개발자 가이드 Day 6)
- **동료를 요청했는데 지금 없으면**(전원 바쁨): **표준은 ②(셀프 승인)다 — 기다리지 말고 ②로 가라.** 굳이 그 동료의 눈을 받아야 할 이유가 있을 때만 카드에 `"승인대기(!MR번호)"` 댓글 + `--label 승인요청`을 남기고 세션을 끝내라(**단 종료 전 10번 서버·포트 정리는 반드시 수행**) — 다음 /todo 때 이어받는다(상태 전이표). (등급 기준은 CLAUDE.md '머지 등급' 절)

### §2-a 레인 ① 동료 승인 — **선택** 레인(요청할 때만). 실행 방법
- `glab mr create --reviewer <아이디>` + 카드에 요청 댓글: `"@아무개 고위험 리뷰 부탁 — {유형 한 줄}. 자기 Claude 세션에서 /todo 열면 뜹니다 — '승인' 한마디면 끝(웹 안 열어도 됨). 웹이 편하면 ▶ 1클릭: {잡URL}"`
- **카드에 `--label 승인요청`을 먼저 붙이고 나서 요청 댓글을 단다**(라벨 먼저 — 알림은 댓글 시점의 라벨로 걸러진다, /done 9단계 순서 규칙과 동일) — 채팅 알림 채널이 이 라벨로 "남의 손이 필요한 승인 부탁"만 울린다(셀프 승인은 조용해야 해서 `고위험`으론 못 거른다 — 2026-08-12 오너 결정). 세트에 없으면 `glab label create --name 승인요청 --color "#ed9121" --description "동료 승인 대기 — 승인·머지 후 제거"` 1회. **동료 play·머지가 끝나면 `--unlabel 승인요청`으로 뗀다**(단 채 방치 = 채널이 계속 대기로 안다).
- ★**잡 실행(▶)은 동료 세션의 몫이다 — 작성자인 네가 API로 눌러도 게이트가 거부한다**(`.gitlab-ci.yml` `.peer-approval-gate`가 실행자=MR 작성자면 exit 1. 네 glab 토큰으로 play하면 실행자가 너로 찍힌다). 동료의 play 후 파이프라인 초록 확인 → 머지는 네가 이어서.
  ("승인 확답을 받았으면 네가 직접 play하라"던 옛 지시(2026-08-06)는 판정 잡 없던 시절 기준 — **폐기**. 확답을 받았어도 작성자 play는 실패한다.)
- 채팅 확답만 오고 동료가 잡을 못 눌러 주면: **②로 전환**하고 카드에 `"동료 {아이디} 채팅 승인 — 잡 실행 불가로 셀프승인 전환"` 사유 댓글 후 ②의 라벨 절차.
- **CLI 승인이 기본, 잡 URL은 부가다**(이 팀은 GitLab 웹을 안 연다 — 실측. 잡 URL: `glab api "projects/{ID}/pipelines/{PID}/jobs?scope[]=manual"` → `high-risk-gate`의 `web_url`).
- 승인자 조건: 구현 미참여자 · 개발자(코드를 읽는 사람) · 자기 MR 자기 승인 금지.

### §2-b 레인 ② 셀프 승인 — **표준** 레인. 라벨이 유일한 열쇠
- 증적 3종(CLAUDE.md '머지 등급': fresh-context AI 리뷰 · 본인 diff 직접 확인 · 카드에 "셀프 승인"+사유+**경고 요지**+확인 범위)을 **전부 남긴 뒤에만**. 증적 없는 ②는 셀프 승인이 아니라 **무승인**이다.
- ★**리뷰가 낸 경고는 채팅으로 사람에게 보고한다** — 이 레인이 제3자 눈 대신 택한 대가가 그 보고다. 경고를 무시하고 머지하면 **그 사유까지** 카드 댓글에 남긴다(무시 건수는 `/metrics`가 센다).
- ★증적 뒤 `glab mr update <iid> --label 셀프승인` — 게이트 잡이 이 라벨을 보고 exit 0 한다.
  → **새 파이프라인을 돌린 뒤**(라벨은 파이프라인 **생성 시점**에 읽힌다 — 빈 커밋 push 또는 Run pipeline) 네가 play해도 통과한다. 라벨만 붙이고 재실행하면 반영 안 된다.
  라벨이 프로젝트 세트에 없으면 `glab label create --name 셀프승인 --color "#dbdbdb" --description "고위험 게이트 셀프 승인 표식 — 증적 3종 필수"` 1회 생성 후.

### §2-c 게이트 잡이 아예 없을 때
- `high-risk-gate`·`high-risk-label-gate`가 잡 목록에 하나도 없으면 **auto-merge·셀프 머지 금지**. 라벨 누락이면 `--label 고위험` + 새 파이프라인부터(라벨은 파이프라인 생성 시점에 읽힌다).
- 그래도 안 생기면(한글 라벨 CI 매칭 미실측): 동료가 diff 확인 후 **직접 머지**(또는 승인 댓글 후 네가 머지)하고 카드에 `"게이트 잡 없음 — 사람 승인으로 대체"` 한 줄. **부탁할 때 §2-a처럼 `--label 승인요청`을 붙이고 끝나면 뗀다**(남의 손이 필요한 순간 = 채널 알림).
- **`고위험` 라벨이 CI 경로매칭보다 정본** — 라벨 달린 카드는 사람 승인 없이 절대 머지하지 마라.
- 경로 기반 잡(`high-risk-gate`)은 **MR 도중 유발 파일을 되돌리면 소멸한다**(!113 실측) — 그래서 라벨 입구(`high-risk-label-gate`)가 필요하다.

## §3 카드 본문 체크박스 갱신의 함정

- **본문 일괄 치환 금지** — 설명문 속 예시 `- [ ]`까지 바뀌고 줄이 뭉개진다(실측 사고: 카드 본문 손상 후 복구). **해당 항목 줄만 지목해 고치고**, 갱신 후 `task_completion_status`(N/M)를 재조회해 확인한다.

## §4 auto-merge 대기 중인데 세션을 끝내야 할 때

- 카드에 "MR 준비완료(!MR번호)" 댓글만 남겨라(**단 종료 전 10번 서버·포트 정리는 반드시**). 화면 확인·검수요청 전환은 다음 /todo 때 머지 확인 후 이어서 수행한다(상태 전이표 참조).
- **파이프라인이 실패(failed)면** "준비완료"가 아니다 — 실패 로그 요지를 카드에 남기고 **테스트 단계(3)부터 재작업**한다(실패면 auto-merge는 안 걸린다).
- **status가 `manual`(blocked)이면** "준비완료"도 실패도 아니다 — 게이트 승인 대기이니 `"승인대기(!MR번호)"` 댓글을 남겨라(§2·상태 전이표, 판정기: `scripts/pipeline-verdict.cjs`). 다음 /todo가 승인 여부를 확인해 이어받는다.

## §5 CI 설정을 건드린 MR — lint 통과가 안전의 근거가 아니다

- `needs`·`rules:changes`·배포 잡을 바꿨으면 **`glab ci lint` 통과는 근거가 못 된다** — 비교할 diff가 없으면 `changes:`가 참으로 계산돼 **원리상 안 잡힌다**(실사고 8회, 잡 0개 파이프라인). **먼저 `_reference/ci-needs.md`를 읽어라.**
- 확인 방법: 머지 후 **문서만 바꾼 커밋을 main에 한 번 올려** 파이프라인이 잡 0개가 아닌지 본다. **새 브랜치 첫 푸시·빈 커밋은 항상 초록이라 근거가 안 된다.** 확인 전엔 "CI 정상"이라고 보고하지 마라.

## §6 무음으로 새는 것 — 경고·라벨

- **`success`인데 경고인 경우**: `allow_failure: true` 잡(`density-check`·`tamper-check`·`ai-connectivity`)은 실패해도 `status`가 `success`로 남고, 경고는 `detailed_status.label`("passed with warnings")에만 뜬다(파일럿 2863 실측 2026-08-06). 조회: `glab api "projects/:id/pipelines/{PID}"`. 이 팀은 GitLab 웹을 안 여니 **네가 말하지 않으면 아무도 모른다** — 실패한 잡 이름 + 로그 요약 한 줄을 최종 보고에.
- **세트에 없는 라벨은 조용히 실패한다**(bnsone 실측). `셀프완료`·`검수요청` 등이 없으면 `glab label create` 1회 후 진행. "라벨 없이 댓글 표식만"이던 옛 규칙이 셀프완료 카드를 라벨 무기록으로 만들어 **/metrics 라벨 커버리지를 9.5%로 무너뜨린 주범**이다 — 댓글은 증거, **라벨이 기록의 정본**.
- 라벨 전환·댓글 뒤에는 **반드시 `glab issue view $0`로 재조회**한다 — 명령 성공 출력 ≠ 반영.

## §7 설정·매니페스트를 바꾼 MR — "머지 = 반영"이 아니다

- 코드는 이미지로 배포돼도 **`k8s/*.yaml`·configmap·env 류는 배포 잡이 apply 하지 않으면 안 붙는다.** 8단계의 "배포된 화면 확인"은 이 전제를 안 깔고 있다.
- **확인 순서**: ①`.gitlab-ci.yml`의 배포 잡 스크립트에 그 파일을 **apply 하는 단계가 있는지** 본다 ②없으면 사람이 적용할 때까지 **화면 확인을 유예**하고 그 사실을 카드에 남긴다.
- **증상이 배포 문제로 안 보인다**: 파이프라인 초록·헬스체크 초록인데 값만 안 붙는다 — bnsone #63 실측에서는 로그인만 **무작위 403(Invalid origin)**으로 나타나 원인 추적이 늦어졌다("머지=반영"으로 읽히는 스킬 문구가 원인).
- 배포 잡이 매니페스트를 적용하도록 고치는 것이 정공법이다(그 repo의 배포 레시피 몫). 이 절은 그때까지의 안전장치다.
