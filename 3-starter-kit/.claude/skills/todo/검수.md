# /todo 검수·승인 대행 절차 (본문 ① 멘션 처리가 가리킬 때 읽는다)

> **정본**: CLAUDE.md 카드 상태 전이표의 "절차 = /todo 검수"가 가리키는 검수 절차가 이 파일이다.
> ⚠️ 부작용 있는 절차 — 게이트 잡 실행·close 대행·라벨 전환. 어느 것도 **사용자 확답 전에 실행 금지**.

## §1 "고위험 리뷰 부탁" 멘션 — 승인 대행 (내가 승인자 세션)

- 그 MR의 diff를 읽고 **고위험 유형별 핵심**(인증: 권한 검사·세션 처리 / 마이그레이션: 되돌리기·데이터 손실 / shared: 기존 사용처 파급) 관점의 **검토 요약을 사용자에게 제시**하라(내가 구현에 참여하지 않은 카드여야 한다).
- **사용자가 "승인" 확답을 주면 네가 대신 실행한다**(웹 안 열어도 됨 — 게이트 잡은 실행자를 판정하므로 **승인자 세션인 네가 눌러야** 통과한다. 작성자 세션이 누르면 exit 1).
  실행 방법은 **/done `함정.md` §2 절차대로** — 단 **게이트 잡 두 입구(`high-risk-gate`·`high-risk-label-gate`)가 동시에 떠 있으면 둘 다 play**해야 머지된다. 문제가 보이면 코멘트로 반려.
- ★**확답 없이 실행 금지** — 이 게이트의 의미가 "작성자 아닌 **사람**의 눈"이다(네 검토 요약은 참고자료일 뿐 승인이 아니다). 이건 **다른 사람의 머지를 막고 있으니 우선 처리**.

## §2 "검수 부탁" 멘션 — 검수 대행 (내가 이 카드 검수 담당)

- 검수 서버에서 카드의 "검수 방법"대로 **3기준(카드 기대대로 동작 · PC/모바일 · 이상 입력)**을 확인하라(검수는 개발자든 비개발자든 **화면 기준** — 코드 품질은 CI·AI리뷰·고위험 승인이 이미 봤다).
- 확인 결과를 보고하고 — **사용자가 화면을 보고 "이상 없음" 확답을 주면 close를 대행한다**(구현자 본인이어도 된다):
  ①`glab api user`로 세션 계정을 확인해 증적에 실명으로 남긴다(카드 "검수" 필드와 달라도 대행 자체는 막지 않는다) ②증적 댓글(확답자·일시+3기준 결과) ③`--unlabel 검수요청` 후 `glab issue close` → 재조회.
- ★**확답 없이 닫는 것은 어떤 경로로도 금지** — "테스트 통과했으니"·"머지됐으니"·"별 문제 없어 보이니"는 확답이 아니다. 라벨을 붙인 직후 스스로 닫는 흐름(2026-08-06 실측: 검수요청 9건 중 5건이 라벨 2초 뒤 닫힘)이 이 규칙이 막으려는 바로 그 사고다.
- **전언("검수자가 OK했대요")으로는 닫지 않는다** — 확답은 지금 이 세션의 사용자에게서 직접 받아라(그 사용자가 구현자 본인이어도 된다. 남이 봤다는 말을 옮기는 건 확답이 아니다). 문제면 반려 댓글(무엇을/했더니/기대/실제) + `진행중` 되돌림 (상세는 docs/00_Guide GitLab 가이드 §5)
