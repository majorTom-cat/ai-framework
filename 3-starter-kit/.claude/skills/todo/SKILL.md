> **예시**: `/todo` (세션 시작·이슈 끝나면 자동 실행되기도 — 내 카드·멘션 브리핑)

> **/start와의 경계**: 환경·구축 단계 진단(첫날·새 팀원·깨졌을 때)이 목적이면 `/start`. 이 스킬은 **오늘 내 카드·멘션 브리핑**이다.

# 현재 상태 (자동 조회됨)

> ⚠️**이 브리핑은 «지금 이 순간»의 스냅숏이다 — 세션이 길어지면 낡는다.** 남이 그 뒤에 올린 MR·바꾼 카드·머지는 여기 안 들어 있다. **다시 보는 지점은 `/done` 1단계**(머지 전 재조회 — 그 스킬이 강제한다). 오래된 세션에서 "지금 열린 MR 없습니다"라고 답하지 마라: 그건 **아까** 없었다는 뜻이다.

> **계약** · 입력: 없음 · 산출물: 내 카드·멘션 브리핑 + 번호 선택지 — 기본 조회형 · 검증: 조회형 — 별도 없음. **예외 부작용**: 검수·승인 멘션 처리 시 게이트 잡 실행·close 대행·라벨 전환이 일어난다(아래 절차 절) · 0-d 는 **내 알림함**의 끝난 To-Do 를 지운다(확인 후)

내 담당 열린 이슈:
!`glab issue list --assignee=@me 2>&1 | head -30`

내게 온 To-Do·멘션:
!`glab todo list -P 100 2>&1 | head -60`

# 할 일

> ★★**곁에 두 파일이 있다 — 해당 자리에 오면 반드시 읽어라**: `스캔상세.md`(0-b·0-c·0-d 스캔의 경위와 함정 §1~§3) · `검수.md`(검수·승인 대행 절차). **이 안내를 여기 둔 이유**: 컴팩션은 스킬마다 **앞 5,000토큰만 남기고 뒤를 자르므로**(공식), 본문 뒤쪽 포인터는 대화가 길어지면 **포인터째로 사라진다.**
> ★★**잘려도 이 둘은 지켜라** — ①**각 선택지는 «무엇이 달라지나»를 한 줄로 적는다. 내부 분류명 단독 금지**(«잔손질»·«수거함»은 사용자에게 아무 정보가 아니다 — 2026-08-28 실측 오너 "무슨말이야" 2회) ②**착수 결정은 사용자가 한다 — 네가 골라서 시작하지 마라.**

**0. 스펙 변경 감지 (선택지 제시 전)**: `git fetch origin -q` 후 `git log origin/main --oneline -10 -- docs/` 로 최근 docs 커밋을 훑어라.
  - **내 열린 카드가 가리키는 정본 경로**(카드 본문의 docs 참조)와 겹치는 변경이 있으면 브리핑 **맨 위에 ⚠️ 경고**: "카드 #N의 근거 문서가 바뀜({커밋 한 줄}) — 착수·진행 전 변경 절 확인, 기획 변경이면 `/change`".
  - (기획자는 카드 없이 웹에서 문서를 고칠 수 있다[길 A] — 이 스캔이 그 조용한 변경을 다음 세션 시작에 잡는 백스톱이다. fetch만 하고 pull·checkout은 하지 마라 — 조회형 스킬이다.)
  - **+ 열린 MR 중 docs 변경 확인**: `glab mr list` 에 docs/만 바꾸는 열린 MR이 있으면 ⚠️ "기획자 문서 변경이 main에 아직 안 들어옴(!N) — Merge 확인 필요" 경고(기획자가 웹 편집 후 Merge를 안 누르고 이탈하면 이 조회에만 걸린다).

**0-b. 내 발행 카드 응답 대기 스캔**: `glab api "projects/:id/issues?state=opened&author_username=<me>&per_page=100"` 로 내 발행 카드를 뽑아, **타인이 남긴 마지막 활동**(notes 최신 + 본문 체크박스) 뒤에 내 응답이 없으면 브리핑에 올린다. **내가 낸 카드인데 담당자가 남이면 To-Do 에 안 뜬다**(체크박스 변경은 알림 자체가 없다).
  - ⚠️**`glab api` 는 `--jq` 를 안 받는다 — 거를 때는 `| jq` 로 파이프하라.** 루프·서브셸 안이면 빈 결과가 «응답 대기 없음»으로 조용히 지나간다.
  - **시안 선택 카드는 체크 수만으로 "채택 확정" 단정 금지** — 체크 뒤 댓글이 있으면 `⚠️ 기획자 요청 미반영 {N}일` 이 먼저다.
  - **경위·판정 서식은 `스캔상세.md` §1.**

**0-c. 안 고쳐진 마찰 스캔**: 두 값을 **함께** 센다 —
  ① 막힘: `grep -n '\[막힘\]' docs/friction.md | grep -v '^[0-9]*:>' | grep -v '\[닫힘:'`
  ② 안 닫힌 줄 전부: `grep -E '^[0-9]{4}-' docs/friction.md | grep -v '\[닫힘:' | awk '$1>="2026-08-31"' | wc -l`(토큰 신설일 이후만)
  - 결과가 있으면 브리핑에 **「막힘 {N}건 / 안 닫힌 줄 {M}건 — 가장 오래된 {날짜}({N}일째)」** 한 줄과 선택지 하나를 올려라(고치는 건 카드가 아니라 그 자리 수리 — `/fix` 아님).
  - ★★**올리기 전 둘**(경위 `스캔상세.md` §2): ①`grep -E '킷 반영 완료|해소 확인'` 로 **«닫힘 표시만 빠진 줄»을 갈라라** — 안 가르면 숫자가 부푼다 ②**「집습니다」 직전에 그 카드 최신 댓글 3건을 다시 읽어라** — 착수 댓글은 push 보다 먼저 온다.
  - ★★**«막힘»만 세면 «불편했다»급이 통째로 안 보인다**(2026-09-07 실측: 막힘 0건인데 안 닫힌 줄 18건). ⚠️**M 을 «미해결 M건»이라 단정하지 마라** — 갈라기 전에 **그 줄의 «수리 후보» 문장까지 읽어라**(앞머리만 보면 고쳐진 듯 읽힌다): ㉠이미 고쳐짐 ㉡진짜 미수리 ㉢기록만.
  - ★**사용자가 «고치자»를 고르면 착수 전에 수거 카드에 「집습니다」 댓글 한 줄**(다른 세션이 같은 줄을 동시에 붙잡는다). 안 닫힌 줄이 있는데 수거 카드에 대응 댓글이 없으면 그 자리에서 멘션 댓글을 남겨라.
  - ★★**「집습니다」 전에 «지금 최신인가»를 확인하라** — ①`git fetch -q origin` 뒤 **최신 main 기준**으로 다시 센다 ②`glab mr list` 로 그 줄을 이미 고치는 **열린 MR** 이 없는지 본다. 옛 트리에서 판정하면 남이 방금 닫아 머지한 줄까지 집는다(2026-09-09 실측 2회 — 한 번은 착수 **2분** 차이).
  - ⚠️**같은 수가 매 세션 뜨면 경보가 아니라 고장이다** — 옛 줄에 `[닫힘:구기록]` 을 붙여 0 으로 만들고 넘어가라.
  - **왜 이렇게 세는지·그 밖의 함정은 `스캔상세.md` §2 를 읽어라.**

**0-d. 끝난 To-Do 비우기**: `glab todo list -P 100 -F json --jq '.[] | select(.target.state != "opened") | "\(.id)\t\(.target.state)\t\(.target.title)"'` 로 **이미 닫힌 카드·머지된 MR** 항목을 뽑아 **사용자에게 목록을 보이고**, 확인받은 뒤 `glab todo done <ID>` 로 **뽑은 ID 만 하나씩** 지운다. GitLab To-Do 는 스스로 사라지지 않는다.
  - 바뀌는 건 **내 알림함뿐**이다. 그래도 **지우기 전에 목록을 보여라** — 남의 검수·승인 요청이 섞여 있을 수 있다.
  - ★★**`glab todo done --all` 을 쓰지 마라 — 위 «닫힌 것만» 필터를 따르지 않고 «열린 것까지» 전부 지운다**(2026-09-09 bnsone 실측: 닫힌 8건을 지우려다 **열린 4건이 함께 사라져** `POST projects/:id/issues/{iid}/todo` 로 복원했다). ID 나열도 **20건 안팎씩 나눠** 돌리고, **지운 뒤 재조회로 건수를 확인하라**(45건 일괄은 첫 건만 찍히고 44건이 시도조차 안 됐다).
  - ⚠️**조회는 `glab todo list`(표)로 — `glab api todos` 는 18만 자를 문맥에 붓는다.** ★**`-P 100` 을 빼지 마라 — 기본 30개라 조용히 잘린다.**
  - **경위는 `스캔상세.md` §3.**

**먼저 (선택지 제시 전)**: 재개 마커는 카드 **댓글**에 있다 — 위 이슈 목록의 내 열린 카드 각각을 `glab issue view <번호> --comments` 로 훑어라(자동 조회된 목록엔 댓글이 없다). ★**여러 장이면 셸 반복문 금지 — `스캔상세.md` §1-b.** `"MR 준비완료(!번호)"`·`"승인대기(!번호)"` 가 있으면 이어서 처리 — **절차는 `스캔상세.md` §4 를 읽고 그대로.**
  - ★**파이프라인 status 한 값으로 판정하지 마라** — `manual`(blocked)은 실패가 아니라 게이트 승인 대기다. `node scripts/pipeline-verdict.cjs <PID>` 1행 토큰으로 판정한다.

위 데이터를 요약해 **번호 선택지**로 제시하라.
★**각 선택지는 «무엇이 달라지나»를 한 줄로 적는다 — 내부 분류명 단독 금지**("잔손질"·"수거함"·"증분" 같은 말은 사용자에게 아무 정보가 아니다. 2026-08-28 실측: 오너 "무슨말이야" 2회). CLAUDE.md 세션 규칙의 «무엇이 어떻게 달라지는지로 말하라»는 **본문만이 아니라 고르라는 항목에도** 적용된다 — 고를 때가 정작 그 정보가 필요한 순간이다.

- ① 새 멘션·댓글이 있으면 **그것부터 (권장 표시)** — 내 카드만이 아니라 **남의 카드에 달린 내 멘션도**(To-Do 목록이 그것이다). 대기·무효 통지·반려 전부 포함 (무효 멘션을 놓치면 없어진 카드를 만들게 된다). **무효 통지에는 확인 댓글 한 줄(ack)로 답한다.** 기획 변경이 맞으면 `/change` 를 제안
  - **"고위험 리뷰 부탁"(승인 대행)·"검수 부탁"(검수 대행) 멘션이 있으면 — 지금 `검수.md`를 읽고 그대로 진행하라.**
    ⚠️부작용 있는 절차다(게이트 잡 실행·close 대행·라벨 전환) — 어느 것도 사용자 확답 전에 실행 금지.
- ② 다음 대기 이슈 (제목·한 줄 요약)
- ③ 보류 / 직접 지정

규칙:
- 착수 결정은 사용자가 한다. 네가 골라서 시작하지 마라.
- ★**카드 본문의 «크기: 작은 수정(/fix)» 표시를 선택지에 한 낱말로 병기하라**(«#189 … — 작은 수정»). 경위 = `스캔상세.md` §5.
- 사용자가 고르면: 기능 개발은 `/dev {번호}`, 작은 수정은 `/fix {번호}` 실행을 제안하라.
- 조회가 실패하면(토큰 등) 원인과 해결법(`glab auth login`)을 알려라.
