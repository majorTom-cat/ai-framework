> **예시**: `/todo` (세션 시작·이슈 끝나면 자동 실행되기도 — 내 카드·멘션 브리핑)

> **/start와의 경계**: 환경·구축 단계 진단(첫날·새 팀원·깨졌을 때)이 목적이면 `/start`. 이 스킬은 **오늘 내 카드·멘션 브리핑**이다.

# 현재 상태 (자동 조회됨)

> ⚠️**이 브리핑은 «지금 이 순간»의 스냅숏이다 — 세션이 길어지면 낡는다.** 남이 그 뒤에 올린 MR·바꾼 카드·머지는 여기 안 들어 있다. **다시 보는 지점은 `/done` 1단계**(머지 전 재조회 — 그 스킬이 강제한다). 오래된 세션에서 "지금 열린 MR 없습니다"라고 답하지 마라: 그건 **아까** 없었다는 뜻이다.

> **계약** · 입력: 없음 · 산출물: 내 카드·멘션 브리핑 + 번호 선택지 — 기본 조회형 · 검증: 조회형 — 별도 없음. **예외 부작용**: 검수·승인 멘션 처리 시 게이트 잡 실행·close 대행·라벨 전환이 일어난다(아래 절차 절) · 0-d 는 **내 알림함**의 끝난 To-Do 를 지운다(확인 후)

내 담당 열린 이슈:
!`glab issue list --assignee=@me 2>&1 | head -30`

내게 온 To-Do·멘션:
!`glab todo list -P 100 2>&1 | head -60`

# 할 일

**0. 스펙 변경 감지 (선택지 제시 전)**: `git fetch origin -q` 후 `git log origin/main --oneline -10 -- docs/` 로 최근 docs 커밋을 훑어라.
  - **내 열린 카드가 가리키는 정본 경로**(카드 본문의 docs 참조)와 겹치는 변경이 있으면 브리핑 **맨 위에 ⚠️ 경고**: "카드 #N의 근거 문서가 바뀜({커밋 한 줄}) — 착수·진행 전 변경 절 확인, 기획 변경이면 `/change`".
  - (기획자는 카드 없이 웹에서 문서를 고칠 수 있다[길 A] — 이 스캔이 그 조용한 변경을 다음 세션 시작에 잡는 백스톱이다. fetch만 하고 pull·checkout은 하지 마라 — 조회형 스킬이다.)
  - **+ 열린 MR 중 docs 변경 확인**: `glab mr list` 에 docs/만 바꾸는 열린 MR이 있으면 ⚠️ "기획자 문서 변경이 main에 아직 안 들어옴(!N) — Merge 확인 필요" 경고(기획자가 웹 편집 후 Merge를 안 누르고 이탈하면 이 조회에만 걸린다).

**0-b. 내 발행 카드 응답 대기 스캔**: **내가 author지만 담당자는 남인 열린 카드는 To-Do(멘션)에 안 뜬다** — 체크박스 변경은 GitLab 알림 자체가 없다(bnsone 실측 2026-08-19: 시안 D안 단독 체크가 4일 방치, 오너가 전수 확인을 대신함 = 브리핑 실패).
  - `glab api "projects/:id/issues?state=opened&author_username=<me>&per_page=100"` 로 내 발행 카드를 뽑고, 각 카드의 **타인이 남긴 마지막 활동**(notes 최신 + 본문 체크박스) 뒤에 내 응답이 없으면 브리핑에 올린다(카드 20~30장 무지연 실측).
  - **시안 선택 카드는 체크 상태와 그 뒤 댓글을 함께 브리핑한다 — 체크 수만으로 "채택 확정" 단정 금지**(실측: 체크 12분 뒤 수정 요청 댓글, 체크 직후 개선 8건 — 체크는 "이 방향이 좋다"는 표시일 수 있다. 채택 여부는 기획자 확답 사항).
    체크 1개여도 **그 이후 댓글이 있으면 `⚠️ 기획자 요청 미반영 {N}일`이 먼저**다. 이후 댓글이 없을 때만 `채택 가능 — 채택 의사 확인 후 /ui 시안 채택 #N, 대기 {N}일`(2개+ = 결정 대기. **같은 취지 재촉 반복 금지** — 오너 지적 08-18).

**0-c. 안 고쳐진 마찰 스캔**: `grep -n '\[막힘\]' docs/friction.md | grep -v '^[0-9]*:>' | grep -v '\[닫힘:'` — 결과가 있으면 브리핑에 **"안 고쳐진 막힘 {N}건"** 한 줄과 선택지 하나를 올려라(고치는 건 카드가 아니라 그 자리 수리 — `/fix` 아님).
  - 왜: `[막힘]`은 **누구에게도 배정되지 않아 멘션·카드 조회에 안 걸린다.** 그래서 3~5일씩 아무도 안 집었고 오너가 물어야만 드러났다(2026-08-31 실측 3건).
  - ⚠️두 번째 `grep -v` 는 **파일 머리의 설명문(`>` 로 시작)을 뺀다** — 머리가 `[막힘]` 형식을 설명하고 있어서 안 빼면 **매 세션 «3건»이 상수로 뜬다**(2026-08-31 실측: 이 스캔을 만든 그 커밋에서 바로 걸렸다). 상수로 뜨는 경보는 곧 안 읽힌다.
  - ⚠️**`[닫힘:` 토큰은 2026-08-31부터다** — 그 이전 줄은 자유서술로 닫혀 있어 이 조회에 «안 닫힘»으로 잡힌다. 옛 줄이 섞여 나오면 **그 자리에서 훑어 닫은 것에 `[닫힘:구기록]`을 붙여라** — 한 번만 하면 다음 세션부터 0이 된다. 그 전까지는 **건수를 단정하지 마라**(키워드 집계는 양쪽으로 틀린다 — 세 번 세어 23·17·19).
  - ⚠️**같은 수가 매 세션 뜨면 그건 경보가 아니라 고장이다** — 바로 위 절차대로 옛 줄을 닫아 0 으로 만들고 넘어가라(2026-08-31 실측: bnsone 이 32건을 상수로 띄우고 있었다).

**0-d. 끝난 To-Do 비우기**: 위 목록에서 **대상이 이미 닫힌 카드·머지된 MR**인 항목은 지워라 — `glab todo list -P 100 -F json --jq '.[] | select(.target.state != "opened") | "\(.id)\t\(.target.state)\t\(.target.title)"'` 로 뽑아 **사용자에게 목록을 보이고**, 확인받은 뒤 `glab todo done <ID>`(전부면 `glab todo done --all`).
  - 왜: GitLab To-Do 는 **스스로 사라지지 않는다.** 아무도 안 지우면 한 달 전 멘션이 매 세션 그대로 뜬다 — 0-c 와 같은 고장이다(같은 목록이 상수로 뜨면 아무도 안 읽는다). 2026-09-01 실측: 대기 **29건 중 22건(76%)**이 이미 닫힌 카드·머지된 MR이었다(가장 오래된 것은 33일 전).
  - 바뀌는 건 **내 알림함뿐**이다(카드·MR·라벨은 안 건드린다). 그래도 **지우기 전에 목록을 보여라** — 남이 보낸 검수·승인 요청이 섞여 있을 수 있다.
  - ⚠️조회는 **`glab todo list`(표)로 한다 — `glab api todos` 는 JSON 전문이라 한 번에 18만 자를 문맥에 붓는다**(2026-09-01 실측 179,951자 → 5,144자, 35배). `| head -N` 은 응답이 **개행 없는 한 줄**이라 아무것도 못 자른다. 표에는 `glab todo done` 에 필요한 **ID** 열도 있다. ★**`-P 100` 을 빼지 마라 — 기본이 30개라 조용히 잘린다**(2026-09-01 실측: 31건 대기인데 기본 조회는 30건만 줬다. 잘린 목록으로 «멘션 없음»을 단정하는 것이 이 킷이 금지하는 바로 그 사고다).

**먼저 (선택지 제시 전)**: 재개 마커는 카드 **댓글**에 있다 — 위 이슈 목록의 내 열린 카드 각각을 `glab issue view <번호> --comments` 로 훑어 마커를 스캔하라(자동 조회된 목록엔 댓글이 없다). 마커가 있으면 이어서 처리 —
- `"MR 준비완료(!번호)"`(auto-merge 대기로 끝낸 경우): 머지 여부를 조회하고, 머지됐으면 /done 의 남은 단계(화면 확인 → 라벨 `검수요청` + 댓글)를 마저 수행. **머지 안 됐고 파이프라인이 실패**면 `/fix`(또는 /dev)로 원인 수정부터.
  - **status가 `manual`(blocked)이면 실패가 아니라 게이트 승인 대기다** — 판정은 `node scripts/pipeline-verdict.cjs <PID>`(1행 토큰: 실패|진행중|게이트대기|종결초록·잡 단위 판정)로. `게이트대기`면 승인 절차로(/done 함정.md §2), `종결초록`이면 종결로 취급(status 한 값 판정 금지 — bnsone #34 실측).
- `"승인대기(!번호)"`(고위험 카드가 **선택한 동료 승인**을 못 받아 끝낸 경우 — 경고 레인에선 드물다): 승인이 붙었으면 머지 → `--unlabel 승인요청`(붙어 있으면 — 알림 라벨 정리) → /done 남은 단계로.
  - 아직이면 리마인드하되, **기다릴 이유가 없어졌으면 `셀프승인` 라벨 경로로 본인이 통과**시킨다(증적 3종 — 이때도 `--unlabel 승인요청`).

위 데이터를 요약해 **번호 선택지**로 제시하라.
★**각 선택지는 «무엇이 달라지나»를 한 줄로 적는다 — 내부 분류명 단독 금지**("잔손질"·"수거함"·"증분" 같은 말은 사용자에게 아무 정보가 아니다. 2026-08-28 실측: 오너 "무슨말이야" 2회). CLAUDE.md 세션 규칙의 «무엇이 어떻게 달라지는지로 말하라»는 **본문만이 아니라 고르라는 항목에도** 적용된다 — 고를 때가 정작 그 정보가 필요한 순간이다.

- ① 새 멘션·댓글이 있으면 **그것부터 (권장 표시)** — 내 카드만이 아니라 **남의 카드에 달린 내 멘션도**(To-Do 목록이 그것이다). 대기·무효 통지·반려 전부 포함 (무효 멘션을 놓치면 없어진 카드를 만들게 된다). **무효 통지에는 확인 댓글 한 줄(ack)로 답한다.** 기획 변경이 맞으면 `/change` 를 제안
  - **"고위험 리뷰 부탁"(승인 대행)·"검수 부탁"(검수 대행) 멘션이 있으면 — 지금 `검수.md`를 읽고 그대로 진행하라.**
    ⚠️부작용 있는 절차다(게이트 잡 실행·close 대행·라벨 전환) — 어느 것도 사용자 확답 전에 실행 금지.
- ② 다음 대기 이슈 (제목·한 줄 요약)
- ③ 보류 / 직접 지정

규칙:
- 착수 결정은 사용자가 한다. 네가 골라서 시작하지 마라.
- 사용자가 고르면: 기능 개발은 `/dev {번호}`, 작은 수정은 `/fix {번호}` 실행을 제안하라.
- 조회가 실패하면(토큰 등) 원인과 해결법(`glab auth login`)을 알려라.
