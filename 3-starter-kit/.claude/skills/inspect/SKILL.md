# /inspect — "$0" 화면 검사 묶음

> **계약** · 입력: 이슈번호/화면경로 · 산출물: 검사 보고 — 부작용 없음 · 검증: 검사형 — "N종 소진·안 돌린 층 X"가 결과(0건≠완료)

> **예시**: `/inspect 12` (보통 `/dev`·`/done`이 자동 호출, 검수 전에 직접도)

**원칙**: 검사는 한 종류씩 재발견하지 않고 **묶음으로 한 번에** 돌린다. 방법마다 잡는 결함 층이 다르다 —
한 방법 0건은 "깨끗함"이 아니라 "그 방법이 바닥남"일 뿐이다.

## 0. 실행 수단 확인
- `npm run inspect` 스크립트(팀 검사 하네스)가 있으면 **그걸 실행**하고 3번으로.
- 없으면(골든 패스 전) 아래 1~2를 수동 배터리로 직접 수행 — 그리고 "하네스 없음"을 보고에 명시.

## 1. 기본 배터리 (도구 없이도 가능한 층)
카드($0)의 수용 기준·검수 방법을 먼저 읽고, 대상 화면마다:
- **정적**: 라우트 응답 200 + 화면에 수용 기준의 문구·요소가 실제로 있는지 (HTML 확인)
- **인터랙션**: 폼 제출·토글·링크를 **실제로 실행하고 상태 변화를 단언** — 요소가 *있다*가 아니라 *동작한다*.
  형제 네비·탭은 목적지가 서로 다른지(죽은 컨트롤: 클릭해도 아무 일 없는 링크는 모든 정적 검사를 통과한다)
- **이상 입력**: 빈 값 · 아주 긴 글 · 잘못된 형식 · 같은 요청 연속 2회 — 검수자 통과 기준 ③과 같다 (검수자가 잡기 전에 네가 먼저)
- **왕복 확인**: 쓰기 액션 후 다시 읽어서 저장·반영이 실제로 됐는지

## 2. 브라우저 배터리 (하네스/Playwright 있는 프로젝트)
- **콘솔 에러 0** · **반응형**: 모바일 뷰포트(375px)로도 렌더 · **가로 넘침**: `document.body.scrollWidth <= viewport` (넘침은 다른 검사를 전부 빠져나간다)
- (시안이 있는 프로젝트만) **시안 소스 diff**: 시안 HTML↔렌더를 구조·문구 단위로 대조 — 스크린샷 눈대조가 아니라 소스로

## 3. 보고 — "0건=완료"라고 말하지 마라
- **"검사 N종 소진, 안 돌린 층: X"** 형식으로. 각 층에서 실행한 것·발견한 것·못 돌린 것을 구분.
- 결함 발견 시: ①고치기 전에 **같은 계열의 형제 화면·요소를 전수 확인** (한 곳에서 나면 패턴으로 났다) ②고친 뒤 그 층 재실행
- **새 실패 유형을 발견하면 하네스에 검사를 영구 추가**하자고 제안 — 검사 묶음은 프로젝트 자산이고, 추가할수록 복리로 자란다. 검수자가 같은 유형을 2번 잡으면 그 검사는 CI로 승격(공통 개발자 가이드 '신호 감지' 표의 규칙)

## ❌ 금지 — 그 순간 드는 핑계와 반박까지

| 하고 싶어지는 말 (핑계) | 반박 |
| --- | --- |
| "테스트 green이니 화면도 될 거다" | 테스트는 코드 층만 본다 — 죽은 링크·콘솔 에러·넘침·미반영 렌더는 전부 테스트 밖이다 |
| "한 바퀴 눌러봤고 이상 없었으니 끝" | 눈으로 한 바퀴 = 기본 상태 한 칸만 본 것. 이상 입력·반복 요청·모바일은 안 본 칸이다 |
| "이 검사에서 0건이니 깨끗하다" | 그 방법이 바닥난 것 — 다른 층(인터랙션·넘침)은 그 방법으로 안 잡힌다. 소진한 종류를 세라 |
