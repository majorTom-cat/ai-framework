# /inspect 함정 목록 — 실측 예외 모음 (본문이 가리킬 때 읽는다)

> 여기 있는 것은 전부 **실제로 겪은 실패와 그 우회**다. 본문이 "함정.md §N"을 가리키면 해당 절만 읽어라.

## §1 보호(로그인 뒤) 화면 — 통과 경로부터 확보하라

- 로그인·강제 리다이렉트(비번 변경 등)가 서버 액션이면 명령줄로 못 뚫는다(bnsone #65 실측: DB 플래그 직접 UPDATE로야 통과).
- 프로젝트에 검수용 우회 절차가 있으면 그걸 쓰고, **없으면 "보호 화면 층 미검사"를 보고에 명시** + 단위·통합 테스트로 대체 + **우회 절차 신설을 카드로 제안**하라(임의로 DB를 만지는 우회는 그 자체를 보고).
- ★**로그인 자체가 안 되면 «앱이 고장» 이 아니라 «자격증명이 없다» 를 먼저 의심하라 — 원인 둘, 해법 하나**(2026-09-01 bnsone: 세 번 밟았다):
  ①시드가 비밀번호를 **안 붙였다** ②**통합 테스트를 돌려 지워졌다**(int 테스트가 시드 계정을 빌려 쓰고 cleanup 에서 지운다).
  ★**둘 다 재시드로 풀리지만 «그냥 재시드» 로는 안 된다** — 시드는 **비밀번호 환경변수가 있을 때만** 계정을 살린다(없으면 «안 붙인다» 가 fail-safe 설계라 조용히 건너뛴다). 표본 게이트가 있으면 그것도 함께 켜라: `{표본변수}=1 {비번변수}='{초기비번}' npm run {재시드명령}` — 멱등이라 몇 번을 돌려도 안전하다.
  값은 **프로젝트 검수 안내 문서의 초기 비밀번호와 같아야 한다** — 정책 미달 값이면 시드가 «못 쓰는 값» 으로 보고 건너뛰며 경고만 남긴다. 그 뒤 인증 API 로 쿠키를 받으면 보호 화면 GET 검사가 전부 열린다.
  ★**«로그인이 안 되니 보호 화면 층 미검사» 로 접기 전에 이것부터 하라** — 접으면 화면 결함이 통째로 안 보인다.

- ★★**로그인 뒤 «최종 URL»부터 확인하라 — 로그인 실패도 200 이다.** 로그인 폼이 200 으로 돌아오고 검사기는 «통과»로 읽어, 그 뒤 화면 검사가 전부 로그인 화면을 검사한다(2026-09-17 배포처 #247 실측: 실패 24건 중 **15건이 거짓 실패**였다). 확인법 = 리다이렉트를 따라간 **마지막 URL** 과 본문의 로그인 표식(`name="password"` 등)을 함께 본다(`curl -sL -o /dev/null -w '%{url_effective}\n'`).
- ★**쿠키 파일을 파이썬으로 읽지 마라 — `MozillaCookieJar` 가 `#HttpOnly_` 줄을 버린다.** 세션 쿠키가 대개 HttpOnly 라 **그 줄이 통째로 사라져** 로그인 상태가 안 실린다(같은 실측). 쿠키 파일은 `curl` 에 그대로 넘기거나(`-b`/`-c`), 꼭 파싱해야 하면 그 접두어를 먼저 걷어라.
- ★**플래그 프리뷰가 «쿠키»로 도는 앱이면 `curl` 에 `-b` 와 `-c` 를 같은 쿠키 파일로 줘라.** 목록 링크엔 `?preview=` 가 없고, 브라우저는 첫 `?preview={플래그}` 요청에서 받은 쿠키로 다음 화면을 연다. 로그인 쿠키만 싣고 **저장(`-c`)을 안 하면 «플래그 뒤 화면이 404»** 로 보인다 — 앱 결함이 아니다(2026-09-11 bnsone 실측).

## §2 서버 액션 폼 — 명령줄로 제출을 재연할 수 없다

- Next `"use server"` 폼에 `Next-Action` 헤더+multipart 로 POST 하면 RSC 프로토콜 불일치로 **500만 난다**(앱 결함이 아닌데 로그엔 500으로 남아 오독까지 부른다 — bnsone #74 실측).
- 이 층은 ①결과 렌더 확인(`?error=` 등 GET 경로) ②엔진 왕복 단위·통합 테스트로 **대체**하고, 3번 보고에 **"액션 제출 층 미실행"을 명시**하라. 브라우저 하네스(Playwright)가 있으면 그걸로 실제 제출을 돌린다.
