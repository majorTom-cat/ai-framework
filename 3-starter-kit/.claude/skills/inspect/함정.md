# /inspect 함정 목록 — 실측 예외 모음 (본문이 가리킬 때 읽는다)

> 여기 있는 것은 전부 **실제로 겪은 실패와 그 우회**다. 본문이 "함정.md §N"을 가리키면 해당 절만 읽어라.

## §1 보호(로그인 뒤) 화면 — 통과 경로부터 확보하라

- 로그인·강제 리다이렉트(비번 변경 등)가 서버 액션이면 명령줄로 못 뚫는다(bnsone #65 실측: DB 플래그 직접 UPDATE로야 통과).
- 프로젝트에 검수용 우회 절차가 있으면 그걸 쓰고, **없으면 "보호 화면 층 미검사"를 보고에 명시** + 단위·통합 테스트로 대체 + **우회 절차 신설을 카드로 제안**하라(임의로 DB를 만지는 우회는 그 자체를 보고).
- ★**로그인 자체가 안 되면 «앱이 고장» 이 아니라 «자격증명이 없다» 를 먼저 의심하라 — 원인 둘, 해법 하나**(2026-09-01 bnsone: 세 번 밟았다):
  ①시드가 비밀번호를 **안 붙였다** ②**통합 테스트를 돌려 지워졌다**(int 테스트가 시드 계정을 빌려 쓰고 cleanup 에서 지운다).
  ★**둘 다 재시드로 풀리지만 «그냥 재시드» 로는 안 된다** — 시드는 **비밀번호 환경변수가 있을 때만** 계정을 살린다(없으면 «안 붙인다» 가 fail-safe 설계라 조용히 건너뛴다). 표본 게이트가 있으면 그것도 함께 켜라: `{표본변수}=1 {비번변수}='{초기비번}' npm run {재시드명령}` — 멱등이라 몇 번을 돌려도 안전하다.
  값은 **프로젝트 검수 안내 문서의 초기 비밀번호와 같아야 한다** — 정책 미달 값이면 시드가 «못 쓰는 값» 으로 보고 건너뛰며 경고만 남긴다. 그 뒤 인증 API 로 쿠키를 받으면 보호 화면 GET 검사가 전부 열린다.
  ★**«로그인이 안 되니 보호 화면 층 미검사» 로 접기 전에 이것부터 하라** — 접으면 화면 결함이 통째로 안 보인다.

- ★★**로그인 뒤 «최종 URL»부터 확인하라 — 로그인 실패도 200 이다.** 로그인 폼이 200 으로 돌아오고 검사기는 «통과»로 읽어, 그 뒤 화면 검사가 전부 로그인 화면을 검사한다(2026-09-17 배포처 #247 실측: 실패 24건 중 **15건이 거짓 실패**였다). 확인법 = 리다이렉트를 따라간 **마지막 URL** 과 본문의 로그인 표식(`name="password"` 등)을 함께 본다(`curl -sL -o /dev/null -w '%{url_effective}\n'`).
- ★**쿠키 파일을 파이썬으로 읽지 마라 — `MozillaCookieJar` 가 `#HttpOnly_` 줄을 버린다.** 세션 쿠키가 대개 HttpOnly 라 **그 줄이 통째로 사라져** 로그인 상태가 안 실린다(같은 실측). 쿠키 파일은 `curl` 에 그대로 넘기거나(`-b`/`-c`), 꼭 파싱해야 하면 그 접두어를 먼저 걷어라.
- ★**플래그 프리뷰가 «쿠키»로 도는 앱이면 `curl` 에 `-b` 와 `-c` 를 같은 쿠키 파일로 줘라.** 목록 링크엔 `?preview=` 가 없고, 브라우저는 첫 `?preview={플래그}` 요청에서 받은 쿠키로 다음 화면을 연다. 로그인 쿠키만 싣고 **저장(`-c`)을 안 하면 «플래그 뒤 화면이 404»** 로 보인다 — 앱 결함이 아니다(2026-09-11 bnsone 실측).
- ★**브라우저 도구(Playwright)로 로그인하면 `Origin`·`Referer` 헤더를 직접 줘라** — `page.request` 로 보낸 로그인은 `Origin` 이 없어 인증 API 가 403 이다(위 `curl` 절차엔 이 언급이 없다). 값은 앱 주소와 `{앱주소}/login`(`scripts/measure-screens.cjs` 가 있으면 그 처리를 이미 한다). 또 **한 호출에 제출 4~5건을 넣으면 브라우저가 중간에 닫혔다 — 제출은 호출당 1~2건**(2026-10-07 bnsone #219).
- ★**관리자 화면은 로그인 뒤 재인증 화면이 한 번 더 나온다**(`/console-reauth` 류 — 경로·칸 이름·버튼 문구는 앱마다 다르니 이 repo 값으로) — 스크립트가 «최종 URL 이 로그인 화면이 아니다»만 보면 재인증 화면을 «열렸다»로 읽는다(배포처 bnsone 세 번 반복: #535·#769). **최종 URL 이 재인증 경로가 아닌지까지 단언**하라. 또 «칸 0개·버튼 0개»는 통과가 아니다 — 열린 화면이 기대한 화면인지 제목·주소로 먼저 확인하라.

## §2 서버 액션 폼 — 명령줄로 제출을 재연할 수 없다

- Next `"use server"` 폼에 `Next-Action` 헤더+multipart 로 POST 하면 RSC 프로토콜 불일치로 **500만 난다**(앱 결함이 아닌데 로그엔 500으로 남아 오독까지 부른다 — bnsone #74 실측).
- **파일 칸을 안 고른 제출은 «빈 파일»로 온다** — Next 서버 액션은 이름 `blob`·형식 `application/octet-stream`·크기 0 인 File 을 준다(이름이 빈 문자열이 아니다). «골랐나»는 이름이 아니라 `size > 0` 으로 가르고, 시험은 이름 `blob`·빈 이름 둘 다 + **브라우저로 파일을 안 건드리고 저장 한 번**을 넣어라(Node 로 만든 가짜 FormData 는 이름이 비어 단위 시험이 전부 초록이었다 — 배포처 bnsone #647).
- 이 층은 ①결과 렌더 확인(`?error=` 등 GET 경로) ②엔진 왕복 단위·통합 테스트로 **대체**하고, 3번 보고에 **"액션 제출 층 미실행"을 명시**하라. 브라우저 하네스(Playwright)가 있으면 그걸로 실제 제출을 돌린다.

## §3 특정 데이터가 있어야 보이는 값(판정·계산 결과) — AI 가 로컬에서 만들어 확인한다

> 2026-10-19 배포처 bnsone #710: 지각 판정 로직 한 줄만 고쳤더니 UI 파일이 0개라 /fix 가 화면 확인을 건너뛰었고, /done 은 사람에게 «확인 없이 검수요청» 선택지를 냈다. 결과는 «지각» 배지로 화면에 나온다 — 로직 카드도 화면 값이 바뀌면 화면 카드다.

- 순서(스택 값은 이 repo 것으로): ①이 트리 전용 `.env`(포트·메일 발송 비움 — `_reference/worktree.md` «전용 DB» 절) ②`docker compose -p issue-N up -d db` ③마이그레이션 적용 ④표본 재시드 ⑤임시 스크립트로 확인에 필요한 기록(사원·휴가·출근 시각 등)을 만들고 판정 함수의 결과도 출력 ⑥개발 서버를 이 트리 전용 포트로 띄워 로그인 후 화면·콘솔·375px 확인.
- **임시 스크립트 첫 줄에 접속 URL 의 포트가 이 트리 전용인지 대조하는 가드**를 넣어라 — 공유 DB 에 기록이 쌓인다.
- **대조군 한 명은 필수**(조건이 없는 사람 · 경계값 바로 안쪽·바깥) — 한 방향만 보면 «전부 지각» 같은 오류가 초록이다.
- 끝나면 임시 스크립트·서버·컨테이너를 정리한다(볼륨은 `/done` 정리가 조건 확인 후 지운다). 시험이 판정 함수를 덮더라도 «화면 배지까지 이어지는가»는 별개 층이다.


## §4 공유 Playwright MCP 가 불안정할 때 — 독립 실행으로 간다 (맥 한정, 배포처 bnsone 실측 2026-10-21)
- 증상: «Browser is already in use», 또는 호출 사이에 페이지가 `about:blank` 로 초기화·로그인 소실·«Target page, context or browser has been closed» — 한 프로필을 여러 세션이 나눠 쓰는 탓이다. 남의 브라우저를 닫지 마라, «검수 서버에서 확인 필요» 로 접지도 마라.
- 방법: 스크래치패드에 `.cjs` 를 쓰고 `node` 로 돌린다(울타리 밖). 저장소 `node_modules/playwright-core` 를 `require`, 브라우저는 `webkit.launch({ executablePath: ".../ms-playwright/webkit-<rev>/pw_run.sh" })`(캐시 경로·리비전은 환경마다 `ls` 로 확인 — Windows 엔 없다. 시스템 Chrome 으로도 된 사례 있음).
- 로그인→재인증→이동→클릭→값 읽기→표본 삭제를 **한 스크립트 안에서** 끝낸다. 호출을 나누면 세션이 사라진다. API 로그인은 `Origin`·`Referer` 헤더가 없으면 403.
- 함정: 안 보이는 라디오(`sr-only`)는 `check()` 가 실패 → 보이는 글자(`getByText(…, {exact:true})`)를 눌러라 · 버튼처럼 보여도 `<a>` 일 수 있다(글자로 찾고 안 잡히면 스크린샷) · 이동 직후엔 `networkidle` 뒤 1~1.5초 더 기다려라 · 개발 서버의 `ChunkLoadError … hmr-client` 는 클릭 없이 화면만 연 대조 실행에서 0건이면 앱 탓이 아니다.

## §5 환경 때문에 생기는 거짓 실패 — 코드 결함으로 읽기 전에 (배포처 bnsone 실측 2026-10-20·21)
- **도커 앱 이미지 빌드가 Node 메모리 부족(OOM, SIGABRT)으로 죽으면**(타입검사·시험은 초록 — #761): DB 만 컨테이너로 띄우고(`docker compose up -d db`) 호스트에서 마이그레이션 → 시드(PATH 에 `node_modules/.bin` 필요 — 안 그러면 `spawn tsx ENOENT`) → 빌드 → `start -p <포트>`. 앱이 요구하는 비밀 환경변수는 compose 의 더미 값을 쓴다.
- **webkit(사파리 계열)을 개발 서버로 돌리면** 첫 화면 몇 번 뒤부터 `ChunkLoadError` 로 하이드레이션이 안 돼, 폼 «저장» 이 값을 주소에 싣고 통째 새로고침되는 **거짓 실패**가 난다(#743 — 같은 흐름이 운영 빌드에선 통과). webkit 은 운영 빌드(`build` 뒤 `start`)로 확인하고, 끝나면 서버를 내려라. 운영 빌드가 비밀 환경변수 부재로 로그인에서 죽으면 로컬 임시 값을 줘라.
- **`npm run typecheck` 가 `JavaScript heap out of memory` 로, 또는 도커 이미지 빌드가 메모리 부족으로 죽으면 코드 결함으로 읽지 마라**(배포처 bnsone #808·#816) — Node 메모리 한도 문제다. 이미지 빌드가 죽는 쪽은 위 첫 줄 우회(DB 만 컨테이너, 호스트에서 마이그레이션·시드·`npm run dev`)로 간다. typecheck 는 같은 코드가 CI 에서 초록이면 PC 한도 탓이니, 그 사실을 보고에 적고 한도를 올린 재실행 결과를 증거로 삼아라.
- **직접 쓴 playwright 스크립트가 `chromium.launch()` 에서 죽으면**(번들 브라우저가 없는 PC — #595) `channel: "chrome"`(설치된 크롬)으로 띄워라. 번들은 있는데 playwright-core 가 요구하는 리비전과 달라 죽으면 설치된 리비전 실행 파일을 `executablePath` 로 줘라(`ls …/ms-playwright/chromium-*` — 새로 내려받지 마라, bnsone 10-26).
- **세션에 브라우저 조작 도구(Playwright 등)가 아예 없으면**(Windows 세션 등 — #735·#747) 클릭·반응형·콘솔 층을 못 돈다. `curl` 은 첫 렌더만 보고, 재인증이 있는 관리자 화면은 `curl` 로도 안 열린다. 순서: ①저장소의 `playwright-core` 로 스크립트를 써서 돌린다(위 `channel: "chrome"` 줄과 같은 길) ②그것도 안 되면 **못 돌린 층을 검수 표의 «미확인» 칸으로 넘기고** 사람에게 확인을 맡긴다. «첫 렌더만 봤다»를 «검사 통과»로 보고하지 마라. 화면 주소처럼 앱마다 다른 함정(예: 기안 화면 주소 규칙)은 이 repo 의 함정 칸에 따로 적는다.

## §6 여러 팝업의 «저장 거절 → 입력 유지» 흐름 — 팝업마다 손 스크립트를 새로 쓰지 마라 (배포처 bnsone #761)
- 흐름은 팝업마다 같다: 팝업 열기 → 잘못된 값으로 저장 → ①오류 글자가 화면에 지속되는지 ②입력값이 남았는지 읽기. 팝업이 여럿이면 «팝업 목록(열기 동작·잘못된 값·오류 글자)»을 받아 이 흐름을 도는 **도우미 함수 하나**를 스크래치패드 스크립트에 두고 목록만 바꿔 돌려라. 팝업마다 손으로 쓴 스크립트는 한 곳을 빠뜨린다.
- 킷은 도우미 파일을 두지 않는다(열기·오류 글자 선택자가 앱 값이라 공용 파일이 못 쓴다) — 위 흐름과 «폼 오류는 지속되는 글자로» 규칙(`CLAUDE.md`)이 기준이다.
