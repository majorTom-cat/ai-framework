# /design — 요구사항 → 기술 설계 (골격 Day 0)

> **계약** · 입력: 차터~요구사항 digest(03 필수) · 산출물: docs/06 설계(스택·ERD·모듈·shared) 2~3안→결정→ADR · 검증: docs/06+ADR 기록 (⏸ 사람 결정)

> **예시**: `/design` (인자 없음 — digest들을 읽어 설계 제안. 요구 더 오면 다시 `/design`)

> ★**모델 확인(소프트 플로어)**: 이 스킬은 깊은 설계 판단이다 — 현재 세션이 경량 모델(haiku급)이면 **시작 전에 멈추고** "설계는 상위 모델 권장 — `/model`로 올린 뒤 다시 `/design`"을 안내하라. 상위 모델이면 그대로 진행.

> **공통 개발자 스킬.** 기획자가 요구사항 문서를 올린 뒤, "분석해줘" 같은 자연어 대신 이 스킬로 설계한다.

**전제 판정** — `docs/_STEP_INDEX.md`의 STEP 3 행과 `docs/03_Requirement/`를 **함께** 본다 (둘이 어긋나면 실물 파일이 사실, 인덱스는 고쳐야 할 대상 — 단 실물 쪽이 **대량 삭제 등 사고로 보이면 revert가 먼저**, 공통 개발자 가이드 '사건 대응' 참조):
- 원본 + `_digest.md` 있음(인덱스 ✅/🔄) → **진행**. 첫 슬라이스 하나만 있어도 성립한다(아래 ★부분 설계).
- 원본은 있는데 **`_digest.md`가 없으면** → **먼저 `/docs`**(digest·지도 갱신)를 돌린 뒤 재실행.
- **요구사항이 아예 없으면 멈춘다** — 단 "기획자에게 요청"으로 끝내지 말고 이렇게 마무리한다:
  1. **첫 슬라이스(영역 하나)만이라도** 올려달라고 요청 — 전 영역을 기다리지 않는다. 담을 내용은 GitLab 실전 가이드 **"요구사항 문서에 담을 것"** 절을 기획자에게 안내.
  2. 요청을 **카드로** 남긴다: `/card 문서 요청 — {영역} 요구사항 (기획자 앞)`.
  3. **대기 중 할 일**: 차터·현황·문제 digest의 **미해결·질문 중 스택을 가르는 것**(모바일 방식·자체 서버/Docker·외부 연계·기존 코드 재사용)을 기획자·인프라 담당과 **지금 확정**해 digest에 기록 — 요구가 도착하면 설계가 바로 나간다. (공통 개발자 가이드 Day 0 ⚠️절과 동일)
  4. `▶ 다음: /card 문서 요청 — {영역}` 으로 끝낸다.
- (04 업무설계·05 UI/UX는 있으면 읽고 **없어도 진행** — 멈춤 사유는 03 요구사항뿐이다.)

1. **읽기 (인접 계약대로 — 통독 금지)**: **차터(00_Project)·현황(01)·문제정의(02)·요구사항(03)의 `_digest.md`** + 필요한 원본 절만(`.claude/rules/docs.md`의 "STEP별 분석" 규칙).
  - **제약(자체 서버·무료 UI·개인정보 등)·인력 규모·미해결 질문은 차터 digest에 있다** — 차터를 빼먹으면 ①플랫폼과 ⑤모듈 분할을 감으로 하게 된다.
  - 무관한 문서까지 통째로 읽지 마라 — 비대화·환각의 원인.
2. **이해 요약 (5줄) + ⏸ 가벼운 확인**: 무엇을 만드나 / 핵심 엔티티 / 주요 화면 / 규모·제약 / 범위 밖. → **기획자와 맞춘다**: 요약을 카드 댓글로 남기고, **물을 것이 없으면 그대로 진행해도 된다.** 질문이 하나라도 있으면 답을 받을 때까지 3으로 가지 마라 — 틀린 이해 위에 설계하면 다 뜯는다.
3. **제안 — 각 2~3안 + 트레이드오프.** ★**부분 설계 규칙**: 요구가 슬라이스 일부만 왔어도 **①~④는 전체 제품 기준으로 지금 못 박는다**(차터의 전 범위·제약이 근거 — 되돌리기 어려운 갈림길을 미루면 뒤가 다 꼬인다 → ADR). **⑤·⑥은 도착한 요구 범위만 확정**하고 나머지 영역은 **이름만 예약**(경계 확정은 그 요구 도착 시 — 재실행).
   - **① 플랫폼·전달 방식** (첫 갈림길 — 스택을 좌우) — 반응형 웹 / PWA(설치·오프라인·푸시) / 네이티브 앱(스토어·기기 기능) / 데스크톱 다운로드 / 하이브리드. 기기 기능(GPS·카메라·푸시·오프라인)·배포 경로·스토어 심사가 갈린다
   - **② 기술 스택** — 위 플랫폼 + 요구 성격(실시간·데이터량)·팀 숙련도. ("팀이 익숙한 것"은 문서에 없다 — 게이트에서 결정권자가 보완하는 항목임을 명시하고 안을 내라) 외부 근거 조사가 필요하면 내장 `/deep-research` 활용(검색 쿼리에 사내 정보·제품명 넣지 않기)
   - **③ DB·데이터 모델** — 주요 엔티티·관계(ERD 초안). RDB냐 문서DB냐는 데이터 구조가 결정. **DB가 필요 없으면 명시** → `/scaffold`가 DB·마이그레이션 단계를 생략한다
   - **④ 그 외 요구가 건드리는 것만** (없으면 생략) — 인증·인가 방식 / API 양식(REST·GraphQL·RPC) / 배포 토폴로지(서버·컨테이너·서버리스) / 외부 시스템 연계 / 비기능(성능·보안·확장성·오프라인·동기화)
   - **⑤ 모듈 분할** — 기능 덩어리 = **수직 슬라이스**(화면+API+DB 통째). 여기서 모듈 이름·경계가 나온다. 개수는 요구가 정하되 **개발자 수와 맞춰라**(개발자 수 = **CLAUDE.md 모듈 소유 표**, 비어 있으면 **차터 digest의 인력** — 영역이 더 많으면 관련 영역을 묶는다, 고아 소유 방지)
   - **⑥ ★ 공통(shared) 추출** — **확실 후보는 처음부터**: 인증·권한 · 공통 UI(테이블·폼·모달·토스트) · 포맷·날짜 유틸 · API 클라이언트 · 네비게이션.
     - **둘째 사용처가 '유력하지만 미확정'인 것**(예: 승인·결재선 엔진 — 다른 영역 요구가 아직 안 옴)은 **첫 사용 모듈에 두고** CLAUDE.md의 승격 규칙(둘째 사용처 카드 확정 시 shared 승격)을 따른다 — 추측으로 미리 shared에 만들지 않는다.
4. **⏸ 게이트 — 공통 개발자가 결정한다**: 감이 아니라 **요구 근거로**. AI는 안(案)을 정리·제시만, **선택은 사람**. (이건 잡담이 아니라 '결정' — 스킬이 못 대신함.)
5. **기록**: `docs/06_TechnicalDesign/`에 (플랫폼 · 스택 · ERD · 모듈 분할 · **shared 목록** · 예약해둔 미설계 영역 목록) + **되돌리기 어려운 결정(플랫폼·스택·DB·모듈 경계·shared 경계)은 ADR**(`docs/adr/` + INDEX 갱신) — 다음 세션이 임의로 뒤엎는 걸 막는다.
  - **이 기록 커밋은 전용 카드를 발행해 그 번호로**(다른 목적의 열린 카드에 얹지 마라 — 설계 이력이 남의 카드에 섞이면 추적 불가).
6. **"▶ 다음: `/scaffold`"** — 이 설계대로 뼈대를 짓는다(`src/shared`·`src/modules`를 여기서 정한 그대로).

> 🔄 **재실행 — 두 경우를 구분하라**:
> - **요구가 더 옴(증분)**: `/design`을 다시 돌려 **⑤·⑥만 넓힌다**(예약해둔 영역의 경계 확정). ①~④가 안 바뀌면 기존 ADR 유지, `docs/06`만 갱신.
> - **설계가 크게 뒤집힘**(플랫폼·스택·DB·모듈 경계 변경): `docs/06` 갱신 + **대체 ADR**(옛것 "대체됨") + 공통 개발자 가이드(`docs/00_Guide/`)의 **재기준선**(docs·ADR 먼저 원자 MR → 보드 재설정 → 코드 정리) 후, 영향 전파는 **`/change`**. 반쯤 바뀐 상태(문서 반·코드 반)가 최악이니 docs를 항상 먼저.

## ❌ 금지 — 핑계와 반박
| 핑계 | 반박 |
| --- | --- |
| "요구 대충 아니까 바로 스택 정하자" | 감 설계 = 뒤에서 전면 재작업. 요구 근거로만. |
| "문서 다 읽고 종합하자" | 통독은 비대화·환각의 원인 — digest + 관련 절만(인접 계약) |
| "공통은 나중에 필요할 때 뽑자" | 인증·공통 UI를 처음부터 shared로 안 잡으면 모듈마다 제각각 = 누더기 |
| "요구가 다 올 때까지 기다리자" | 첫 슬라이스로 ①~④를 못 박는 게 이 스킬의 일이다 — 기다림은 설계가 아니라 지연 |
| "내가 정리했으니 됐다" | 되돌리기 어려운 결정을 ADR로 안 남기면 다음 세션이 뒤엎는다 |
