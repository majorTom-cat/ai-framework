# /tidy — 메모리 정리 후보 뽑기

목적: 목차가 커져 읽기 한도(200줄)에 닿기 전에, 낡은 메모를 **근거와 함께** 골라 사람이 승인하게 한다. 혼자 지우지 않는다.

대상 폴더 = 현재 프로젝트의 메모리 폴더(시스템 프롬프트 «Memory» 절에 적힌 경로).

1. **백업부터**: 메모리 폴더 전체를 스크래치패드에 복사한다(`cp -R`). 백업 경로를 보고에 적는다.
2. **현황 조회**: `wc -lc MEMORY.md` · 메모 파일 개수 · 목차에 없는 고아 파일(`ls` ↔ 목차 링크 비교, 한글 정렬 때문에 `comm` 말고 `grep -vxFf` 로).
3. **후보 수집 — 항목마다 근거를 붙인다**
   - 스스로 «종료·끝남·해소» 라고 적힌 메모(제목·description 에 `종료`).
   - 메모가 가리키는 카드가 닫혔는지(`glab api issues/N` — 닫혔다고 교훈이 낡은 것은 아니다, **참고만**).
   - 프로젝트 문서에 같은 문구가 이미 있는지(`CLAUDE.md`·`.claude/rules`·`CLAUDE.local.md` 를 `grep -a` 로) — 있으면 «겹침» 후보. **겹친다고 지우지 않는다**: 메모를 열어 문서에 **없는 내용**(실측 숫자·함정·예외)이 있는지 확인하고, 있으면 «둘 것».
   - 현재 규칙과 **어긋나는** 메모(예: 폐지된 절차를 권하는 것).
   - 같은 주제 메모 둘 이상(합칠 후보).
4. **표로 보고**: `지울 것 / 합칠 것 / 둘 것` 3구획 — 각 줄에 `메모 이름 · 근거 · 확인한 방법`. «근거 없는 추정»은 «둘 것» 으로 보낸다.
5. **승인 뒤에만 실행**: 사용자가 고른 것만. 목차 줄 삭제는 Edit/Write 로. **파일 삭제는 샌드박스가 막을 수 있다** — 그러면 `rm` 명령을 사용자에게 건네 터미널에서 실행하게 한다(우회 금지).
6. **끝 확인**: 정리 후 목차 줄 수·바이트, 목차 링크 중 실제 파일이 없는 것 0건, 백업 위치를 보고한다.

금지: 승인 없는 삭제 · 백업 없이 시작 · «겹쳐 보인다» 만으로 지우기 · 메모 본문을 고쳐 쓰기(합칠 때도 원문은 남긴다).
