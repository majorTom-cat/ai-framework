# /scaffold — 앱 뼈대 생성 (골격 Day 1, 프로젝트당 1회)

> ★★**곁에 두 파일이 있다 — 해당 단계에 오면 반드시 읽어라**: `단계상세.md`(§1 3단계 뼈대 구성 목록 · §2 4단계 CI·대조표 · §3 5~7단계 · §4 ❌금지) · `함정.md`(실측 사고 경위 §1~§7). **이 안내를 여기 둔 이유**: 컴팩션은 스킬마다 **앞 5,000토큰만 남기고 뒤를 자르므로**(공식), 본문 뒤쪽에 있는 포인터는 대화가 길어지면 **포인터째로 사라진다.** 이 줄은 앞쪽이라 살아남는다.
> ★★**잘려도 이 셋은 지켜라** — ①**설계 문서 없이 스택을 정하지 마라**(감 스택 = 뒤에서 전면 재작업) ②**브라우저에 실제로 뜨기 전엔 완료가 아니다**(2번 게이트·7번 확인) ③**모듈 이름을 임의로 만들지 마라** — 모듈 경계는 설계(요구 근거) 산출물이다. 나머지는 `단계상세.md` §4.

> **계약** · 입력: 설계(docs/06) · 산출물: 앱 뼈대(src·docker·CI·CLAUDE.md 빈칸·훅) 커밋 · 검증: 새 clone→docker compose up→빈 앱 렌더 (⏸ 게이트)

> **예시**: `/scaffold` (인자 없음 — `docs/06` 설계를 읽는다)

> 이건 **공통 개발자 스킬**이다. 개발자의 `/dev`처럼, 공통 개발자의 "앱 뼈대 만들기"를 붙여넣기 프롬프트 대신 이 스킬로 한다.

**전제**: Day 0 기술설계가 끝나 `docs/06_TechnicalDesign/`에 **스택·DB·모듈 분할**이 있고 `docs/adr/`에 핵심 결정이 있다. **없으면 여기서 멈추고 Day 0(설계)부터** 하라 — 감으로 스택을 정하면 뒤에 재작업이 크다.

1. **설계 읽기** — `docs/06_TechnicalDesign/`(스택·ERD·모듈)·`docs/adr/INDEX.md`(결정)를 읽고, **"이 스택·구조로 뼈대를 짠다"를 5줄로** 요약(스택 / DB·마이그레이션 도구 / 모듈 이름들 / 배포 방식 / 범위 밖).
   - **마이그레이션 도구가 설계에 없으면** 기본값(plain-SQL + 자체 러너)을 제안하고 게이트에서 확정한다.
   - **언어가 설계에 없으면 TypeScript를 기본값으로** 제안한다(근거는 /design ② — 타입=AI의 기계 검증 루프). TS면 test 잡에 **typecheck를 반드시 포함**(3단계 ② CI 잡·4단계) — 검사 없는 타입은 이득이 준다.
   - **repo에 기존 src·CI(다른 앱 잔재)가 있으면** 교체/보존 범위도 요약에 넣는다(어느 모듈·파일을 걷어내고 무엇을 새로 짓는지 — 4단계 "주석 스테이지 활성화"는 이미 CI가 켜진 repo엔 해당 없음).
2. **⏸ 게이트**: **위 5줄 요약을 먼저 텍스트로 출력**하라 — 승인 UI(질문 위젯)엔 질문만 크게 보여 본문 요약이 안 보일 수 있으니, **승인 요청 문구에도 요약(축약)을 포함**한다. 사용자가 승인(스택·모듈 이름·교체범위 확정)할 때까지 **코드 생성 금지**.
2-1. **골격 카드 발행** — 게이트 승인 후 `/card`로 골격 카드(제목 예 `앱 골격 생성`, **`고위험` 라벨** — shared 전체를 건드리므로)를 만들고 **그 번호를 커밋(6단계)에 쓴다**.
   - (CLAUDE.md '카드 #1 예외'는 최초 구축 한정 — 이미 보드가 도는 repo엔 이 단계로 카드를 남긴다.)
   - **3단계에서 모듈 플래그를 만들면 그 자리에서 플래그 제거 카드도 함께 발행**한다(CLAUDE.md '플래그 생성 = 제거 카드 동시 발행' 규칙).
3. **뼈대 생성** — **`단계상세.md` §1 을 열어 목록대로 만들어라.** 요지: `src/shared/`·`src/modules/{설계의 모듈들}/`(각각 `ui`·`api`·`schema`·`seed`·`tests`·`index`)·`db/migrations/` · docker-compose(db→migrate→app) · 기능 플래그 · 강제 장치(husky·공개 API 스냅샷·`.gitattributes` lock 안전판·모듈 가드 훅) · 화면 하단 버전 표시 · 경계검사·CI 잡 스택 치환 · 멱등 시드 + 시드 테스트.
   — ★**잘려도 지킬 것**: **설계에 DB·마이그레이션이 없으면** 관련 절·파일을 **생략·제거**한다(§1 첫 줄) · **모듈 폴더를 만들면 그 자리에서 `.claude/rules/module-{이름}.md` 도 함께 찍는다**(여기서 안 찍으면 영영 못 찍는다 — `함정.md` §6) · 각 모듈은 **`index` 만 외부에 노출** · **검수 서버에 별도 `/sian/` 라우트를 만들지 마라**.
4. **CI 활성화** — `.gitlab-ci.yml`의 주석 처리된 `test`·`boundaries` 스테이지를 이 스택 명령으로 채워 활성화한다. **절차와 ★자기 검증 대조표는 `단계상세.md` §2 를 열어 그대로 실행하라**(대조표는 필수 — 지시만 있고 이행이 새는 게 실측됐다).
   — ★**잘려도 지킬 것**: 경계검사는 **`npm run boundaries` 이름만** 부른다(변형 선택은 package.json 한 줄) · 검사기 파일 이름을 바꾸면 **CI `high-risk-gate` 경로·`check-push.sh` 의 `HITS`·회귀 테스트의 `CHECKER` 를 같은 커밋에서** 함께 고친다(셋은 한 몸) · `needs` 를 쓰면 가리키는 잡과 `rules` 를 맞춰라(안 맞으면 잡 0개로 전 게이트 무효).
5. **CLAUDE.md 빈칸 채우기** — 이 스택으로 결정되는 플레이스홀더(`<기동명령>` 등)와 **check-push 경로 패턴**을 채운다. **절차는 `단계상세.md` §3.**
6. **커밋** (첫 줄 `#<카드> chore: 앱 골격`, 카드 = 2-1 발행분) — **새 clone 검증(7)은 커밋된 상태만 보므로 커밋이 먼저다**(순서 뒤집지 말 것). 공지 예외는 `단계상세.md` §3.
7. **✅ 눈으로 확인** — **다른 폴더에 새로 clone → `docker compose up` → 브라우저에 빈 앱이 뜨는지.** 안 뜨면 고쳐 **수정 커밋을 추가**한다(뜨는 게 완료 기준). 남은 `<…>` 훑기와 다음 안내는 **`단계상세.md` §3.**

**❌ 금지 절**(§4)은 `단계상세.md` 에 있다 — 위 «잘려도 지킬 것» 셋이 그 요약이다.
