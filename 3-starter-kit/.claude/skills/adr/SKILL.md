# /adr — 설계 결정 기록: "$ARGUMENTS"

> **계약** · 입력: 결정 요약 · 산출물: docs/adr/NNNN 파일 + INDEX 갱신(같은 커밋) · 검증: INDEX에 행 추가(대체면 옛것 "대체됨→NNNN")

> **예시**: `/adr 게시판·회원은 getUserSummary(id)로만 연동` (되돌리기 어려운 결정·모듈 간 계약)

> 되돌리기 어려운 결정(스택·DB·모듈 경계·**두 모듈 간 계약**·공개 API 형태)은 ADR로 남긴다 — 없으면 다음 세션 AI가 옛 방향으로 "복원"하는 사고가 난다. (요구사항 변경 자체는 `/change`, 전체 초기 설계는 공통 개발자 `/design`. 이 스킬은 **개발 중 생기는 개별 결정**용.)

1. **INDEX 먼저** — `docs/adr/INDEX.md`(현행 결정 목록)를 읽어 ①다음 번호 ②이 결정이 **기존 결정을 뒤집나** 확인. (전체 grep은 대체된 옛 결정까지 걸리니 INDEX가 정본. INDEX 없으면 만든다.)
2. **새냐 대체냐**:
   - **새 결정** → 새 파일 `docs/adr/NNNN-슬러그.md`.
   - **기존 뒤집기** → 새 파일로 쓰고 **옛 ADR 머리에 "대체됨 → NNNN" 한 줄만**(본문 수정 ❌ — 안 그러면 옛 방향이 되살아난다).
3. **작성**: `docs/adr/0000-템플릿.md` 를 복사해 채운다(절 이름을 여기 다시 적지 않는다 — 서식 정본은 그 템플릿 하나다).
4. **두 모듈 간 계약이면**: 인터페이스 시그니처(함수 이름·입출력)를 결정에 명시하고 **양쪽 모듈 소유자를 @멘션**(병렬 착수 *전* 계약 확정이 목적) + 관련 카드 링크.
5. **`INDEX.md`를 같은 커밋에서 갱신**(대체면 옛 항목 상태도) → 커밋 첫 줄 `#<카드> docs: ADR NNNN 요약`.
   — ★**커밋 직전 번호를 «열린 MR 까지» 재확인하라 — `origin/main` 만 보면 못 잡는다**: `git fetch -q --prune origin` 뒤 `git for-each-ref --format='%(refname)' refs/remotes/origin | xargs -I{} git ls-tree -r --name-only {} docs/adr/ | sort -u` — **모든 원격 브랜치**의 ADR 파일명을 모아 그 뒤 번호를 쓴다.
     `origin/main` 하나만 보던 옛 명령은 **아직 안 머지된 MR 이 이미 쓴 번호를 못 본다**: 절차대로 재확인했는데 열린 MR !386 이 0051 을 쓰고 있었다(2026-09-08 bnsone). 로컬 INDEX만 믿는 것도 같은 사고다 — 두 브랜치가 **INDEX의 서로 다른 줄**에 추가하면 자동 병합이 충돌 없이 통과해 번호가 중복되고 git도 CI도 못 잡는다. 같은 사고 **3회**(2026-08-19·08-25·09-08).
   — ★**번호 «예약»은 파일로만 된다 — 인계문·메모에 «0061 로 바꾼다»만 적지 마라.** 위 조회는 파일만 보므로 그 사이 다른 세션이 그 번호를 쓴다(2026-09-17 bnsone 실측). 바꾸거나 비워 둘 번호가 있으면 **그 자리에서 파일을 만들어 브랜치로 push** 하라.
   — ★**번호를 인용하는 자리를 «머지 뒤 못 고치는 파일»에 두지 마라**(마이그레이션 SQL 주석 등) — 번호는 머지 순서로 바뀔 수 있다. 거기엔 **카드 번호**를 적어라(`rules/migrations.md`).
   — ★**ADR 을 여러 장 한 브랜치에서 쓸 땐 카드별로 커밋을 가르고, `INDEX.md` 항목도 그 커밋에 나눠 넣어라** — 한 커밋에 뭉치면 카드별 되돌리기가 통째로 막히고, 어느 결정이 어느 카드 것인지 이력이 지워진다(2026-09-18 배포처 `!566`).
   — ★**미룬 것에는 카드 번호를 달아라** — «별도 카드로»·«후속»·«착수 직전 ADR» 문장만 남기면 아무도 안 만든다(2026-09-17 bnsone 실측: 예고만 된 카드 11건). 번호가 없으면 `/card` 로 만들고, 필요 없으면 `(카드 불요: 사유)`. CI `deferred-check`(`scripts/check-deferred.sh`)가 번호 없는 줄을 막는다.
   — ★**연결할 카드가 지금 열려 있는지 확인하라** — `glab issue view <카드>`로 `state`가 `opened`인지 본다.
     닫힌 카드에 `관련:`을 걸면 그 MR은 **추적되는 카드 없이 머지**된다(bnsone 2026-08-06 실측: 전날 닫힌 #39에 MR !73). 열린 카드가 없으면 `/card`로 만들고 그 번호로 진행.
   — ★**`Closes #N` 금지 — `관련: #<카드>` 링크만**(머지 순간 자동 닫힘 — 경위·정본은 /done 7단계). ADR은 보통 구현 카드의 일부라 그 카드는 아직 열려 있어야 한다.
6. 보고 + **"▶ 다음: 이 결정대로 `/dev` 착수 (계약이면 양쪽 소유자 확인 후)"**.

## ❌ 금지
- INDEX 안 보고 전체 grep으로 판단 · 옛 ADR **본문 수정**(대체 표시만) · 계약 없이 두 모듈 병렬 착수.
- **열린 카드 없이 MR 머지** — ADR도 카드 위에서 움직인다(5단계 확인).
