!`glab issue view "$0" 2>&1 | head -40`

최근 댓글 (반려 사유·추가 지시는 여기 있다):
!`glab issue view "$0" --comments 2>&1 | tail -40`

> **★위 조회가 «오류·빈 결과·엉뚱한 카드» 중 무엇이든이면 여기서 멈춘다** — 번호를 문맥으로 추측하지 마라(엉뚱한 카드에 브랜치·커밋이 생긴다). `/fix {번호}` 로 다시 부르라고 안내하고 종료.
> **인자 없이 불렀으면 `$0` 가 숫자가 아닌 값으로 확장돼 조회가 실패한다** — 그것도 이 정지 사유다.

# /fix — 이슈 #$0 작은 수정

> **계약** · 입력: 이슈번호(+지시) · 산출물: 소수정 코드+회귀테스트(fix 브랜치 커밋) · 검증: 테스트 green (+화면이면 /inspect) → /done

> **예시**: `/fix 12` · `/fix 12 버튼 색만 회색으로` — 번호 뒤 지시도 반영(전체 입력: `$ARGUMENTS`).

1. 이슈 본문과 **최근 댓글까지** 읽고 **한 문장으로 무엇을 고칠지** 말하고 바로 진행 (게이트 없음 — 이해가 틀렸으면 사용자가 끊는다). 검수 반려 카드면 반려 사유 댓글이 스펙이다. **카드에 `대기(불명확)` 라벨이 있으면 착수 거부**하고 작성자에게 명확화 요청
   — ★**반려 카드면 수평 점검**: 반려 사유가 **원인 수준에서** 다른 화면·모듈에도 있는지 같은 패턴을 검색(grep)하라.
     있으면 **거기까지 고치지 말고**(남의 모듈·별도 카드 범위) **그 카드에 예고 댓글 + 필요시 `/card` 발행**
     (파일럿 실측: #68 반려 사유〔배너를 URL 쿼리로〕가 poll에 그대로 남아 #69가 같은 사유로 재반려 — 예고 댓글을 단 건 재량이었는데, 이걸 규칙으로 만든다)
   — ★**체크박스가 여러 개 남은 «목록 카드»면 한 문장으로 요약하기 전에 «이번에 어느 항목까지»를 고르게 하라**(남은 항목을 번호로 제시). 항목마다 성격이 달라 위험도·레인이 통째로 달라진다(문서 한 줄 ↔ 인증·마이그레이션·인프라가 한 카드에 섞인다). 범위를 안 고르면 «같은 번호로 계속 /fix» 가 되어 사용자가 어디까지 됐는지 잃는다(2026-08-20 오너 지적). **고른 범위를 착수 댓글에 한 줄로 남겨라.**
   — **고치기 전 대상 함수의 호출부를 전부 grep한다**(반려 카드가 아니어도) — 공유 지점 한 곳의 가드가 호출부마다 패치보다 작은 diff고, 지목된 경로만 고치면 나머지 호출부는 여전히 깨져 있다.
2. **착수 처리**: `git pull origin main` → **`git status --short` 가 비어 있지 않으면 정지·보고** → 카드가 이미 `진행중`+**타인의** 착수 댓글이고 그 브랜치가 내게 없으면 정지(중복 세션 의심) → 브랜치 `fix/$0-{슬러그}` + 착수 댓글 한 줄
   — 라벨 전환은 명령으로: `glab issue update $0 --label 진행중 </dev/null` → `glab issue view $0` 재확인(이미 `진행중`이면 — 반려 카드는 검수자가 되돌려놨을 수 있다 — 생략). **반려 카드에 `검수요청`이 아직 달려 있으면 `--unlabel 검수요청`도 함께**(검수자는 흔히 댓글만 단다 — 안 지우면 재작업 중 보드에 '검수 대기'로 오표시)
   — ★**고위험 카드면 지금 "경고 레인"임을 알려라**(`고위험` 라벨, 또는 CLAUDE.md '머지 등급'의 고위험 유형 — 목록 정본은 그 절):
     "머지 때 **AI 경고 리뷰 + 증적 3종**을 남기고 본인이 게이트를 실행합니다(동료 승인은 선택)" 한 줄 안내 + 카드에 `"고위험 카드 착수 — 머지 때 경고 레인(증적 3종)"` **예고 댓글**(실제 절차는 `/done` 7단계).
     ★**승인자를 정하려고 사용자에게 묻고 멈추지 마라** — 동료를 붙이기로 했으면 예고 댓글에 그 사람을 @멘션한다(선택).
     **작은 수정이라고 면제되지 않는다** — `/fix` 범위에 "검수 반려·카드 댓글 반영"이 들어 있어 **인증·결제 재작업이 바로 이 경로로 온다**(`함정.md` §2 = /done 폴더).
3. 버그면: **재현하는 실패 테스트를 먼저** 작성 → 고침 → green. 구현은 본보기 패턴 준수
4. **화면을 건드렸으면 커밋 전에 `/inspect $0`**(반응형·콘솔 에러·인터랙션 — 검수 반려 재작업이면 특히) → `npm test` green 확인(변경에 `.gitlab-ci.yml` 있으면 `glab ci lint`도 — 무효 CI는 테스트가 못 잡는다) → **변경을 커밋**(첫 줄 `#$0 요약` — ★경로 지목 add, `add -A`·`add .` 금지: 무관한 미추적 파일이 쓸려 들어간다) → "/done $0 하세요" 안내
   — ★**`Closes #$0` 금지 — `#$0`·`관련: #$0` 링크만**(자동 닫힘 = 검수 건너뛴 완료 — 경위·정본은 /done 7단계). 반려 카드는 특히 — 다시 검수받아야 한다.
   — ★**스킬·규칙·킷 문서에 막혔거나 우회했으면** `docs/friction.md` 한 줄(이 커밋 동봉 — 양식은 그 파일 머리, CLAUDE.md ★friction 규칙)

**이 스킬이 맞는 경우**: 버그·문구·작은 개선 + **제거·정리(chore) 작업** + **검수 반려·카드 댓글 반영** — 반나절 미만이면 /fix로.
**이 스킬을 쓰면 안 되는 경우** (그럼 /dev로): 스키마 변경 필요 · 화면 신설 · shared 수정 · 이슈 설명만으로 방향이 애매함
