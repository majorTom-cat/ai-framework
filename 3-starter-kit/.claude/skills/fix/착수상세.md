# /fix 착수 상세 — 2단계에서 pull 로 남의 변경이 섞여 왔을 때 (본문이 가리킬 때 이 파일을 열어라)

> 왜 따로 두나: `SKILL.md` 는 컴팩션 뒤 **앞 5,000토큰만** 남는다. 보조 파일은 그 예산 밖이라, 「그 자리에 가면 읽는다」로 두는 편이 안전하다.

## 남의 변경이 섞여 왔는지 «가려내기»
★**«섞여 왔나»는 눈으로 말고 «명령»으로 가려라** — pull **전에** `git rev-parse HEAD` 를 적어 두고, pull 뒤 `git diff --name-only {그 해시} HEAD` 로 본다. ⚠️`HEAD@{1}` 을 쓰지 마라: **브랜치를 만든 뒤면 어긋나 빈 결과**가 나오고, 그 빈 결과를 「스키마 변경 없음」으로 읽는다(2026-09-10 실측). **결과가 비면 «없다»가 아니라 «잘못 쟀다»를 먼저 의심하라.**

## 섞여 왔으면 — 셋 다 돌린다
★**pull 에 남의 `package.json`·스키마 변경이 섞여 왔으면 셋 다 돌려라**: `npm install`(새 의존성) → 마이그레이션 적용(**새 테이블은 생성물 재생성으로 안 생긴다**) → ORM 생성물 재생성. 안 하면 **남의 모듈이 무더기로 빨개져 「내가 뭘 깼나」로 읽는다**(2026-09-03 두 세션 실측). 이어서 **`git status package-lock.json` 확인**(`npm install` 이 `dev`→`devOptional` 로 142줄 재분류 — 공통 영역 파일이 더러워진다. 의존성 변화 0이면 되돌려라).
★**마이그레이션은 «돌렸나»가 아니라 «적용됐나»를 물어라** — `npx prisma migrate status`(그 repo 의 상태 명령)로 미적용을 확인하고, 있으면 적용한다. 앱 컨테이너를 안 띄우고 `npm run dev` 로만 돌리면 **컨테이너가 하던 자동 적용이 안 돈다** — 재시드가 «없는 컬럼»(P2022)으로 죽어 «내가 뭘 깼나»로 읽힌다(2026-09-10 실측).

## 그래도 빨간불이면 — 내 탓인지 가르기
★**내 탓인지 가르는 법**: `git worktree add {임시} origin/main` 으로 깨끗한 main 을 **같은 로컬 환경에서** 돌려 대조하라 — 남의 모듈이 빨간 원인이 내 변경인지 pull 로 들어온 것인지 이걸로 갈린다. **확인이 끝나면 `git worktree remove {임시}` 로 반드시 지워라** — 남겨 두면 다음 세션의 `session-guard` 점검에 «정체불명 점유»로 잡히고, 이 팀은 폴더 하나 규칙이다.
