# /dev 단계 상세 — 본문이 가리킬 때 그 절만 읽어라

> `SKILL.md` 본문은 «무엇을 하는 단계인가 + 반드시 지킬 것»만 담는다. 이 파일은 그 단계의 **판정 순서와 실측 경위**다.
> **왜 뺐나**: 컴팩션은 스킬마다 **«앞 5,000토큰만 남기고 뒤를 자른다»**(공식). 4단계 뒤가 전부 그 밖이라 대화가 길어지면
> **게이트째로 안 읽혔다.** 보조 파일은 그 예산에 안 든다(읽을 때만 로드) — **잘려서 안 읽히느니 포인터로 읽히는 편이 낫다.**
> 보조 파일을 실제로 찾아 읽는 것은 2026-09-07 격리 프로브로 실증했다(강한 지목·약한 지목 둘 다).

## §1 테스트 — red 를 고치기 전에 답할 것 (6단계)

**순서: ①의존이 떠 있나 ②생성물·설치가 최신인가 ③내 탓인가 ④내가 남의 초록을 깼나.**

- ★**DB·외부 의존이 필요한 스택이면 돌리기 전에 기동부터 확인** — 컨테이너가 내려가 있으면 실패가 **코드 결함처럼 보인다**(bnsone 실측: 오독할 뻔). red를 고치기 전에 "의존이 떠 있나"를 먼저 답하라.
- ★★**«컨테이너가 내려갔다»보다 흔한 건 «Docker 데몬 자체가 안 떠 있다»이고, 이때 오류에 원인이 안 적힌다** — 통합 테스트가 `Serialized Error: { clientVersion: …, errorCode: undefined }` 만 뱉고 죽는다(맥이 잠들었다 깨는 다음 날 세션에서 반복 — 2026-09-08 bnsone). **`docker info` 를 먼저 돌려라** — 여기서 죽으면 코드·스키마·시드를 뒤질 이유가 없다. **사람이 Docker Desktop 을 켜야 한다 — AI 는 못 켠다**(한 줄로 알리고 멈춰라).
- ★**"의존"은 컨테이너만이 아니다 — 스키마가 바뀐 pull 뒤엔 생성물(ORM 클라이언트 등)을 먼저 재생성하라.** 남의 스키마 변경을 받은 직후 타입 검사가 **남의 모듈 오류로 무더기 red** 가 되는데 원인은 낡은 생성물이다(2026-08-19 실측 7건). 남의 코드를 고치러 가기 전에 재생성부터.
  - ★**`package.json` 이 함께 왔으면 재생성만으로는 안 풀린다 — 설치(`npm install`)가 먼저다**(2026-09-03 bnsone 실측: 남의 카드가 들여온 패키지 미설치로 타입 오류 30건).
- ★**남의 모듈이 빨간데 main CI 는 초록이면 «내 탓인가»부터 가려라** — `git worktree add {임시} origin/main` 으로 **깨끗한 main 을 같은 로컬 환경에서** 돌려 같은 실패가 나는지 본다(내 클론 HEAD 는 안 건드린다). 환경 탓이면 내 변경을 뒤질 이유가 없다(2026-09-01 bnsone 실측: 가리는 데 시간이 들었다).
- ★**반대로 «내 변경이 남의 초록을 깬» 경우도 있다 — 기존 테스트가 무더기로 깨지면 먼저 «그 상황을 일부러 만들던 케이스인가»를 보라.** 새 DB 제약·새 반영 경로를 넣으면 남의 스위트가 한꺼번에 빨개질 수 있는데 **결함이 아니라 의도한 동작**이고 고칠 곳은 남의 테스트다. **지우지 말고 관례 안에서 살려라**(2026-09-04·09-07 bnsone 실측 2회: 겹침 EXCLUDE 로 13건).

**테스트를 거는 자리 — 왜 그렇게 거나**

- **공개 경계에 건다**(모듈 `index` 공개 함수·API 응답·화면 동작) — 내부 함수·비공개 구조에 건 테스트는 행동이 안 변해도 리팩토링에 깨진다(그렇게 깨지면 잘못 건 것). 남의 모듈을 mock 할 때도 그 모듈의 공개 인터페이스만.
- **동어반복 테스트 금지**: 기대값을 코드와 같은 방식으로 계산해 넣으면(`expect(add(a,b)).toBe(a+b)` 류·구현을 베낀 스냅샷) 항상 통과하는 가짜다 — 기대값은 **독립 출처**(스펙·손으로 푼 예시·알려진 리터럴)에서 가져와라.
- ★**공유 DB 에서 «내 행만 본다»는 «내가 부른 함수의 반환값»에도 걸린다** — 전역을 훑는 배치 함수의 **반환 합계로 단언**하면 시드 표본·남의 행이 섞여 실패한다(2026-09-01 bnsone 실측). 단언은 **내가 만든 행으로 좁혀라.**

## §2 마무리 — 화면을 보기 전에 (7단계)

- ★**로컬 화면을 보기 전에 재빌드부터**(`docker compose up -d --build` 류) — 컨테이너가 **소스 마운트 없는 프로덕션 빌드**면 코드 변경이 화면에 안 나타나 "구현이 틀렸다"로 오독한다.
  재빌드했으면 **브라우저 하드 리로드**까지 하라 — 서버 액션·번들 ID가 바뀌어 **옛 페이지에서 누른 저장이 조용히 실패**한다. (검수 서버 배포 화면은 /done이 보는 것이라 이 문제를 안 덮는다)
- ★**디자인 정본이 «채택 대기»(시안을 아직 안 골랐다)면 `/ui` 는 채택 후로 미루고 `/inspect` 만 돌린다** — 채택 전에 꾸미면 채택 뒤 다시 만든다. **미룬 사실을 카드 댓글 한 줄로 남겨라**: 기록이 없으면 다음 세션은 이걸 «절차 생략»으로 읽는다(2026-08-28 실측: 화면 카드마다 건너뛰었는데 이유가 매번 세션 판단으로만 남았다).

## §3 1단계 상세 — 스펙 확인

- **내 모듈인지 먼저 확인** — 카드의 `모듈:` 라벨을 CLAUDE.md 소유 표와 대조. 내 모듈이 아니면 착수 거부하고, 필요한 기능이면 **소유자 앞 인터페이스 카드(`/card`)**를 제안한다(남의 모듈은 그 모듈의 `index`로만 쓴다)
- **카드에 `대기(불명확)` 라벨이 있으면 착수 거부** — 수용 기준이 모호하다는 표시다. 작성자에게 무엇을 명확히 해야 하는지 되묻고, 명확해질 때까지 시작하지 마라
- **전 모듈이 얹히는 기반(인증·권한·알림·배치 같은 공통 인프라)이면 /dev를 시작하지 말고 `/design` 증분(⑤·⑥ 확장)을 먼저 제안한다** — 판정 기준: "이 카드가 실패하면 다른 모듈도 다시 만들어야 하나" (경위 `함정.md` §1)
  - ★**단 산출물이 «ADR 한 장»뿐인 결정 카드는 /design 이 아니라 `/dev` + `/adr` 로 간다** — 기반을 건드려도 코드가 안 나오면 /design 증분은 과하다(2026-08-26 실측: 갈 곳이 규정에 없어 매번 선례를 뒤졌다).
- ★**«수거함·감사·전수 점검» 유형이면 1단계를 «스펙 이해»가 아니라 «항목별 현재 상태 재실측»으로 바꿔라** — 이런 카드의 항목은 등록 뒤에 저절로 해소돼 있곤 하다(2026-08-24 실측: 18건 중 5건이 이미 해소). 산출물도 코드가 아니라 «고침 + 카드 + 판단»이다. **재실측 없이 착수하면 이미 없는 문제를 고친다.**
- **★본보기 모듈이 실제로 있는지 지금 확인한다** — CLAUDE.md의 `<본보기모듈>`이 **치환됐는지**, 그 폴더에 **실기능이 있는지**, 그리고 **이 카드가 쓸 축이 거기 실제로 있는지**까지 — 화면 카드면 화면·화면 테스트 수단, 연동 카드면 `index` 공개 계약, 메뉴·네비 카드면 렌더 방식(**해당 축만** 본다).
  - 미치환·빈 뼈대·쓸 축이 비었으면 **그 자리에서 공백으로 보고**하라(공통 개발자가 채울 몫). **속으로 메우지 마라** — 경위 `함정.md` §2.
  - 5단계에서 읽을 것이라도 **없다는 사실은 1단계에서 말한다.**
- **먼저 `git pull --ff-only origin main`** — 최신 docs·코드로 시작한다 (변경(#N 대체) 카드면 특히: 로컬 docs가 옛 스펙일 수 있다)
- 이슈 본문·최근 댓글과 `docs/`의 관련 요구사항·시안을 읽고 — **카드가 가리키는 정본 경로의 해당 절만**(docs 전체를 통째로 읽지 마라: 무관한 문서는 노이즈가 되어 정확도를 떨어뜨린다) — **"이렇게 이해했다"를 5줄 이내로** 정리:
  무엇을 / 데이터는 / 화면은 / 실패 시엔 / 범위 밖은.
- 애매한 점은 추측 대신 **질문 목록**(질문마다 `➡️ 추천: …` 병기 — '사실'은 직접 조회하고 사람에겐 '결정'만) + 질문이 없어도 **가정 표면화**(`가정: 1)… 2)… — 틀리면 지금 고쳐주세요. 없으면 진행합니다.`).
  **재작업이 큰 가정(= 2단계 조건 ③과 같은 축 — 남이 쓰는 계약: 스키마·`shared`·모듈 간 인터페이스)은 질문으로 승격**해 멈춘다
  ⚠️**여기 잣대를 ③보다 넓게 두지 마라** — 넓으면 질문이 하나 생겨 묶음 게이트 조건 ①(질문 0건)이 깨지고, ③에서 뺀 것이 **다른 문으로 다시 두 번 서게 된다**(2026-09-07).

## §4 2단계 상세 — 묶음 게이트의 조건과 예외

- 단축 조건: 카드에 docs 정본 참조 + 수용 기준이 완비돼 있고 **질문 목록이 비어 있으면**, "이해 요약 5줄 + **가정 목록**"을 카드 댓글로 남기고 통과해도 된다 (가정도 기록 없이는 통과 못 한다). **질문이 하나라도 있거나, 정본 문서의 해석을 바꾸는 가정이 있으면 반드시 멈춘다**(화면 배치 가정은 아래 묶음 게이트 ④ 참조 — 2026-09-04 완화).
- **★묶음 게이트 — 작은 카드는 게이트 1회**: 아래가 **전부** 맞으면 1·3단계를 이어서 하고 «이해 5줄 + 가정 + 계획»을 **한 화면에 함께** 보여준 뒤 **여기서 한 번만 선다**(4단계 게이트를 이 게이트가 겸한다. 승인은 "스펙+계획 go" 하나로 받는다).
  ① 질문 목록이 비어 있다 ② 계획이 작업 3개 이하 ③ **실제 소비자가 있는 계약을, 그 형태를 내가 정해서 바꾼다**(둘 다 참일 때만 선다) — 스키마·`shared` 는 소비자가 항상 있으니 참이다. **자기 모듈 `index` 는 «추가냐 변경이냐»가 아니라 «다른 모듈이 실제로 import 하나»로 판정하라**(모듈 지도 `src/modules/_MODULE_MAP.md`, 없으면 그 심볼을 다른 모듈에서 grep) — **소비자가 0이면 추가든 «의미» 변경이든 해당 없음** ④ **정본 문서(docs)의 해석을 바꾸는 가정**이 없다
  - ★**④는 2026-09-04 에 바꿨다** — 종전 「화면 상호작용·데이터 형태를 결정하는 가정」은 **화면 카드에 없을 수 없어**(「어느 칸을 어디에 둘까」) 화면 카드가 사실상 언제나 두 번 섰다. 오너 지적: 「계속 물어봐서 너무 불편하네. 개선한거 아니었나?」(한 카드 정지 4회). **화면 배치 가정은 계획과 함께 한 화면에 보이면 충분**하다.
    ⚠️④를 ③과 같은 말(계약 변경)로 쓰면 **③에 포섭돼 조건이 셋이 된다** — ④가 지키는 축은 «계약»이 아니라 **«스펙 이해»**다(정본을 이렇게 읽었다는 가정이 틀리면 구현 전체가 헛돈다). 그래서 «정본 해석»으로 남긴다.
  - ★**조건 ③ 예외 — 카드 본문에 요청 시그니처가 적힌 «인터페이스 카드»**: 정의상 항상 모듈 간 계약을 바꾸므로 **구조적으로 절대 못 묶인다.** 그런데 ③이 막으려는 건 «계약 형태를 내가 새로 정하는 것»이고 인터페이스 카드는 **소비자가 이미 정해 온 것**이라 정반대다. 시그니처가 본문에 있고 질문이 0건이면 묶어도 된다(2026-09-03 bnsone 실측).
  - ★★**같은 조건에 예외가 두 번째로 필요해지면, 예외를 붙이지 말고 조건을 다시 써라** — ③은 «리스크»를 잡아야 하는데 「공개 `index`」라는 말이 **«카드 유형»**을 잡고 있었다(9-03 인터페이스 카드 → 예외 신설, 9-07 자기 모듈 export → 또 걸림). 두 번째에 말 자체를 «남이 쓰는 계약»으로 좁혔다.
    ★**9-09 세 번째** — 그 새 말에 붙은 «**추가**는 해당 없음»이 «**의미** 변경»을 빠뜨려 또 걸렸다(bnsone `friction.md:141`). 형용사를 고치면 다음 형용사에 또 걸린다. 그래서 이번엔 말을 **«소비자가 있나»라는 확인 가능한 물음**으로 바꿨다 — grep 한 번으로 답이 나오고, 답이 «있다»면 정지는 여전히 옳다(게이트를 약하게 만든 게 아니다).
  - ★★**사용자 본인이 쓴 카드는 ②③을 보지 않는다**(2026-09-08 오너 결정 · bnsone #233 「또 묻네, 이거 고친거 아니었나?」): 카드 작성자가 **세션 사용자 본인**이고 설계·수용 기준이 본문에 있으며 질문이 0건이면 작업 수·`shared` 여부와 무관하게 **묶음 1회**다(①④만 본다). 판별 기준은 CLAUDE.md 세션 규칙 «여기서 아니오가 나올 수 있나» — **자기가 쓴 설계를 자기에게 다시 승인받는 정지는 도장찍기**다(실측: 스펙 게이트 답 「그래」, 정정 0건, 두 번째 정지에서 지적). ②③이 지키는 축(계약 리스크)은 **남이 쓴 카드**에서만 살아 있다. 안전은 머지 쪽 게이트가 진다(아래).
  - ★**`고위험` 라벨은 배제 사유가 아니다**(2026-08-28 오너 결정 "1"): 고위험은 «머지 리스크»(인증·결제·마이그레이션·설정)이고 이 게이트가 보는 건 «스펙 이해 리스크»다 — **둘은 직교한다.** 스펙이 세 줄인 고위험 카드에서 스펙·계획을 따로 승인받아 두 번 다 즉답이 나온 실측이 근거다.
  - 안전은 **머지 쪽 게이트**가 진다(AI 경고 리뷰·증적 3종·`셀프승인` 라벨 — CLAUDE.md '머지 등급'. 2026-09-09 부터 되돌리기 어려운 경로·`고위험` 라벨 MR 은 라벨로도 안 열리고 사람이 ▶ 를 누른다). 그건 그대로 선다.
  - **하나라도 아니거나 애매하면 지금까지대로 2회** — 게이트는 «줄이는 쪽»이 아니라 «맞추는 쪽»이 기본값이다.
  - 묶음 게이트에서 **스펙이 정정되면 계획을 다시 짜서 다시 보여준다** — 정정된 스펙 위에 옛 계획으로 착수 금지.

## §5 5단계 상세 — 구현

- **착수 처리 먼저**: `git pull --ff-only origin main` 재실행(게이트 대기 사이에 main이 앞섰을 수 있다)
  - ★**`--ff-only` 를 빼지 마라** — 맨 `git pull`·`git merge` 는 병합 커밋을 만들 수 있어 **같은 클론을 쓰는 다른 세션의 발밑에서 HEAD 가 움직인다**. 그래서 훅이 매번 확인 창을 세운다(2026-09-10 오너가 찍어 보낸 창이 이것 — `git merge origin/main --no-edit`). `--ff-only` 면 훅이 무음이고, 진짜로 갈라졌을 때만 실패한다.
  - ★★**이 폴더를 다른 세션이 쓰고 있으면 pull 자체를 하지 마라 — 워크트리로 나가라.** 점유 확인은 훅이 해 주지만 **준비 넷은 아무도 안 해 준다**: ①`git worktree add ../issue-{번호} -b {브랜치} origin/main` ②의존성은 **링크하지 말고 그 트리에 설치**(`npm ci` 류) + ORM 생성물 재생성.
    ③**전용 DB**(`.env` 의 포트·접속 URL **둘 다** 고치고 컨테이너도 이름을 달리 띄운다) ④그 DB 에 마이그레이션 적용. 레시피·함정 = `_reference/worktree.md`.
    ⚠️**③을 빠뜨리면 공용 DB 를 가리켜, 준비 0단계가 다른 세션의 시험용 DB 를 통째로 지운다**(2026-09-10 실측).
  - **pull에 이 카드가 가리키는 정본(docs) 변경이 섞여 왔으면 정지**: 해당 절을 다시 읽고 스펙 이해(1·2단계)가 여전히 유효한지 확인, 달라졌으면 게이트로 복귀(기획 변경이면 `/change` 확인)
  - **`git status --short` 가 비어 있지 않으면 정지·보고**(더러운 트리 위 브랜치 금지)
  - ★**pull 로 남의 스키마 변경을 받았으면 ORM 생성물부터 재생성하라** — 안 하면 **시드가 먼저 깨진다**(2026-09-01 bnsone 실측: 지워진 컬럼을 참조해 P2022). 6단계에도 같은 안내가 있지만 **시드는 그보다 먼저 돈다.**
  - ★**의존성·마이그레이션도 같이 온다 — 셋 다 돌려라**: `npm install`(남이 더한 새 패키지) → 마이그레이션 적용(**새 테이블은 생성물 재생성으로 안 생긴다**) → ORM 생성물 재생성. 그리고 **`git status package-lock.json` 확인**(`npm install` 이 `dev`→`devOptional` 로 재분류해 공통 영역 파일을 더럽힌다 — 의존성 변화가 없으면 되돌려라). 상세·판별법 = `/fix` 2단계.
  - ★★★**«진행중» 인데 착수 댓글이 없으면 «아무도 안 잡았다»가 아니다 — 그게 제일 위험한 모양이다.** 라벨은 명령 한 줄이라 남고, 착수 댓글은 산문 지시라 빠진다 — **둘이 갈리면 «잡은 사람이 있는데 흔적만 없는» 상태**가 된다(2026-09-10 #268 실측: 다른 세션이 이미 커밋까지 했는데, 착수하려던 세션이 «우연히» 남의 워크트리를 보고서야 멈췄다).
    ⇒ 라벨이 `진행중` 인데 착수 댓글이 없으면 **세 가지를 다 조회한 뒤에만 착수**하라: ①`git worktree list` ②`git ls-remote --heads origin '*$0*'` ③그 카드 최신 댓글. **하나라도 걸리면 정지·보고**(먼저 그 세션에 물어라).
  - ★**착수 댓글도 «명령»으로 남겨라 — 산문 지시는 안 지켜진다**(라벨 전환이 명령이라 지켜지는 것과 같은 이유). 남긴 뒤 `glab issue view $0 --comments | tail -5` 로 실제로 붙었는지 확인한다.
  - **카드가 이미 `진행중`+착수 댓글이 있는데 그 작업 브랜치가 내 로컬에 없으면 정지**(다른 세션·PC가 작업 중 의심 — 카드 댓글로 확인 후 진행) — **단 직전 `/module`로 생성한 모듈 스캐폴드는 예외**(곧 이 브랜치에 함께 커밋할 정당한 미커밋 파일이다)
  - 브랜치 `git checkout -b feature/$0-{슬러그}` + **라벨 전환을 명령으로**: `glab issue update $0 --label 진행중 </dev/null` → `glab issue view $0`로 반영 재확인
    (**명령·재확인까지가 전환이다** — 산문 지시는 안 지켜졌다, 경위 `함정.md` §3) + 착수 댓글 한 줄(base main 해시 포함 권장 — 상태 전이표의 "착수 시"가 바로 지금이다). 모듈 스캐폴드가 있으면 이 브랜치 첫 커밋에 함께 담는다
- **고위험 카드면**(`고위험` 라벨, 또는 CLAUDE.md '머지 등급'의 고위험 유형 해당) **지금 "경고 레인"임을 알려라**:
  - "머지 때 **AI 경고 리뷰 + 증적 3종**을 남기고 `셀프승인` 라벨로 게이트를 통과시킵니다(▶ 불필요 · `.claude/**` 같은 되돌리기 어려운 경로와 `고위험` 라벨 MR 만 사람이 ▶ · 동료 승인은 선택)"를 한 줄로 알린다. ★**승인자를 정하려고 묻고 멈추지 마라.**
  - 카드에 `"고위험 카드 착수 — 머지 때 경고 레인(AI 경고 리뷰 + 증적 3종)"` 예고 댓글을 남긴다(실제 절차는 /done 7단계). 동료를 붙이기로 했으면 함께 @멘션(선택).
- **의존 카드라면** 두 갈래:
  ① 선행이 **이미 머지됨** → main에 선행 커밋이 있는지 확인하고 main에서 착수. 선행이 검수 반려 중이면 그 여파(스펙이 또 바뀔 수 있음)를 카드에 기록하고 진행 여부를 판단
  ② 선행이 **미머지** → 선행 feature 브랜치에서 분기 + 카드에 "base: feature/{선행} — 머지는 선행 먼저" 기록
- **먼저 본보기 모듈(`src/modules/<본보기모듈>`)의 해당 패턴(파일 위치·`index` 노출·테스트 형태·플래그 사용법)을 읽고 그 관례를 따라라.**
  이탈은 CLAUDE.md '작업 절차' 관례 규칙대로(의식적 이탈+이유 기록). 억지로 맞추다 이상해지는 게 베끼기의 실패 모드다.
- **구현 수단은 사다리 순서로**: 기존 코드(shared·본보기) 재사용 → 표준 라이브러리 → 플랫폼 내장(`<input type=date>`·CSS·DB 제약) → 기설치 의존성. **몇 줄로 되는 일에 새 의존성 금지**(추가 = package.json 공통 영역 공지 대상). 없으면 자기 모듈 안에 만든다(shared 승격은 2개 모듈 필요 시). 단 **검증·에러 처리·보안·접근성은 줄이는 대상이 아니다.**
- 과잉 추상화 금지: 구현 1개뿐인 인터페이스·제품 1개뿐인 팩토리·바뀔 일 없는 값의 설정화 — 둘째가 생길 때 만든다(shared 승격 기준과 동형). 의도적으로 한계를 남기면 주석 한 줄로 한계+승급 경로 명기(`// 한계: 전역 락 — 처리량 문제 시 계정별 락`), 크면 카드로.
- 상대 모듈 index 확인은 모듈 지도(`src/modules/_MODULE_MAP.md`)가 있으면 grep 대신 지도부터 — 재생성 `npm run boundaries -- --map`(**스크립트 이름만 부른다 — 경계검사 변형 선택은 `package.json` 한 줄이 정본**. 코드와 다르면 재생성이 정답. 지도가 없거나 스캐폴드 전이면 `함정.md` §4).
- 스키마 변경이 있으면: 마이그레이션(날짜시각 파일명 — ★**규칙 형식이 도구 기본과 다르면 생성 직후 rename**, 어느 쪽이든 `ls | sort`로 **내 것이 맨 뒤인지** 확인. rules/migrations.md) + 멱등 시드 갱신 동봉(표본은 게이트 변수 뒤 — 같은 문서).
  **★마이그레이션 카드는 `고위험` 라벨 + 착수 전 «충돌 없음» 확인**(전역 직렬 자산 — 두 사람이 동시에 만들면 나중 것 순서가 꼬여 스키마가 깨진다).
  **확인 절차·공지 조건은 `rules/migrations.md` '착수 공지 = 조건부'가 정본** — 요지: main 최신 마이그레이션과 열린 MR 둘 다 깨끗하면 **공지 없이 착수하고 확인 결과를 카드에 한 줄**, 하나라도 걸리거나 조회가 실패하면 **공지**(2026-08-31 오너 결정 "2" — 무조건 공지는 3연속 거절돼 무력화되고 있었다).
- **되돌리기 어려운 결정을 이 작업에서 새로 정하게 되면**(모듈 경계·두 모듈 간 계약·공개 API 형태·스키마 방향) → **`/adr` 로 기록**하고 진행한다(안 남기면 다음 세션 AI가 옛 방향으로 "복원"한다). 두 모듈 계약이면 양쪽 소유자 확인 후.
