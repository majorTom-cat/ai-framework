# /dev 함정 — 본문에서 지목될 때 그 절만 읽어라

> `SKILL.md` 는 «무엇을 하라»만 담는다. 이 파일은 «이렇게 하면 틀린다 + 왜»다.
> 분리 근거: `/dev` 본문이 **12,072 토큰**(2026-09-07 실측)으로 컴팩션 재부착 상한(≈5천)의 2.4배였다.
> ★**한국어는 1자 ≈ 0.93토큰**(같은 날 실측: 13,003자 → 12,072토큰) — 가이드의 「13KB ≈ 5천 토큰」은
> 영어 기준 환산이라 한국어 문서에선 2.4배 틀린다. **바이트로 재지 마라**(한글 1자 = 3바이트라 더 부푼다).
> 보조 파일이 실제로 읽히는지는 격리 프로브로 실증했다(같은 날 — 강한 지목·약한 지목 둘 다 읽고 따랐다).
> ⚠️**아직 목표 미달이다** — 이 분리로 본문은 13,003→10,540자(≈9,800토큰)가 됐지만 한도는 5,000토큰이다.
> 남은 본문은 «함정»이 아니라 **절차**라 더 뺄 «함정»이 없다. 5,400자로 맞추려면 절차 문장에서
> «실측 근거 괄호»를 이 파일로 걷어내는 **본문 재작성**이 필요하다 — 되돌리기 어려운 작업이라 따로 잡아라.
> 그때까지는 **컴팩션 뒤 본문 뒷부분(6·7단계·금지 절)이 재부착에서 잘릴 수 있다**고 알고 써라.

## §1 돌연변이 검증 — «이 케이스가 결함을 잡는가»

- ★★**초록은 케이스가 유효하다는 증거가 아니다 — «이 케이스가 결함을 잡는가»를 따로 확인하라.** 케이스 **수**는 근거가 못 된다(2026-08-28 두 번 실측).
  ★**순서가 있다 — ①겨눈다 ②지운다 ③판정한다 ④되돌린다.** 넷이 각각 다른 방식으로 틀렸다(bnsone 실측 2026-08~09, 이 절에 6번 걸렸다).
  - **①겨눈다 — «어느 파일·어느 함수·어느 층»을 먼저 정한다.**
    - **대상 함수의 시작·끝 줄을 먼저 잡고 그 안에서 고른다.** `grep -n '패턴' | head -1` 은 파일 안 첫 매치를 집어 **이웃 함수를 건드린다**(2026-09-03 실측: 6곳 중 맨 앞을 집어 «케이스가 정렬 축을 못 잡는다»는 오판을 냈다). 치환 뒤 **«함수 시그니처 줄 + 바뀐 줄»을 함께 출력**해 문맥을 눈으로 확인하라.
    - **층을 맞춰라 — 「못 잡음」이 나오면 먼저 «겨눈 파일이 맞나»를 의심하라.** 순수 규칙을 지웠는데 통합 테스트를 돌리면 당연히 통과한다(2026-09-04 실측: 방어 8개 중 1개를 엉뚱한 층에 겨눠 **멀쩡한 방어에 케이스를 덧붙일 뻔했다** — 반대 방향 낭비).
    - **가드는 «그 가드가 유일한 방어인 경로»에서 확인한다.** 인가 가드를 지웠는데 화면 테스트 16건이 전부 초록이었다 — 화면이 자기 필터로 먼저 거른다. 정작 뚫리는 건 **서버 액션**이고 거기선 엔진이 유일한 방어다(2026-09-01 실측).
    - ★**가드성 코드(검사기·훅·게이트·권한 판정)는 방어를 하나씩 지워 보라** — 각 방어를 고정하는 케이스가 있어야 한다. 실측: 24케이스 전부 통과인데 가드 2개를 지워도 여전히 전부 초록이었다(하나는 없으면 헛FAIL, 하나는 없으면 놓친다). **케이스가 없는 방어는 다음 사람이 «군더더기»로 지운다.**
  - **②지운다 — 커밋한 뒤에 망가뜨린다.**
    - **회귀 케이스를 만들었으면 «고치기 전 판»에 걸어 FAIL 하는지 본다.** 실측: 새 밀도 케이스가 옛 검사기에서도 통과했다(한글 100자 = 정확히 300바이트라 상한 비교가 거짓 — 250자로 올려서야 결함이 드러났다). 11 OK 초록이라 그냥 넘어갈 뻔했다.
    - ★★**그 검증을 스크립트로 짜면 첫 줄에 게이트를 박아라 — 문장 규칙은 세 번 다 못 막았다**(2026-08-25·08-26·09-03): `[ -n "$(git status --porcelain -uno)" ] && { echo "⛔ 커밋 뒤에 돌려라"; exit 1; }`. 세 번째는 손으로 친 명령이 아니라 **내가 방금 만든 검증 스크립트의 복원 줄**이 리뷰 반영분을 지웠고 **티도 안 났다**. **스크립트는 자기가 무엇을 지우는지 묻지 않는다.**
      (★**`-uno` 를 빼지 마라** — 빼면 `/card` 가 만들라고 시킨 `docs/inbox/_tmp/` 같은 **미추적 파일에도 걸려** 정상 상태에서 매번 막힌다. 게이트가 지키는 건 «복원이 미커밋 **수정**을 지우는 것»이지 미추적 파일이 아니다. 헛FAIL 하는 방어는 곧 통째로 지워진다 — 바로 아래가 그 경고다. 2026-09-04 bnsone 실측·수리.)
  - **③판정한다 — «빨간 글씨»가 아니라 «종료 코드»와 «무엇이 뽑혔나»로.**
    - ★★**가드는 «잡고도 통과»할 수 있다 — 판정 기준은 «빨간 글씨가 보이나»가 아니라 «종료 코드가 0이 아닌가»다.** 새 그물이 위반을 사번까지 정확히 지목해 찍고도 **종료 코드가 0이라 CI 는 초록**이었다(2026-09-01 bnsone 실측: vitest globalSetup teardown 에서 throw 가 삼켜졌다). **돌연변이를 넣은 뒤 `echo $?` 까지 봐라.**
    - ★**집계(개수·길이)로 단언하는 케이스는 «뒤처리»가 결함을 가린다** — 회차 필터를 지워도 «재상신 문서가 한 줄» 케이스가 그대로 통과했다(«문서당 한 줄로 접기»가 중복을 가려서다). **개수가 아니라 «무엇이 뽑혔나»로 단언하라**(2026-09-01 bnsone 실측).
    - ⚠️**검사기의 헛FAIL 은 «검사기를 느슨하게» 라는 압력을 만든다** — 고칠 것은 **검사기의 그 케이스**이지 판정 자체가 아니다. 급하면 코드를 더 단순한 형태로 바꿔 피하고 **검사기 수정은 카드로 남겨라**(2026-08-31 bnsone 실측: 첫 사례).
  - **④되돌린다 — 역치환하고, 돌아왔는지 확인한다.**
    - 복원은 `git checkout -- {파일}` 이 아니라 **역치환**으로 되돌려라 — checkout 은 그 파일의 미커밋 수정을 **전부** 지운다(2026-08-25 실측: 유실).
    - ★**역치환 뒤 `git diff --quiet {파일}` 로 복원을 확인하라.** 역치환 패턴이 파일 안 다른 자리에 먼저 매치돼 **엉뚱한 함수를 되돌린 채** 다음 돌연변이로 넘어가면 **판정이 오염된다**(2026-09-03 실측: 두 함수가 동시에 손상됐고 `git diff` 를 눈으로 봐야 알았다). **안 돌아왔으면 그때는 커밋해 둔 파일이므로 `git checkout -- {파일}` 이 오히려 안전하다** — 그 갈래가 지금까지 없었다.

## §2 구현 — 커밋·add·되돌리기

  - ★**변경 파일을 경로로 지목해 add 하라 — `git add -A`·`add .` 금지**: 작업트리엔 남의 미추적 파일·잔해가 있을 수 있다(실사고 경위 `함정.md` §5)
