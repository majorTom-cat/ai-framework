# /dev — 이슈 #$0 기능 개발

> **계약** · 입력: 이슈번호(+지시) · 산출물: 구현 코드+테스트(feature 브랜치 커밋); 화면이면 /ui·/inspect 자동 · 검증: 테스트 green + /inspect → /done

> **예시**: `/dev 12` · `/dev 12 로그인은 소셜 로그인만` — **번호 뒤에 덧붙인 지시도 스펙에 반영**한다(전체 입력: `$ARGUMENTS`).

**이 스킬을 쓰면 안 되는 경우**: 반나절 미만의 작은 수정·버그·정리 → `/fix $0` (판별 기준은 /fix 참조)

아래 체크리스트를 응답에 복사해 진행하며 체크하라. **⏸ 게이트에서만 멈추고, 그 사이는 연속 실행.**
★**게이트 질문은 텍스트 선택지로 물어라 — 선택 폼(AskUserQuestion) 금지**(근거 실측 = /done 머리).

```
- [ ] 1. 스펙 확인
- [ ] 2. ⏸ 스펙 승인
- [ ] 3. 계획
- [ ] 4. ⏸ 계획 go
- [ ] 5. 구현
- [ ] 6. 테스트 green
- [ ] 7. 화면 확인 안내 → /done
```

## 1. 스펙 확인
- **내 모듈인지 먼저 확인** — 카드의 `모듈:` 라벨을 CLAUDE.md 소유 표와 대조. 내 모듈이 아니면 착수 거부하고, 필요한 기능이면 **소유자 앞 인터페이스 카드(`/card`)**를 제안한다(남의 모듈은 그 모듈의 `index`로만 쓴다)
- **카드에 `대기(불명확)` 라벨이 있으면 착수 거부** — 수용 기준이 모호하다는 표시다. 작성자에게 무엇을 명확히 해야 하는지 되묻고, 명확해질 때까지 시작하지 마라
- **전 모듈이 얹히는 기반(인증·권한·알림·배치 같은 공통 인프라)이면 /dev를 시작하지 말고 `/design` 증분(⑤·⑥ 확장)을 먼저 제안한다** — 판정 기준: "이 카드가 실패하면 다른 모듈도 다시 만들어야 하나". 설계 한 줄 위에서 구현 중 즉흥 결정하면 리뷰가 끝난 뒤에야 잡힌다(bnsone #63 실측: Blocker 5건, 병렬 구현 되돌림)
- **★본보기 모듈이 실제로 있는지 지금 확인한다** — CLAUDE.md의 `<본보기모듈>`이 **치환됐는지**, 그 폴더에 **실기능이 있는지**.
  - 미치환·빈 뼈대면 **그 자리에서 공백으로 보고**하라(공통 개발자가 채울 몫). **"아마 저 모듈이겠지"로 속으로 메우지 마라**(침묵 진행 실측: 2026-07-28 파일럿).
  - ★**"폴더가 있나"에서 멈추지 마라 — 이 카드가 쓸 관례**(화면이면 화면·화면 테스트 수단, 연동이면 `index` 공개 계약, 메뉴·네비면 렌더 방식)**가 본보기에 실제로 있는지**까지 본다.
    **쓸 축이 비어 있으면 그 축을 공백으로 보고**하라(착수 직전에야 발견한 실측: bnsone #51 — 빈 축 3개).
  - 5단계에서 읽을 것이라도 **없다는 사실은 1단계에서 말한다.**
- **먼저 `git pull origin main`** — 최신 docs·코드로 시작한다 (변경(#N 대체) 카드면 특히: 로컬 docs가 옛 스펙일 수 있다)
- 이슈 본문·최근 댓글과 `docs/`의 관련 요구사항·시안을 읽고 — **카드가 가리키는 정본 경로의 해당 절만**(docs 전체를 통째로 읽지 마라: 무관한 문서는 노이즈가 되어 정확도를 떨어뜨린다) — **"이렇게 이해했다"를 5줄 이내로** 정리:
  무엇을 / 데이터는 / 화면은 / 실패 시엔 / 범위 밖은.
- 애매한 점은 추측 대신 **질문 목록**(질문마다 `➡️ 추천: …` 병기 — '사실'은 직접 조회하고 사람에겐 '결정'만) + 질문이 없어도 **가정 표면화**(`가정: 1)… 2)… — 틀리면 지금 고쳐주세요. 없으면 진행합니다.`).
  **재작업이 큰 가정(스키마·공개 인터페이스·모듈 간 계약)은 질문으로 승격**해 멈춘다

## 2. ⏸ 게이트: 사용자가 스펙 이해를 승인할 때까지 진행 금지
- 단축 조건: 카드에 docs 정본 참조 + 수용 기준이 완비돼 있고 **질문 목록이 비어 있으면**, "이해 요약 5줄 + **가정 목록**"을 카드 댓글로 남기고 통과해도 된다 (가정도 기록 없이는 통과 못 한다). **질문이 하나라도 있거나, 화면 상호작용·데이터 형태를 결정하는 가정이 있으면 반드시 멈춘다.**

## 3. 계획
- 작업을 30분~2시간 크기로 쪼갠 목록 작성. 각 작업에 **정확한 파일 경로**와 완료 기준.

## 4. ⏸ 게이트: 사용자가 "go" 할 때까지 코드 작성 금지 (브랜치도 만들지 않는다 — no면 빈 브랜치만 남는다)

## 5. 구현
- **착수 처리 먼저**: `git pull origin main` 재실행(게이트 대기 사이에 main이 앞섰을 수 있다)
  - **pull에 이 카드가 가리키는 정본(docs) 변경이 섞여 왔으면 정지**: 해당 절을 다시 읽고 스펙 이해(1·2단계)가 여전히 유효한지 확인, 달라졌으면 게이트로 복귀(기획 변경이면 `/change` 확인)
  - **`git status --short` 가 비어 있지 않으면 정지·보고**(더러운 트리 위 브랜치 금지)
  - **카드가 이미 `진행중`+착수 댓글이 있는데 그 작업 브랜치가 내 로컬에 없으면 정지**(다른 세션·PC가 작업 중 의심 — 카드 댓글로 확인 후 진행) — **단 직전 `/module`로 생성한 모듈 스캐폴드는 예외**(곧 이 브랜치에 함께 커밋할 정당한 미커밋 파일이다)
  - 브랜치 `git checkout -b feature/$0-{슬러그}` + **라벨 전환을 명령으로**: `glab issue update $0 --label 진행중 </dev/null` → `glab issue view $0`로 반영 재확인
    (산문 지시("전환하라")는 안 지켜졌다 — 라벨 커버리지 9.5% 실측 2026-08-06. 명령·재확인까지가 전환이다) + 착수 댓글 한 줄(base main 해시 포함 권장) (상태 전이표의 "착수 시"가 바로 지금이다). 모듈 스캐폴드가 있으면 이 브랜치 첫 커밋에 함께 담는다
- **고위험 카드면**(`고위험` 라벨, 또는 CLAUDE.md '머지 등급'의 고위험 유형 해당) **지금 "경고 레인"임을 알려라**:
  - "머지 때 **AI 경고 리뷰 + 증적 3종**을 남기고 본인이 게이트를 실행합니다(동료 승인은 선택)"를 한 줄로 알린다. ★**승인자를 정하려고 묻고 멈추지 마라** — 옛 "동료 1명 승인"은 폐기다.
  - 카드에 `"고위험 카드 착수 — 머지 때 경고 레인(AI 경고 리뷰 + 증적 3종)"` 예고 댓글을 남긴다(실제 절차는 /done 7단계). 동료를 붙이기로 했으면 함께 @멘션(선택).
- **의존 카드라면** 두 갈래:
  ① 선행이 **이미 머지됨** → main에 선행 커밋이 있는지 확인하고 main에서 착수. 선행이 검수 반려 중이면 그 여파(스펙이 또 바뀔 수 있음)를 카드에 기록하고 진행 여부를 판단
  ② 선행이 **미머지** → 선행 feature 브랜치에서 분기 + 카드에 "base: feature/{선행} — 머지는 선행 먼저" 기록
- **먼저 본보기 모듈(`src/modules/<본보기모듈>`)의 해당 패턴(파일 위치·`index` 노출·테스트 형태·플래그 사용법)을 읽고 그 관례를 따라라.**
  이탈은 CLAUDE.md '작업 절차' 관례 규칙대로(의식적 이탈+이유 기록). 억지로 맞추다 이상해지는 게 베끼기의 실패 모드다.
- **구현 수단은 사다리 순서로**: 기존 코드(shared·본보기) 재사용 → 표준 라이브러리 → 플랫폼 내장(`<input type=date>`·CSS·DB 제약) → 기설치 의존성. **몇 줄로 되는 일에 새 의존성 금지**(추가 = package.json 공통 영역 공지 대상). 없으면 자기 모듈 안에 만든다(shared 승격은 2개 모듈 필요 시). 단 **검증·에러 처리·보안·접근성은 줄이는 대상이 아니다.**
- 과잉 추상화 금지: 구현 1개뿐인 인터페이스·제품 1개뿐인 팩토리·바뀔 일 없는 값의 설정화 — 둘째가 생길 때 만든다(shared 승격 기준과 동형). 의도적으로 한계를 남기면 주석 한 줄로 한계+승급 경로 명기(`// 한계: 전역 락 — 처리량 문제 시 계정별 락`), 크면 카드로.
- 상대 모듈 index 확인은 모듈 지도(`src/modules/_MODULE_MAP.md`)가 있으면 grep 대신 지도부터(재생성 `npm run boundaries -- --map`, 스캐폴드 전엔 `node scripts/check-boundaries.cjs --map` — 코드와 다르면 재생성이 정답).
- 스키마 변경이 있으면: 마이그레이션(날짜시각 파일명 — ★**규칙 형식이 도구 기본과 다르면 생성 직후 rename**, 어느 쪽이든 `ls | sort`로 **내 것이 맨 뒤인지** 확인. rules/migrations.md) + 멱등 시드 갱신 동봉(표본은 게이트 변수 뒤 — 같은 문서).
  **★마이그레이션 카드는 착수 전 팀 채팅에 한 줄 공지 + `고위험` 라벨**(전역 직렬 자산 — 두 사람이 동시에 만들면 나중 것 순서가 꼬여 스키마가 깨진다).
- **되돌리기 어려운 결정을 이 작업에서 새로 정하게 되면**(모듈 경계·두 모듈 간 계약·공개 API 형태·스키마 방향) → **`/adr` 로 기록**하고 진행한다(안 남기면 다음 세션 AI가 옛 방향으로 "복원"한다). 두 모듈 계약이면 양쪽 소유자 확인 후.

## 6. 테스트
- 층별 테스트 작성(본보기의 테스트 형태 참조) → `npm test` → **green이 될 때까지 반복. red인 채 다음 단계 금지.** (변경에 `.gitlab-ci.yml` 있으면 `glab ci lint`도 — 무효 CI는 테스트가 못 잡는다)
  (명령이 repo CLAUDE.md '실행·테스트' 절과 다르면 **CLAUDE.md가 정본**)
- ★**DB·외부 의존이 필요한 스택이면 돌리기 전에 기동부터 확인** — 컨테이너가 내려가 있으면 실패가 **코드 결함처럼 보인다**(bnsone 실측: 오독할 뻔). red를 고치기 전에 "의존이 떠 있나"를 먼저 답하라.
- **테스트는 공개 경계에 건다**(모듈 `index` 공개 함수·API 응답·화면 동작) — 내부 함수·비공개 구조에 건 테스트는 행동이 안 변해도 리팩토링에 깨진다(그렇게 깨지면 잘못 건 것). 남의 모듈을 mock 할 때도 그 모듈의 공개 인터페이스만
- **동어반복 테스트 금지**: 기대값을 코드와 같은 방식으로 계산해 넣으면(`expect(add(a,b)).toBe(a+b)` 류·구현을 베낀 스냅샷) 항상 통과하는 가짜다 — 기대값은 **독립 출처**(스펙·손으로 푼 예시·알려진 리터럴)에서 가져와라

## 7. 마무리
- 화면이 있는 카드면 **`/ui $0` 로 UI를 디자인 시스템에 맞춰 완성도 있게 만들고**(공용 컴포넌트·모바일 우선·상태 3종) → **`/inspect $0` 로 화면 검사 묶음**(인터랙션·이상 입력·반응형)을 돌려라 — 테스트 green은 코드 층만 본다
- **모든 변경을 커밋**(첫 줄 `#$0 무엇을 했는지`) — 미커밋 작업트리인 채 /done 으로 가지 마라
  - ★**변경 파일을 경로로 지목해 add 하라 — `git add -A`·`add .` 금지**: 작업트리엔 남의 미추적 파일·잔해가 있을 수 있다(bnsone 실사고 15c882c — 충돌 해결 중 `add -A`가 무관한 .idea·기획 파일을 main에 쓸어 담음. 파일명 NFC 중복 사고의 유입 경로이기도)
- 구현이 docs와 달라진 점이 있으면: docs 수정을 이 브랜치에 동봉 + 차이 요약을 준비해 둔다 (실제 카드 댓글은 `/done` 6단계가 남긴다).
- 완료 보고에는 **증거**를 붙여라: 테스트 출력 요약 + 무엇을 실행해 어떻게 확인했는지. "될 겁니다"는 증거가 아니다. (실앱 확인엔 내장 `/run` 등을 써도 된다 — 화면 검사 정본은 /inspect)
- ★**스킬·규칙·킷 문서에 막혔거나 우회했거나 헷갈렸으면 스스로 남긴다**(사용자에게 묻지 말고 판단): `docs/friction.md` 한 줄(`날짜 /스킬 — 무엇이`, 이 커밋 동봉) — **막힘·우회는 줄 머리 `[막힘]` 태그**(즉시 수리 후보). 있는데 그냥 넘어가는 게 채널이 비는 원인이다(외부 도구·라이브러리 함정은 대상 아님).
- 사용자에게: "완료했습니다. `/done $0` 으로 머지하고, 배포 후 화면을 직접 확인하세요."
