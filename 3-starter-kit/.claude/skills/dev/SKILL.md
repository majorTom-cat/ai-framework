# /dev — 이슈 #$0 기능 개발

> **계약** · 입력: 이슈번호(+지시) · 산출물: 구현 코드+테스트(feature 브랜치 커밋); 화면이면 /ui·/inspect 자동 · 검증: 테스트 green + /inspect → /done

> **예시**: `/dev 12` · `/dev 12 로그인은 소셜 로그인만` — **번호 뒤에 덧붙인 지시도 스펙에 반영**한다(전체 입력: `$ARGUMENTS`).

**이 스킬을 쓰면 안 되는 경우**: 반나절 미만의 작은 수정·버그·정리 → `/fix $0` (판별 기준은 /fix 참조)

> ★★**곁에 두 파일이 있다 — 해당 단계에 오면 반드시 읽어라**: `단계상세.md`(§1 테스트 판정 · §2 화면 확인 · §3 1단계 · §4 2단계 게이트 · §5 5단계 구현 · §6 ❌금지) · `함정.md`(이렇게 하면 틀린다 + 경위 §1~§6). **이 안내를 여기 둔 이유**: 컴팩션은 스킬마다 **앞 5,000토큰만 남기고 뒤를 자르므로**(공식), 본문 뒤쪽에 있는 포인터는 대화가 길어지면 **포인터째로 사라진다.** 이 줄은 앞쪽이라 살아남는다.
> ★★**잘려도 이 셋은 지켜라**(«❌ 금지» 절은 `단계상세.md` §6) — ①**남의 모듈을 수정하지 마라** ②**main 에서 직접 작업하지 마라** ③**게이트를 건너뛰지 마라(예외 없음)**. 그리고 «단순해서 스펙 확인 불필요»·«아마 되겠지, 테스트는 나중에»는 핑계다 — 완료 기준은 두 줄이면 되고, Seems right 는 증거가 아니다.

아래 체크리스트를 응답에 복사해 진행하며 체크하라. **⏸ 게이트에서만 멈추고, 그 사이는 연속 실행.**

```
- [ ] 1. 스펙 확인
- [ ] 2. ⏸ 스펙 승인   ← 작은 카드는 4와 묶어 한 번만
- [ ] 3. 계획
- [ ] 4. ⏸ 계획 go
- [ ] 5. 구현
- [ ] 6. 테스트 green
- [ ] 7. 화면 확인 안내 → /done
```

## 1. 스펙 확인
**«이 카드가 무엇을 요구하는지»를 5줄로 정리하고, 애매하면 질문 목록으로 멈춘다.** 절차 전체는 **`단계상세.md` §3 을 열어 그대로 하라.**
- ★**잘려도 지킬 것**: **내 모듈인지 먼저 확인**(카드 `모듈:` 라벨 ↔ CLAUDE.md 소유 표. 남의 모듈이면 착수 거부+소유자 앞 인터페이스 카드 제안) · **`대기(불명확)` 라벨이면 착수 거부** · **전 모듈이 얹히는 기반이면 `/design` 증분을 먼저 제안** · **`git pull --ff-only origin main` 먼저** · **docs 는 카드가 가리킨 절만** 읽는다.
- ★**본보기 모듈이 실제로 있는지 지금 확인하고, 없으면 그 자리에서 «공백»으로 보고하라 — 속으로 메우지 마라**(경위 `함정.md` §2).

## 2. ⏸ 게이트: 사용자가 스펙 이해를 승인할 때까지 진행 금지
**«이해 5줄 + 가정»을 보이고 승인을 받는다. 조건이 맞으면 3단계까지 이어서 한 번만 선다**(묶음 게이트 = 4단계 게이트를 겸한다). **조건 넷과 예외는 `단계상세.md` §4 를 읽고 판정하라.**
- ★**잘려도 지킬 것**: 묶음 조건은 **①질문 0건 ②작업 3개 이하 ③«실제 소비자가 있는» 계약을 안 바꾼다(소비자 0이면 해당 없음 — §4) ④정본 해석을 바꾸는 가정이 없다**. ★**사용자 본인이 쓴 카드는 ①④만 본다**(§4). 남이 쓴 카드는 하나라도 아니면 2회. 묶음에서 **스펙이 정정되면 계획을 다시 짜서 보여준다.**

## 3. 계획
- 작업을 30분~2시간 크기로 쪼갠 목록 작성. 각 작업에 **정확한 파일 경로**와 완료 기준.
- ★**이전(migration)·개명 작업은 «호출부 N곳 — 그중 의미를 따져야 하는 것 M곳»을 계획 단위로 적어라.** 파일 경로 + 완료 기준만 요구하면 정작 시간을 먹는 일이 계획에 안 잡힌다(2026-08-26 실측: 호출부 35곳·26곳, 일부는 기계적 치환 불가라 하나씩 의미를 따져야 했다). M 이 크면 그것만으로 작업 한 칸이다.
- ★**그 목록은 내부 정확도용이다 — 사용자에게 보여줄 때는 따로 쓴다**: 파일명 나열이 아니라 «무엇이 어떻게 달라지는지»로(CLAUDE.md 세션 규칙).

## 4. ⏸ 게이트: 사용자가 "go" 할 때까지 코드 작성 금지 (브랜치도 만들지 않는다 — no면 빈 브랜치만 남는다)
- 2단계에서 **묶음 게이트로 승인받았으면 이 게이트는 이미 통과**다(같은 승인을 두 번 받지 마라).

## 5. 구현
**착수 처리(pull 재실행 → 트리 확인 → 브랜치 → 라벨 전환 + 착수 댓글)부터 하고 짠다. 절차 전체는 `단계상세.md` §5 를 열어 그대로 하라.**
- ★**잘려도 지킬 것**: **`git status --short` 가 비어 있지 않으면 정지·보고**(더러운 트리 위 브랜치 금지) · pull 로 **정본(docs) 변경이 섞여 왔으면 정지**하고 스펙 이해가 유효한지 다시 본다 · **pull 뒤엔 `npm install` → 마이그레이션 적용 → ORM 생성물 재생성 셋 다** 돌린다(시드가 먼저 깨진다) · **라벨 전환은 명령 + 재확인까지가 전환이다**(산문 지시는 안 지켜졌다 — `함정.md` §3).
- ★**먼저 본보기 모듈의 해당 패턴을 읽고 그 관례를 따라라.** 구현 수단은 **기존 코드 → 표준 라이브러리 → 플랫폼 내장 → 기설치 의존성** 사다리 순서 — **몇 줄로 되는 일에 새 의존성 금지**(단 검증·에러 처리·보안·접근성은 줄이는 대상이 아니다). **과잉 추상화 금지**(둘째가 생길 때 만든다).
- ★**되돌리기 어려운 결정을 새로 정하게 되면 `/adr` 로 기록**하고 진행한다(안 남기면 다음 세션이 옛 방향으로 "복원"한다).
- ★**마이그레이션 카드는 `고위험` 라벨 + 착수 전 «충돌 없음» 확인**(전역 직렬 자산). 공지 조건은 `rules/migrations.md` 가 정본.

## 6. 테스트
- 층별 테스트 작성(본보기의 테스트 형태 참조) → `npm test` → **green이 될 때까지 반복. red인 채 다음 단계 금지.**
  (명령이 repo CLAUDE.md '실행·테스트' 절과 다르면 **CLAUDE.md가 정본**. 변경에 `.gitlab-ci.yml` 있으면 `glab ci lint` 도 — 무효 CI는 테스트가 못 잡는다)
- **테스트는 공개 경계에 건다** · **동어반복 테스트 금지**(기대값은 **독립 출처**에서) · **공유 DB 에서는 내가 만든 행으로 단언을 좁혀라**. 이유는 `단계상세.md` §1.
- ★**red 를 고치기 전에 «의존이 떠 있나 · 내 탓인가»를 먼저 답하라** — 컨테이너·ORM 생성물·미설치 패키지가 원인인 red 를 **코드 결함처럼 읽는 사고가 반복됐다**(실측 4건). 판정 순서는 **`단계상세.md` §1 을 읽어라.**
- ★★**초록은 케이스가 유효하다는 증거가 아니다 — «이 케이스가 결함을 잡는가»를 따로 확인하라.** 케이스 **수**는 근거가 못 된다(2026-08-28 두 번 실측). **방법은 `함정.md` §6 을 지금 읽고 그대로 하라** — ①겨눈다 ②지운다 ③판정한다 ④되돌린다, 넷이 각각 다른 방식으로 틀렸다(실측 6건. 여기서 짐작하지 마라).

## 7. 마무리
- ★**로컬 화면을 보기 전에 재빌드 + 브라우저 하드 리로드** — 안 하면 코드 변경이 화면에 안 나타나 «구현이 틀렸다»로 오독하고, 옛 페이지에서 누른 저장이 **조용히 실패**한다. 경위는 **`단계상세.md` §2.**
- 화면이 있는 카드면 **`/ui $0` → `/inspect $0`**(테스트 green 은 코드 층만 본다). ★**디자인 정본이 «채택 대기»면 `/ui` 는 채택 후로 미루고 `/inspect` 만** 돌리고, **미룬 사실을 카드 댓글 한 줄로 남겨라**(`단계상세.md` §2).
- **모든 변경을 커밋**(첫 줄 `#$0 무엇을 했는지`) — 미커밋 작업트리인 채 `/done` 으로 가지 마라.
  - ★**변경 파일을 경로로 지목해 add 하라 — `git add -A`·`add .` 금지**: 작업트리엔 남의 미추적 파일·잔해가 있을 수 있다(실사고 경위 `함정.md` §5)
- 구현이 docs와 달라지면 **`_digest.md` 수정을 동봉**(원문 금지). 완료 보고에는 **증거**(테스트 출력 요약 + 무엇을 실행해 어떻게 확인했는지)를 붙여라 — "될 겁니다"는 증거가 아니다.
- ★**막혔거나 우회했거나 매끄럽지 않았으면 `docs/friction.md` 한 줄**(이 커밋 동봉, 묻지 말고 판단) — **`[막힘]` 태그면 «마찰 수거» 카드 멘션 한 줄까지가 한 벌**이다. 정본 = CLAUDE.md friction 절.
- 사용자에게: "완료했습니다. `/done $0` 으로 머지하고, 배포 후 화면을 직접 확인하세요."

**❌ 금지 절**은 `단계상세.md` §6 — 위 «잘려도 지킬 것» 셋이 그 요약이다.
