# /ui — 화면 UI 완성도 있게 만들기

> **계약**
> - 입력: 이슈번호/화면명(구현) 또는 `시안 {화면}`(후보 생성) 또는 `시안 채택 {화면} {안} [#카드]`(채택 확정)
> - 산출물: 구현=프론트 코드(diff) / 시안 생성=HTML 후보 2~3안+notes+갤러리 섹션+**시안 선택 카드(체크박스)** / 채택=갤러리 배지·notes·카드에 결정 기록
> - 검증: 구현=/inspect+상태3종 / 시안=⏸ 사람 선택 게이트(허브 URL 전제)
> - 도구: glab(카드 생성·체크 읽기·닫기)

> **예시**: `/ui 12` (구현 — 보통 화면 카드에서 `/dev`가 자동 호출) · `/ui 시안 출퇴근화면` (후보 2~3안) · `/ui 시안 채택 출퇴근화면 B` (B안으로 확정)

> ★CLAUDE.md **'남기기 전 미리보기'** 공통 규칙 적용 — 시안 선택 카드 발행·카드 닫기·갤러리/notes 결정 기록은 **만들기 직전 요약 → 사용자 OK 후** 진행.

## 🎨 시안 모드 — 인자가 `시안 …`이면

디자이너 없는 팀에서 "화면이 어떻게 생겨야 하나"를 **고를 수 있게**. /design의 "2~3안 → 사람 결정"의 화면판.

### 0. 진입 판정 (생성·채택 어느 갈래든 **만들기 전에** 여기부터)
- **모드 분기**: `시안 채택 {화면} {안} [#카드]` → **갈래 2**. `시안 {화면}` → **갈래 1**.
- **★전제 — 시안 허브 URL이 없으면 여기서 멈춰라**: `CLAUDE.md` ★실행 절에 시안 허브 URL(`<시안허브URL>`이 리터럴로 남아 있으면 미설정)이 있어야 시안을 **아무도** 볼 수 있다. 없으면 HTML을 만들기 전에 멈추고: "공통 개발자가 시안 허브 세팅 먼저(→ `docs/00_Guide/sian-hub-setup.md`) — 또는 인스턴스에 GitLab Pages가 정상이면 각 프로젝트 CI `pages` 잡" 안내.
- **오진입 가드**: `시안 {화면}`인데 그 화면 코드가 `src/`에 **이미 있으면** — "이미 구현된 화면. 시안이 아니라 수정(`/ui {카드번호}`)을 원하신 것 아닌지" 확인 후 멈춤.
- **보강 재실행**: 갈래 1인데 그 화면에 **이미 시안이 있으면**(`docs/05_UIUX/screens/{화면}/` 존재) — 기존 안을 지우지 마라. "안을 더 추가할지, 특정 안만 고칠지" 물어 **기존 유지 + 새 안 추가**로 진행.

### 갈래 1) 후보 생성 — `시안 {화면이름}` (구현 전, 화면당 1회)

1. `git pull` 후 **그 화면과 관련된 요구만** 읽는다 — `_digest.md` + 근거 절(통독 금지).
   - **요구 문서가 아직 없는 화면이면**(digest에 그 영역이 없음): 감으로 지어내지 마라 — 기획자에게 요구를 요청(`/card {화면} 요구 문서 요청`)하거나,
     있는 **백엔드 계약**(그 모듈 `index`의 공개 함수)·유사 화면을 데이터 앵커로 삼고 **미정 항목(카테고리·핀·페이지네이션 등)을 `notes.md`에 "미해결"로 명시**한다.
   - 디자인 시스템(`docs/05_UIUX/_designsystem.md`·`src/shared/ui`)이 있으면 그 안에서, 없으면 이 시안이 씨앗이 됨을 인지(씨앗은 채택/구현 때 심는다 — 시안은 `docs`만).
2. **구조가 다른 2~3안** — 장식이 아니라 **레이아웃·동선이 다른 안**(예: A=큰 버튼 · B=대시보드 · C=단계형). 각 안 컨셉 한 줄.
   - **색·타이포·톤은 `docs/05_UIUX/design-tokens.md`(디자인 아이덴티티 정본)가 있으면 그걸 따르고, 없으면 기존 채택 시안의 토큰 계열을 유지**한다 — 안마다 다른 건 구조지 정체성이 아니다.
   - (정본이 아직 없고 채택 시안이 2개+ 쌓였으면 "토큰을 추출해 정본을 만들자"고 공통 개발자에게 제안)
3. **시안 선택 카드부터 만든다**(번호가 있어야 커밋·채택 명령이 그걸 가리킨다) — **`/ui`가 glab로 직접 생성**한다(`/card`엔 이 체크박스 양식이 없으니 위임하지 마라). **결정권자(assignee) = 이 화면의 검수/결정 담당** — 차터의 기획/결정권자 또는 CLAUDE.md 소유표의 그 모듈 소유자에서 도출하고, **불명확하면 사용자에게 물어라**(초기·파일럿엔 보통 공통 개발자):
   ```
   glab issue create --title "{화면} — 시안 선택" --assignee <결정권자아이디> --description "<아래 본문>"
   ```
   본문 = **GitLab task list 체크박스**(허브 링크 = `<시안허브URL>/<프로젝트>/screens/{화면}/시안X.html`):
   ```
   ## {화면} 시안 — 하나만 체크하세요 ✅ (댓글 아님)
   - [ ] **A안** · {A 컨셉} — [열기](<시안허브URL>/<프로젝트>/screens/{화면}/시안A.html)
   - [ ] **B안** · {B 컨셉} — [열기](…/시안B.html)
   체크하면 개발자가 `/ui 시안 채택 {화면} <안> #<이 카드번호>` 로 확정 → 갤러리·notes에 자동 기록.
   ```
   나온 카드번호를 사용자에게 알린다.
4. **파일 생성**:
   - `docs/05_UIUX/screens/{화면이름}/시안A.html`·`시안B.html`(·`C`) — 각각 **자기완결 단일 HTML**(인라인 CSS, 더미 데이터로 실감), **375px 모바일 우선**+데스크톱, 핵심 상태(빈·에러) 표현.
     - **외부 요청 0**(CDN 폰트·스크립트 금지 — 시스템 폰트 스택·인라인만. 사내망에서 CDN이 막히면 검수자마다 다른 화면을 본다).
     - **`<body>` 직후에 갤러리 복귀 링크 고정 배지**(`<a href="../../index.html">← 시안 갤러리</a>`, 화면 좌상단 고정·작게) — 없으면 열람자가 뒤로 갈 길이 없어 URL을 지워야 한다.
   - `notes.md` — 안별 컨셉·차이 표 + 맨 끝에 `## 선택` **미결정 블록**(`> ⏸ 미결정 — 선택: __안 · 이유: __ · 결정일: __ · 결정자: __`).
   - **갤러리 `docs/05_UIUX/index.html`** — 없으면 **`.claude/skills/ui/gallery-template.html`을 그 자리로 복사**하고 `<프로젝트>`를 채운다. 그 파일의 예시 `<section>`과 **똑같은 구조**로 이 화면 섹션을 추가(`picked-tag` span은 `hidden`인 채, 안별 링크). 마커 주석(`▲ 새 화면 …`) 위에 넣는다. → 허브가 이 index.html을 그대로 보여준다(화면 여럿이면 섹션이 쌓임).
5. **발행**: `#<카드번호> 시안: {화면} 후보` 로 커밋 → **브랜치→MR→main 머지**(팀 규칙: main 직접 push 금지). 머지되면 git-sync가 ≈30초 뒤 허브에 올려 카드의 링크가 살아난다.
   - **시안 요청 카드에서 출발했으면**(기획자 발주 — `/card` 유형) 그 요청 카드에 "후보 발행 — 선택은 #<선택카드번호> · `셀프완료`" 댓글(증거 = 선택 카드·허브 링크)을 달고 닫는다(화면 없는 발주 카드 = 셀프완료 예외).
6. **⏸ 선택 게이트 — 여기서 멈춘다. AI는 고르지 않는다.**
   - 열람 = **시안 허브** `<시안허브URL>/<프로젝트>/` — 링크 클릭 시 **브라우저에서 실물 HTML(스크롤·버튼 O)**, 이미지 아님. 앱 검수 서버와 별개, 공통 개발자가 인스턴스 1회 세팅.
   - ⚠ **GitLab CE 체크박스는 상호배타가 안 된다**(라디오 아님·스코프라벨 유료) — 카드에 "하나만 체크" 명시. 여러 개 체크는 갈래 2에서 "미결정"으로 막는다.
   - **⚖️ 역할 경계**: 시안 선택 = 구조·배치·정보 우선순위. 세부 인터랙션은 구현 단계(`?preview=`)의 몫.
   - ❌ **기각된 경로(다시 쓰지 마라)**: GitLab 파일뷰(코드로만) · 채팅 HTML 전송 · 스크린샷 이미지(잘림·인터랙션 불가) · 화면공유. (Design Management 18.6 deprecated.)
   - ▶ 다음: 결정권자가 허브에서 보고 카드 체크 → `/ui 시안 채택 {화면} {안} #<카드번호>`.

### 갈래 2) 채택 확정 — `시안 채택 {화면} {안} [#카드번호]` (체크됐거나 결정권자 지시가 있을 때만)

결정을 **댓글 한 줄이 아니라 3곳에 기록으로** 남긴다(나중에 STEP6 설계·STEP7 개발 입력):
0. **카드 찾기 + 체크 상태 확인**:
   - 카드번호가 인자에 있으면 그 카드, 없으면 `glab issue list --search "{화면} 시안 선택"` 로 찾는다.
   - **`glab issue view <카드>` 로 본문의 체크 상태(`- [x]`)를 읽는다.**
   - **2개 이상 체크** → **채택하지 말고 멈춰라**: "여러 안이 체크됨 = 아직 미결정. 하나만 남겨 주세요" 확인 요청(**AI가 임의로 고르지 마라**).
   - **인자 `{안}` ≠ 체크된 안** → 어느 게 맞는지 확인 후 진행.
   - **카드 댓글에 혼합·수정 요청이 있으면**("A 레이아웃 + B 색" 등) → 체크된 안을 그대로 채택하지 말고 멈춰라: 요청대로 **혼합안을 새 후보로 추가**(갈래 1 보강 재실행 — 기존 안 유지)한 뒤 다시 고르게 안내한다(GitLab 가이드 §5-1이 사용자에게 이 경로를 안내함).
   - **0개 체크(구두 지시만)** → 지시받은 `{안}`으로 진행하되, 카드 본문의 그 줄을 `- [x]`로 바꿔 기록을 일치시킨다.
1. **갤러리** `index.html` 그 화면 섹션(gallery-template 클래스 그대로): `picked-tag`의 `hidden` 제거 + 텍스트 `· 선택: {안}` / 채택안 링크에 `class="picked"` / 나머지 안 링크에 `class="dropped"` + `href`를 `_drafts/{화면}/시안X.html`로 / notes 줄을 "채택: {안}"으로.
2. **notes.md** `## 선택` 블록을 **안·이유·결정일·결정자**로 채움. **이미 채택 이력이 있으면(번복)** 옛 줄을 지우지 말고 "변경: {옛안}→{새안}(날짜·사유)"로 **병기**. 탈락안 → `docs/05_UIUX/_drafts/{화면}/`로 이동(삭제 ❌ — 이력).
3. **카드**: 결정 요약 + **`셀프완료` 표식** 댓글(증거 = 갤러리·notes 링크) + **닫는다**(시안 선택 카드는 화면 없는 **docs·결정 카드** → "셀프완료(AI 대행 가능)" 예외에 해당. 검수 카드가 아니다). `docs/_STEP_INDEX.md` STEP 5 행을 **🔄 진행**+링크로 갱신(화면 하나 채택 ≠ STEP5 완료 — 전 화면 채택·구현돼야 ✅). `#<카드> 시안: {화면} {안} 채택`으로 커밋 → MR → 머지.
→ 머지 후 git-sync가 허브 갤러리를 "채택됨"으로 갱신. 채택안이 이 화면의 **정본 시안**(/dev·구현 /ui가 참조).
▶ 다음: 화면 카드 없으면 `/card {화면} 구현`, 있으면 `/dev {번호}`.

⛔ 시안 모드 금지: 앱 코드(`src/`) 수정(시안은 docs만) · AI가 임의로 안을 선택·폐기 · 안끼리 장식만 다르게(구조가 달라야 고를 의미가 있다).

> 이 팀엔 **디자이너가 없고**(charter), 모듈을 여러 명이 나눠 만든다. 그래서 목표는 둘:
> ① **일관성**(모듈이 달라도 한 앱처럼) ② **완성도**(AI 특유의 밋밋함 회피).
> **친절한 선배처럼**: 만들기 전 방향 한 줄 → 만들고 → 반드시 `/inspect`.

## 0-a. 구현 모드 오진입 가드 (인자가 `시안 …`이 아닐 때)
- 인자가 **이슈번호가 아니고**, 그 화면의 코드가 `src/`에 **아직 없으면** — 구현할 대상이 없는 것이다. **"시안을 원하신 건가요? → `/ui 시안 {화면이름}`"이라고 묻고 멈춰라.** 시안 없이 화면 코드부터 새로 만들지 마라(순서 역행 — 시안 선택이 먼저다). (인자가 `시안 …`인 경우의 가드는 위 "0. 진입 판정"에 있다.)

## 0. 먼저 — 우리 디자인 시스템을 읽어라 (일관성의 핵심)
- **`<디자인시스템 위치>`**(예: `src/shared/ui/` · `docs/05_UIUX/_designsystem.md`)를 먼저 읽는다: 색·타이포·간격 토큰, 공용 컴포넌트, 브레이크포인트, 쓰는 프레임워크(`<UI프레임워크>`).
- **아직 없으면**(초기 화면): 지금 화면을 근거로 **최소 토큰·공용 컴포넌트·프레임워크를 먼저 정해** `docs/05_UIUX/_designsystem.md` + `src/shared/ui` 에 씨앗을 심는다 — 그래야 다음 화면들이 여기서 안 벗어난다. (shared 변경이니 착수 전 채팅 공지.)
- 시안이 있으면(`docs/05_UIUX/screens/{화면}/`) 그 소스가 정본. **없으면**(디자이너 부재라 대부분) 요구사항 + 디자인 시스템으로 직접 설계한다.

## 1. 이 화면의 방향 (frontend-design 원칙 — 단, 시스템 안에서)
- 목적·사용자·주요 동작을 한 줄로. 이 앱은 **업무용**(중소기업 직원 다수) — 화려함보다 **명료·빠름·모바일**이 먼저.
- 그 안에서 완성도를 올린다: 뚜렷한 **타이포 위계**, 넉넉한 간격·정렬, **모든 상태(로딩·빈·에러·성공)**, 명확한 1차 액션, 접근성 기본(대비·키보드 포커스·라벨·터치 타깃 44px).
- ⛔ **밋밋한 AI 기본값 회피**: 시스템 폰트 그대로·보라 그라데이션·의미 없는 카드 나열·상태 없는 화면.
- 화면마다 미학을 제멋대로 바꾸지 마라 — **일관성 > 개별 플레어**. 바꾸려면 시스템(shared)에서.
- (플러그인 `frontend-design`이 설치돼 있으면 이 단계에서 그 접근을 활용해도 좋다 — 없어도 위 원칙으로 충분하다.)

## 2. 만들기 — 공용부터, 모바일부터
- **`src/shared/ui` 공용 컴포넌트를 먼저 쓴다.** 없어 새로 만들면, 2개 이상 모듈이 쓸 것은 **shared 승격 제안**(CLAUDE.md 소유 경계 규칙).
- **모바일 우선**(charter: 모바일 전체 지원): 375px에서 먼저 설계 → 넓은 화면으로 확장.
- **무료 UI 프레임워크·템플릿만**(charter 제약) — 유료 에셋 금지.
- 본보기 모듈(`src/modules/<본보기모듈>`)의 화면 패턴이 있으면 그것을 먼저 베낀다.

## 3. 만든 뒤 — 반드시 검사로 넘긴다
- **`/inspect $0`**: 반응형(375px)·가로 넘침·콘솔 에러·인터랙션·이상 입력 (시안 있으면 소스 대조).
- **상태 3종(빈·로딩·에러)이 실제로 렌더되는지** 눈으로 확인. 안 보이면 아직 안 끝난 것.

## ❌ 금지 — 핑계와 반박
| 핑계 | 반박 |
| --- | --- |
| "일단 되게만, 디자인은 나중에" | 나중은 안 온다(디자이너 없음) — 만들 때가 완성도의 유일한 기회 |
| "이 화면만 좀 다르게 하고 싶다" | 여럿이 만드는 앱에서 개별 미학 = 누더기. 바꿀 거면 shared에서 전체로 |
| "데스크톱에서 잘 보이니 됐다" | charter는 모바일 전체 지원 — 375px가 1차 기준 |
| "빈/에러 상태는 흔치 않으니 생략" | 실사용 첫날 바로 나오는 상태다 — 상태 없는 화면은 미완성 |
