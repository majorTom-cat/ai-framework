# /docs — 받은 문서를 정본에 반영

> **계약** · 입력: 압축/폴더 경로(+카드번호) 또는 웹으로 이미 올라온 STEP 문서 · 산출물: 정본 폴더 배치+파일명 정규화, digest·지도 갱신 · 검증: 제자리 배치 + 인덱스 행 갱신 (⏸ 배치 전 확인)

> **예시**: `/docs inbox/기획_2월.zip` · `/docs "받은 문서/2월 기획"` (경로에 공백 있으면 따옴표) · `/docs` (기획자가 웹으로 올린 새 STEP 문서 반영 = 경로 A)

받은 파일: $ARGUMENTS

> **먼저 어느 경로인지 판단하라 — 문서가 repo 안에 이미 있나?**
> - **경로 B (뭉치 받기)**: repo *밖* zip/폴더를 넘겨받았다 → 0~4 그대로 (inbox 해제 → 배치).
> - **경로 A (웹 직접 커밋 = 길 A)**: 기획자가 GitLab 웹으로 STEP 문서를 이미 `docs/`에 올렸다(인자 없음 또는 "올라온 문서 반영"). → **1(inbox 해제)을 건너뛴다.** 문서가 이미 정본 위치에 있으니 2는 **배치·명명이 맞는지 검토만**. **두 경로 모두 5(digest·지도 갱신)는 필수** — 이게 빠지면 인덱스가 현실과 어긋난다.

0. `git pull origin main` 후 시작. **이 문서 반영에 연결된 카드 번호를 확인**한다(초기 문서 뭉치를 넘겨받은 경우 등).
   - 없으면 `/card`로 먼저 만들어 번호를 확보하라 — 이후 커밋·브랜치가 `#{카드번호}`를 쓴다.
   - **다른 목적의 열린 카드를 빌리지 마라**(인수 이력이 남의 카드에 섞이면 추적 불가).
   - **경로 A는 기획자 커밋에 카드가 없는 게 보통** — 정상이다. 이 digest·지도 반영 작업의 카드를 공통 개발자가 만들어 그 번호로 커밋한다.
1. **〔경로 B만〕 수신함에 풀기**: `docs/inbox/{오늘날짜}-{간단이름}/` 에 압축 해제 — **repo 밖 경로의 파일이면 inbox로 복사해서** 시작(원본은 건드리지 않는다). *경로 A는 이미 정본 위치에 있으니 건너뛴다.*
2. **내용 목록화**: 파일들을 훑고, 각각이 정본의 어디에 해당하는지 **표로 제안**하라(경로 A는 "이미 올바른 위치인지" 검토):
   | 받은 파일 | 내용 요약 | 배치 제안 (docs 폴더: 00_Project·01_CurrentState·02_Problem·03_Requirement·04_Business·05_UIUX·06_TechnicalDesign·adr·00_Guide·inbox) | 비고(신규/기존 갱신/충돌) |
   - **STEP 분석 문서**: 차터→`00_Project/` · 현황분석→`01_CurrentState/` · 문제정의→`02_Problem/` · 요구사항→`03_Requirement/` · 업무설계→`04_Business/` · UI/UX→`05_UIUX/` · 기술설계→`06_TechnicalDesign/` · 시안 파일 → `05_UIUX/screens/{화면}/`
   - **여러 뎁스(하위 폴더가 깊은) 문서를 받으면 원래 계층 구조를 보존해 배치**한다 — 억지로 한 파일로 평탄화하지 마라. 받은 폴더 트리를 정본 폴더 아래에 그대로 옮기되 이름만 정규화
   - **기존 문서와 내용이 충돌하면 반드시 "충돌"로 표시**하고 어느 쪽이 최신인지 사용자에게 물어라
3. **⏸ 사용자 확인 후** 배치: 복사 + 파일명을 정본 규칙(영문 PascalCase, **원제목은 문서 첫 줄에 병기** — 보낸 사람이 못 알아보면 정본이 아니다)으로 정규화.
   - **전달용 머리말("정본 아님·검토용" 류)은 배치 시 제거**(원문 무수정 원칙의 유일한 예외 = 파일명·위치·전달용 머리말). 원본은 `docs/inbox/_archive/{오늘날짜}/` 로 이동해 보존.
   - *경로 A는 이미 배치돼 있으니, 명명이 규칙과 다를 때만 정규화 제안 — 기획자가 웹에서 올린 파일명을 바꿀 땐 카드 댓글로 알린다.*
   - ***정규화·이동할 것이 없으면 검토 표 제시로 확인을 갈음하고 이 게이트는 생략해도 된다.***
4. **용량 검사**: 10MB 넘는 파일(psd·fig 원본 등)은 커밋하지 말고 "공유 드라이브에 두라"고 안내
5. **〔STEP 문서면 필수 — 경로 A·B 공통〕 digest·지도 갱신** (같은 커밋에): 배치한 문서가 STEP 산출물(현황·문제·요구·업무·UIUX·기술설계)이면 —
   - 그 STEP 폴더에 **`_digest.md` 생성/갱신** — 양식(`.claude/rules/docs.md`): **한눈에 · 확정된 것 · 다음 STEP 입력 · 미해결·질문 · 근거 링크**. **현재 상태만** 담고 원본을 통째로 복사하지 마라(요약).
   - **`docs/_STEP_INDEX.md`** 의 해당 STEP 행: digest 링크를 채우고 상태 갱신 — **그 STEP의 예정 범위가 다 찼으면 `✅ 확정`, 일부 슬라이스만 왔으면 `🔄 진행`**(예: 요구사항 9영역 중 1영역만 도착. 애매하면 기획자에게 확인). **이 파일이 없으면** 킷이 배송하는 양식(STEP 0~10 개별 행 + STEP 11 의도적 생략 각주 · 상태 어휘 `⏳ 대기`/`🔄 진행`/`✅ 확정`)으로 **새로 만든 뒤** 채운다.
   - 기존 요구의 **변경**이면 앞 STEP digest의 영향 절도 함께 손본다. 새 문서가 **앞 STEP digest의 '미해결'을 해소**하면 그 항목에 해소 표시(→ 근거 링크)를 하고, **앞 STEP에 없던 새 사실**을 담고 있으면(근거 단절) digest '미해결·질문'에 "출처 확인 필요" + 기획자 @멘션 대상으로 기록한다.
   - **옛 STEP 문서와 내용이 상충하면**(차수·정책 등) — **최신 문서가 정답**(`rules/docs.md`). 세 동작:
     - ①양쪽 `_digest.md`에 상충·확정 기록
     - ②옛 문서 원문의 해당 절 머리에 **대체됨 표지판** 삽입: `> ⚠️ 대체됨(YYYY-MM-DD): 이 절의 {항목}은 {최신 문서 경로 §절}에서 조정됨 — 그쪽이 정본` — **내용은 지우지도 고치지도 않는다, 표지판만**
     - ③문서 주인(기획자) **@멘션 통보** — 허락이 아니라 알림(기계적 마커라서), 내용 정리는 주인이 원할 때.
     - 표지판 삽입도 repo 산출물이므로 **미리보기 규칙 적용**: 어느 파일 어느 절에 무슨 문구인지 보여주고 OK 후 실행.
   - (문서 정리·시안 등 STEP 산출물이 아니면 이 단계는 건너뛴다.)
6. **커밋·알림**: 브랜치 `docs/{카드번호}-{간단이름}` 에서 커밋(첫 줄 `#{카드번호} docs: {요약}`) — **digest·`_STEP_INDEX` 갱신을 같은 커밋에 포함** → push → MR (**문서만 변경이면 CI 통과 후 셀프 머지 허용**) — main 직접 push 금지는 docs에도 적용된다.
   - ★**`Closes #N` 금지 — `관련: #{카드번호}` 링크만**(자동 닫힘 — 경위·정본은 /done 7단계).
   - MR 본문이 여러 줄이면 `-d`에 직접 넘기지 말고 파일로 쓴 뒤 `-d "$(cat 파일)"` + **`</dev/null`**(`rules/gitlab-cli.md`), 생성 후 `glab mr list`로 **실제로 생겼는지 재조회**한다(무음 실패는 조회로만 잡힌다).
   - *경로 A는 원본 문서가 이미 main에 있으니 이 커밋 = digest·지도 갱신[+명명 정규화].*
   - 머지 후 변경 요약을 카드 댓글로 — `@{기획자}` 멘션({기획자} = CLAUDE.md에서 실행 시점에 읽는다) "받은 문서 반영됨, docs/ 확인해주세요"
7. **▶ 다음 판단 (위에서부터 처음 맞는 것 하나)**:
   - **기존 요구사항의 변경**이면: 배치로 끝내지 말고 `/change` 로 영향 분석까지 이어가자고 제안하라.
   - **요구사항(STEP 3) 문서**면: **설계(`docs/06_TechnicalDesign`)가 아직 없으면 `/design` 먼저** — 첫 슬라이스 하나로도 /design은 성립하고, 카드 분해는 모듈 경계(=설계 산출물)가 나와야 `모듈:` 라벨을 달 수 있다. **설계가 이미 있으면** `/card docs/03_Requirement/{문서} 분해` (그 요구가 설계 범위를 뒤흔들면 `/design` 재실행 먼저).
   - **디자인 가이드류(여러 화면에 걸치는 문서)면**: 기존 화면·본보기 모듈과 충돌하는지 확인하고, 충돌하면 **소급 반영 카드**(본보기 갱신 포함)를 발행 제안 — 새 화면 작성자가 두 정본 사이에서 혼자 판단하게 두지 마라

## ❌ 금지
- 확인(3번 게이트) 없이 정본 폴더(03_Requirement·05_UIUX 등)를 덮어쓰기
- 받은 문서의 내용을 임의로 요약·수정해서 배치 (원문 그대로, 정규화는 파일명·위치만)
- **STEP 문서를 배치하고 digest·인덱스(5번)를 건너뛰기** — 인덱스가 현실과 어긋나 다음 세션이 진행 상태를 오판한다
