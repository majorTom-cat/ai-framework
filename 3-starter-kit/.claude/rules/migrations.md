# 마이그레이션 규칙

> ★**`paths:` 를 뗐다(2026-08-28)** — 조건부 규칙은 **Read 도구로 열 때만** 걸리고 셸로 읽으면 무음이다(실측: `_reference/rules-loading.md`).
> 이 규칙은 **어기면 스키마가 깨지고 되돌리기 어렵다.** 옛 `paths:` 는 스택 실경로로 치환해야 살아나는 구조라 «치환을 잊으면 조용히 죽는» 함정도 있었다(bnsone #53) — 그 함정까지 함께 사라진다.

- 파일명 = `YYYYMMDD_HHMMSS_설명.<확장자>` (확장자는 프로젝트 마이그레이션 도구 표준 — 킷 도입 시 치환). **초 단위 필수** — 분 단위는 병렬 작업 시 같은 분 충돌이 실제로 난다. 같은 초라면 파일명 사전순이 적용 순서다
- ★**형식은 치환 시점에 도구 기본과 맞춰라** — Prisma `migrate dev`는 구분 `_` 없는 `YYYYMMDDHHMMSS_`로 만든다. 규칙 형식이 도구와 다르면 **생성물이 기존 것보다 앞서 정렬**돼(`0` < `_`) "최신 뒤로"가 조용히 깨진다(bnsone #64·#65·#84 세 번 실측 — 파일럿은 도구 기본을 채택해 무사고).
  **이미 다른 형식으로 굳은 repo면**(머지된 마이그레이션은 불변이라 형식 전환 불가) 도구 생성 **직후 규칙 형식으로 rename**하고(적용 전이면 폴더명만·적용했으면 `_prisma_migrations` 메타도) `ls | sort | tail -3`으로 **내 것이 맨 뒤인지 눈으로** 확인한다.
- ★**기존 스키마에서 마이그레이션을 «뽑아내는» 명령(`prisma migrate diff` 류)의 함정 3개**(2026-08-25 bnsone 실측 — Prisma 예, 명령 이름은 스택 치환): ①**섀도 DB 자리에 실 DB 를 넘기면 그 DB 가 비워진다** — 반드시 별도 빈 DB(매번 DROP/CREATE)를 준다 ②**마이그레이션 폴더는 diff 출력을 본 뒤에 만들어라** — 빈 폴더가 먼저 있으면 도구가 «이미 적용됨»으로 읽어 **빈 스크립트**를 낸다 ③**도구가 붙이는 시각은 UTC** — rename 할 때 현지 시각으로 고치지 마라(순서만 중요하다). 적용한 뒤 rename 하면 체크섬이 어긋나 리셋을 요구한다 — **적용 전에만 rename.**
- ★**호스트에서 마이그레이션 도구를 직접 돌릴 땐 컨테이너 내부 호스트명(`db:5432` 류)을 못 쓴다**(Prisma는 P1012로 죽는다) — 그 실행에만 호스트용 접속 URL을 앞에 붙여라. **실제 값은 프로젝트마다 다르다 — 그 repo 가 정한 곳(CLAUDE.md '실행·테스트' 또는 `.env.example`)이 정본이고, 두 곳에 중복 기재하지 마라**(포트가 바뀌면 갈린다).
- ★**"파일만 만든다"는 옵션(`--create-only` 류)도 DB에 적용될 수 있다** — 생성 직후 적용 이력 테이블(`_prisma_migrations` 등)을 조회해 미적용을 확인하라. 이미 적용됐으면 **폴더를 지우지 말고** 그 상태를 기준으로 진행한다(지우면 이력만 남아 다음 실행이 깨진다).
- **main에 머지된 마이그레이션 파일은 수정·삭제 금지(불변).** 고칠 것도 새 파일로.
- ★**적용 이력을 조회하려는데 `.env` 를 못 읽으면**(도구 권한에 막히는 경우가 있다 — `.env.example` 은 읽혀도 DB명이 실제와 다를 수 있다) **컨테이너에 직접 물어 실물을 확인하라**: `docker compose exec {db서비스} psql -U {user} -l`. 짐작한 DB명으로 조회하면 «미적용»이 아니라 «빈 결과»가 나온다(2026-09-02 bnsone 실측).
- ★**아직 머지 전이라 고칠 수 있는 파일이어도, 이미 로컬에 적용해 놨다면 «고치기»는 파일 수정으로 끝나지 않는다 — 로컬 재적용까지가 한 작업이다.** 파일만 고치면 적용 이력의 체크섬이 어긋나 **다음 카드에서 도구가 리셋을 강제**한다(2026-08-28 실측: /done 리뷰에서 적용된 마이그레이션에 백필을 추가 → 다음 카드에서 Prisma 가 reset 요구. 로컬만 깨졌고 main 은 정상이라 원인 찾는 데 시간을 썼다).
  **리셋은 파괴적이라 사람이 실행한다**(AI 대행 금지 — 위 선언형 충돌과 같다). 리셋 전에 «되돌리는 내용의 새 마이그레이션»으로 풀리는지 먼저 보라.
- 되돌리기는 down이 아니라 "되돌리는 내용의 새 마이그레이션" 추가 (forward-only). 머지커밋 revert는 머지된 마이그레이션 파일을 **지운다**(불변 위반 — `migration-immutable` 잡이 차단) — 절차는 `_reference/revert.md` B로(B는 Prisma 예시 — 경로·역DDL은 스택 것으로 치환).
- **★전역 직렬 자산**(모듈 소유로 못 막는다): 머지는 생성 순서대로 직렬. 내 브랜치가 뒤처진 새 마이그레이션이 main에 들어왔으면 내 것을 최신 뒤로 재생성. (왜·벤더 경고: `_reference/schema-conflicts.md`)
- ★**날짜를 «하루» 단위로 자를 땐 현지 시각(KST) 기준으로 잘라라** — SQL 의 `::date` 캐스팅도, TS 의 `toISOString().slice(0,10)` 도 **UTC** 라 한국 시각 오전 9시 이전이 **전날로 밀린다**. 같은 버그가 TS·SQL 두 층에서 따로 났다(2026-08-24 bnsone 실측).
- ★**제약이 걸린 테이블·enum 을 다시 만드는 마이그레이션은 그 제약의 재생성을 함께 써라** — 겹침 차단(EXCLUDE)·CHECK·유니크를 빠뜨리면 **앱 쪽 검사만 남고 DB 원천 보장이 조용히 사라진다**(bnsone 예약 테이블 실측 — 앱은 멀쩡해 보였다).
- **★착수 공지 = 조건부**(2026-08-31 오너 결정 "2"): 옛 규칙은 «착수 전 팀 채팅 한 줄 공지»를 무조건 요구했는데, **오너가 3연속 「공지 없이」로 답했다** — 규칙과 실행이 갈린 채 누적되면 그 게이트는 무력화되고 옆 게이트까지 형식이 된다. 그래서 **막으려던 것(동시 작업 충돌)을 직접 확인하는 것으로 바꾼다.**
  - 착수 전에 **둘 다** 확인하라: ①`git fetch origin -q` 후 main 의 최신 마이그레이션이 내 base 보다 앞서 있지 않다 ②열린 MR 중 마이그레이션 경로를 건드리는 것이 없다(`glab api "projects/:id/merge_requests?state=opened"` → 각 iid 에 `.../changes`).
  - **둘 다 깨끗하면 공지 없이 착수**하고, **확인 결과를 카드에 한 줄로 남긴다**(무엇을 조회해 무엇이 없었는지 — 이게 공지를 대신하는 기록이다).
  - **하나라도 걸리면, 또는 조회 자체가 실패하면 공지한다**(모르는 상태는 «깨끗»이 아니다). 이때는 멈추고 사용자에게 문구를 건네라.
  - ⚠️**공용 테이블의 이름변경·삭제 공지는 이 완화 대상이 아니다**(아래 줄) — 그건 순서 문제가 아니라 남의 코드를 깨뜨리는 문제다.
- **★선언형 스키마 파일**(Prisma `schema.prisma`·Drizzle 등 한 파일에 여러 모듈)**은 package-lock처럼 동시 편집 충돌 자산**: 충돌 시 양쪽 정의 합친 뒤 도구 검증(`prisma validate`), 잦으면 모듈별 파일 분리. 충돌 뒤 리셋 요구 = 파괴적 작업이라 **사람이 실행**(AI 대행 금지). (실측·상세: `_reference/schema-conflicts.md`)
  - ★**포매터가 그 자산을 통째로 재정렬한다** — `prisma format` 류를 돌리면 **내 파일 하나 고쳤는데 남의 모듈이 diff 에 올라온다**(경계 규칙 위반으로 보인다). **format 뒤 `git diff --numstat` 로 내 파일만 남았는지 확인**하고, 추가·삭제 줄 수가 같은 순수 정렬이면 되돌려라(2026-09-01 bnsone 실측: 남의 모듈 3개).
- 자기 모듈 테이블은 자유(추가 위주). **공용 테이블(users 등)의 이름변경·삭제는 확장→이전→축소 3단계 + 채팅 공지.**
- 스키마 변경 MR에는 해당 모듈 시드(멱등: 있으면 갱신·없으면 생성) 갱신을 같이 포함한다.
  - **새 모듈 시드는 본보기 시드의 게이트 관용구를 그대로 베껴라** — 기본 데이터 밖 **표본(샘플) 데이터는 게이트 변수(예: `SEED_SAMPLE`) 뒤에**. 안 걸면 게이트 검사 잡이 머지 CI에서야 잡는다(bnsone #69 실측 — 로컬은 통과, 머지에서 실패).
