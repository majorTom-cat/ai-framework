# 마이그레이션 규칙

- 파일명 = `YYYYMMDD_HHMMSS_설명.<확장자>` (확장자는 프로젝트 마이그레이션 도구 표준 — 킷 도입 시 치환). **초 단위 필수** — 분 단위는 병렬 작업 시 같은 분 충돌이 실제로 난다. 같은 초라면 파일명 사전순이 적용 순서다
- ★**형식은 치환 시점에 도구 기본과 맞춰라** — Prisma `migrate dev`는 구분 `_` 없는 `YYYYMMDDHHMMSS_`로 만든다. 규칙 형식이 도구와 다르면 **생성물이 기존 것보다 앞서 정렬**돼(`0` < `_`) "최신 뒤로"가 조용히 깨진다(bnsone #64·#65·#84 세 번 실측 — 파일럿은 도구 기본을 채택해 무사고).
  **이미 다른 형식으로 굳은 repo면**(머지된 마이그레이션은 불변이라 형식 전환 불가) 도구 생성 **직후 규칙 형식으로 rename**하고(적용 전이면 폴더명만·적용했으면 `_prisma_migrations` 메타도) `ls | sort | tail -3`으로 **내 것이 맨 뒤인지 눈으로** 확인한다.
- ★**호스트에서 마이그레이션 도구를 직접 돌릴 땐 컨테이너 내부 호스트명(`db:5432` 류)을 못 쓴다**(Prisma는 P1012로 죽는다) — 그 실행에만 호스트용 접속 URL을 앞에 붙여라. **실제 값은 프로젝트마다 다르다 — 그 repo 가 정한 곳(CLAUDE.md '실행·테스트' 또는 `.env.example`)이 정본이고, 두 곳에 중복 기재하지 마라**(포트가 바뀌면 갈린다).
- ★**"파일만 만든다"는 옵션(`--create-only` 류)도 DB에 적용될 수 있다** — 생성 직후 적용 이력 테이블(`_prisma_migrations` 등)을 조회해 미적용을 확인하라. 이미 적용됐으면 **폴더를 지우지 말고** 그 상태를 기준으로 진행한다(지우면 이력만 남아 다음 실행이 깨진다).
- **main에 머지된 마이그레이션 파일은 수정·삭제 금지(불변).** 고칠 것도 새 파일로.
- 되돌리기는 down이 아니라 "되돌리는 내용의 새 마이그레이션" 추가 (forward-only). 머지커밋 revert는 머지된 마이그레이션 파일을 **지운다**(불변 위반 — `migration-immutable` 잡이 차단) — 절차는 `_reference/revert.md` B로(B는 Prisma 예시 — 경로·역DDL은 스택 것으로 치환).
- **★전역 직렬 자산**(모듈 소유로 못 막는다): 만들 카드는 착수 전 팀 채팅 한 줄 공지, 머지는 생성 순서대로 직렬. 내 브랜치가 뒤처진 새 마이그레이션이 main에 들어왔으면 내 것을 최신 뒤로 재생성. (왜·벤더 경고: `_reference/schema-conflicts.md`)
- **★선언형 스키마 파일**(Prisma `schema.prisma`·Drizzle 등 한 파일에 여러 모듈)**은 package-lock처럼 동시 편집 충돌 자산**: 충돌 시 양쪽 정의 합친 뒤 도구 검증(`prisma validate`), 잦으면 모듈별 파일 분리. 충돌 뒤 리셋 요구 = 파괴적 작업이라 **사람이 실행**(AI 대행 금지). (실측·상세: `_reference/schema-conflicts.md`)
- 자기 모듈 테이블은 자유(추가 위주). **공용 테이블(users 등)의 이름변경·삭제는 확장→이전→축소 3단계 + 채팅 공지.**
- 스키마 변경 MR에는 해당 모듈 시드(멱등: 있으면 갱신·없으면 생성) 갱신을 같이 포함한다.
  - **새 모듈 시드는 본보기 시드의 게이트 관용구를 그대로 베껴라** — 기본 데이터 밖 **표본(샘플) 데이터는 게이트 변수(예: `SEED_SAMPLE`) 뒤에**. 안 걸면 게이트 검사 잡이 머지 CI에서야 잡는다(bnsone #69 실측 — 로컬은 통과, 머지에서 실패).
