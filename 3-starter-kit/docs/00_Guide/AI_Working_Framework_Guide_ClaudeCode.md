# 문서 올리는 두 가지 방법 — 웹 or Claude Code (기획·디자인 담당자용)

> **대상:** 기획·디자인 등 문서(요구사항·시안)를 만들어 올리는 분. **코드는 안 건드립니다.**
> 두 방법 다 **당신이 `docs/`를 직접 소유**하는 건 똑같아요(개발자 안 거침). **문(門)만 다릅니다** — 편한 걸 고르세요.
> 📚 **별책 4권 중 1권** — 전체 지도: [README](/README.md) · 형제: [GitLab 실전 가이드](AI_Working_Framework_Guide_GitLab.md)(웹 조작·카드·검수의 정본) · [개발자 ONBOARDING](ONBOARDING.md) · [공통 개발자 가이드](AI_Working_Framework_Guide_Leader.md)

## 어느 걸로 할까?

| | 🌐 웹으로 (설치 0) | 🤖 Claude Code (AI 도움) |
| --- | --- | --- |
| 준비 | **없음** — 브라우저만 (**토큰도 불필요**) | 처음 1회 설치·연결(~15분, **혼자 가능**) |
| 좋은 점 | 지금 바로 시작 | **스킬 하나(`/docs`)로 정리+올리기 한 번에** + AI 도움 |

- **🤖 Claude Code로** 하려면 → 아래 계속.

# 🤖 Claude Code로 하기

## 0. 30초 그림
- 이 팀은 **일을 "스킬"로 합니다** — 손으로 git(커밋·push — "저장·업로드"에 해당하는 개발 도구 조작) 하지 않아요. 당신은 **스킬만 부르면**, 스킬이 정리부터 올리기까지 다 합니다.
- 문서 올리기 = **`/docs`** 한 번 → 정리 + 저장 + 업로드까지 자동. 올라간 문서는 자동 검사(CI) 통과 후 팀 공식 문서로 **합쳐지는 것까지 스킬이 마무리**합니다 — 당신이 더 할 일은 없어요.
- **폴더 구조 그대로** 올라가고, "요구사항을 표로 정리해줘" 같은 부탁도 됩니다.
- **당신이 만지는 건 `docs/` 폴더입니다** — AI에게 "docs만"이라는 규칙이 걸려 있어서, `/docs`·`/card`로 일하는 한 코드 쪽으로 갈 일이 없어요. (기술적으로 코드를 100% 못 열게 막는 장치는 없습니다 — 대신 **틀려도 되돌릴 수 있게** 되어 있어요: 올리기 전 미리보기, 자동 검사(CI), 그리고 잘못 올라가도 한 번에 되돌리기.)
- **이미 claude.ai를 써봤다면 거의 다 아는 거예요** — "내 폴더에서 일하는 Claude"입니다. 단, **작업은 `/docs` 같은 스킬로** 진행하고, AI가 매번 응답 끝에 **"▶ 다음: …"** 으로 다음에 할 걸 알려주니 **고르기만** 하면 돼요 (자유롭게 타이핑하는 건 *질문하거나 고칠 때만*).

## 잠깐 — "터미널"이 뭐고 어떻게 켜요? (안 무섭습니다)

Claude Code는 **"터미널"** 이라는 창에서 돌아갑니다. 명령어를 외울 필요는 **전혀 없고**, 아래처럼 **창만 열면** 돼요. 둘 중 편한 걸로:

**방법 A — 터미널(PowerShell) 켜기 (가장 간단)**
1. 화면 **왼쪽 아래 ⊞ (Windows 로고)** 를 클릭
2. 그대로 키보드로 **`powershell`** 이라고 타이핑
3. 뜨는 **"Windows PowerShell"** 을 클릭 → **파란(또는 검은) 창**이 나오면 그게 터미널이에요.
> 이 가이드에서 **"터미널을 켜라 / PowerShell 열고"** 는 전부 이 창을 말합니다. 창 안에 글자를 붙여넣고 Enter만 치면 돼요.

**방법 B — VS Code (채팅창처럼 생겨 더 친숙, 검은 창이 부담되면)**
1. VS Code 설치(https://code.visualstudio.com) → 실행
2. `Ctrl+Shift+X` → **"Claude Code"** 검색 → 설치
3. 우상단 **✱** 아이콘 → 로그인 → **오른쪽 채팅창**에 그냥 말하면 됩니다 (claude.ai랑 똑같이 생겼어요)
> **둘 다 같은 Claude**입니다 — `/docs` 같은 **스킬도 VS Code에서 똑같이 됩니다.** A(터미널)로 시작하고, 익숙해지면 B로 갈아타도 돼요.

> 아래 세팅·사용법은 **방법 A(터미널)** 기준으로 씁니다.

## 1. 처음 한 번만 — 혼자 세팅 (~20분)
> 처음 딱 한 번입니다. 아래 **6개를 순서대로**. 막히면 그 줄을 **그대로 복사→붙여넣기** 하세요.

**① Claude Code 설치** — **위에서 연 터미널(PowerShell)** 에 아래 한 줄을 붙여넣고 Enter:
```
irm https://claude.ai/install.ps1 | iex
```
끝나면 **터미널을 껐다 다시 켭니다.**

**② Claude에 로그인** — 터미널에 `claude` 라고 입력하고 Enter. 처음이면 로그인이 시작돼요:
- **브라우저가 자동으로 열리면** → 평소 쓰던 **Claude 계정으로 로그인** → 저절로 터미널로 돌아오면 끝. (계정이 없으면 → 공통 개발자에게 좌석 요청)
- **자동으로 안 열리면** → 터미널 안내대로 **`c` 키**를 누르면 URL이 복사돼요 → 브라우저 주소창에 붙여넣고 로그인.
- **로그인했더니 브라우저에 "코드"가 뜨면** → 그 코드를 복사해서 **터미널의 `Paste code here` 자리에 붙여넣고** Enter. (Windows에선 종종 이 방식이에요 — 정상입니다.)

  → "로그인됨" 표시가 나오면 성공. 확인했으면 `/exit` 로 잠깐 빠져나옵니다.

**③ Git 설치** (문서를 주고받는 도구) — https://git-scm.com/download/win 에서 받아 설치. 설치 창은 **계속 "Next"**(기본값 그대로) 누르면 됩니다.

**④ 프로젝트 받기** — 터미널에 아래를 한 줄씩:
```
cd $env:USERPROFILE\Documents
git clone <프로젝트 clone URL>
```
(clone URL은 공통 개발자가 알려줍니다. 직접 찾으려면: GitLab 프로젝트 페이지 → 파란 **Code** 버튼 → **Clone with HTTPS** 주소 복사)
→ **로그인 창이 뜨면 평소 쓰던 GitLab 계정으로 로그인**하면 됩니다. (한 번만 하면 저장돼요. **대개 여기서 끝 — 토큰 없이 됩니다.**)

> 🔑 **만약 비밀번호 말고 "토큰(Access Token)"을 달라고 하면**(2단계 인증을 켰거나 회사 GitLab 설정 때문) — 그때만 아래로:
> `<사내GitLab주소>` 로그인 → 우상단 프로필 사진 → **Edit profile → Access Tokens** → 이름 아무거나 · 만료일 넉넉히(예: 1년 뒤) · scope(권한 범위)에서 **`api`** 체크 → **Create** → 나온 **토큰 복사** → clone 창의 **비밀번호 자리에 붙여넣기**.

> 잘됐는지 확인: `Documents` 안에 프로젝트 폴더가 생겼으면 성공.

⑤ **glab 설치·연결 (5분)** — `/card`·`/docs`가 GitLab과 대화할 때 쓰는 도구라 **없으면 스킬이 실패합니다**:
```powershell
winget install glab.glab
glab auth login --hostname <사내GitLab주소>
```
→ 토큰을 물으면 ④의 토큰 방법으로 만든 토큰을 붙여넣습니다. 막히면 AI에게 "glab 설치 도와줘".

⑥ **(Windows) 시스템 환경변수 `CLAUDE_CODE_GIT_BASH_PATH`** = `C:\Program Files\Git\bin\bash.exe` 등록 — 팀 안전장치(훅)가 이게 없으면 **조용히 안 돕니다** (Windows 검색 → "시스템 환경 변수 편집" → 새로 만들기. 막히면 AI에게 "환경변수 등록 도와줘").

## 2. 매번 쓸 땐 — 스킬 하나면 끝
1. **Claude 켜기** — 터미널(방법 A)에서 폴더로 가 `claude`, 또는 VS Code(방법 B) 채팅창:
   ```
   cd $env:USERPROFILE\Documents\<프로젝트>
   claude
   ```
   > `<프로젝트>`는 §1-④ clone 때 `Documents` 안에 생긴 **폴더 이름**으로 바꿔 칩니다(예: `our-app`).
   > 로그인은 처음 한 번(위 ②)만 — 이제부턴 바로 켜집니다.
   > **맨 처음 켤 때 "이 저장소를 신뢰합니까?" 물음이 뜨면 → 수락** — 이걸 해야 팀 스킬·안전장치가 켜집니다.
2. **스킬을 부른다** (이게 이 팀의 방식 — 손으로 git 하지 않습니다):
   - 문서를 올리거나 정리 → **`/docs`**
   - 할 일·요구를 등록 → **`/card`**
   - 뭐부터일지 막막하면 → **`/start`**
3. **끝.** 스킬이 **정리 + 저장 + 업로드 + 반영(합치기)까지 한 번에** 하고 "올렸습니다"라고 알려줍니다.
   → **당신이 "커밋"이니 "push"니 신경 쓸 게 없어요.** 스킬이 다 합니다.

## 3. 당신이 쓰는 스킬은 3개뿐 (나머진 개발자용)
| 스킬 | 언제 | 예시 | 부르고 나서 |
| --- | --- | --- | --- |
| **`/docs`** | 만든 문서를 docs에 정리·업로드 | `/docs C:\받은문서\기획` | 폴더/파일 경로를 뒤에 → 배치안 확인 → **올리기까지 자동** |
| **`/card`** | 할 일·요구를 카드로 등록 | `/card 게시판 검색 추가` | 문서 경로를 주면 여러 카드로 쪼개 초안→확인→등록 |
| **`/start`** | 뭐부터 할지 막막할 때 | `/start` | 상태 진단 + 다음 한 걸음 안내 |

> ⛔ `/dev`·`/fix`·`/done`·`/module`·`/ui`는 **개발자용**(코드). 실수로 쳐도 AI가 "그건 개발자용이에요"라고 안내합니다 — 혹시 그냥 진행되더라도 **올리기 전에 미리보기로 물어보니** 거기서 "아니오" 하면 됩니다.

### 3-1. 카드 등록, 실제로 이렇게 흘러갑니다

**카드 = 이 팀의 할 일 딱지** (GitLab 이슈 — 요청·버그·개선 전부 카드 한 장씩). `/card` 뒤에 한 줄만 붙이면 AI가 양식을 채워 등록해줘요:

```
당신:  /card 휴가신청 화면에 반차 옵션 추가
AI:    (유사 카드 중복 확인 → 양식을 채우고, 스스로 못 채우는 칸만 물어봅니다)
       "검수는 누구로 할까요?"
당신:  기획자B
AI:    등록했습니다 — #23 (담당: 휴가 모듈 개발자 · 검수: @기획자B) ▶ 다음: …
```

- 모든 칸이 채워지면 AI가 **등록 직전에 3~5줄 요약을 보여주고, OK 하면 등록**해 번호를 알려줘요(팀 규칙 '남기기 전 미리보기' — 추가 질문 없이 요약 확인 한 번이면 됩니다).
- 등록된 카드는 GitLab 웹 **Plan → Issue boards**(카드판)에서 누구나 볼 수 있어요.
- **검수 카드를 받았거나 시안을 고를 차례**가 되면 — 그건 웹에서 합니다: [GitLab 가이드 §5 검수](AI_Working_Framework_Guide_GitLab.md#5-검수--배정받은-사람이-확인하고-완료-처리하는-법) · [§5-1 시안 고르기](AI_Working_Framework_Guide_GitLab.md#5-1-화면-시안--보고-고르기-기획결정권자)
- 카드가 뭔지·양식 칸을 잘 쓰는 법·담당자 지정·닫기 같은 조작의 **정본은 [GitLab 실전 가이드 §2](AI_Working_Framework_Guide_GitLab.md#2-카드이슈-등록하기--누구나-1분)와 [§2-2 조작 치트시트](AI_Working_Framework_Guide_GitLab.md#2-2-카드-화면-조작-치트시트--gitlab이-처음이면-여기부터)** — 웹 화면 기준 설명이지만 개념은 같아요.

## 4. 자주 하는 일 — §3에 없는 팁만
- **뭉치(폴더·zip) 올리기 팁**: zip은 자동으로 풀어 배치하고 폴더 구조는 그대로 보존. 경로에 공백이 있으면 따옴표(`/docs "C:\받은 문서\기획"`)
- **문서 내용 고치기**: 간단한 수정은 **웹이 제일 빠릅니다**([GitLab 가이드 §1](AI_Working_Framework_Guide_GitLab.md#1-프로젝트-맨-처음--요구사항기획시안-문서를-올린다-시작-시-1회)의 Edit·Web IDE). Claude Code에서 하려면 "○○ 문서 이렇게 고쳐줘"(내 컴퓨터의 파일이 고쳐짐) → 이어서 `/docs`(그 수정을 서버로 올림)로 반영.
- **확인하고 싶을 때**: "지금 뭐가 바뀌었어?" / "이거 올려도 안전해?"

## 5. 안심하세요 (비개발자 전용)
- **git·브랜치·커밋·push 몰라도 됩니다** — `/docs`·`/card` 스킬이 저장·업로드까지 다 합니다. 당신은 **스킬만 부르면** 돼요.
- **실수해도 되돌릴 수 있습니다 — 그게 핵심이에요.** 이 팀엔 "코드는 절대 못 열린다" 같은 자물쇠는 없어요(쓰는 GitLab 버전이 폴더별 잠금을 지원하지 않습니다 — 배경: [ADR-0001](/docs/adr/0001-비개발자-docs-직접푸시.md)). 대신 **틀린 걸 되돌리는 길**이 잘 나 있습니다:
  - 올리기 전에 스킬이 **항상** "이렇게 할게요"(미리보기)를 먼저 보여줘요 — 이상하면 거기서 "아니오".
  - 올라간 뒤에도 **자동 검사(CI)** 가 한 번 더 보고, `docs/` 밖이 바뀌면 기록이 남습니다.
  - 그래도 잘못 들어갔으면 개발팀이 **한 번에 되돌립니다**(revert). 아무도 혼내지 않아요 — 되돌리기가 정상 절차입니다.
- **"docs만" 규칙은 규율이지 자물쇠가 아닙니다** — 그래서 `/docs`·`/card`로만 일하면 됩니다. 걱정되면 그냥 물어보세요: "이거 코드 건드리는 거야?"
- **누가 같은 파일을 동시에 고쳤다(충돌)** — AI가 "충돌 났어요" 하고 같이 풀어줍니다.

## 6. 안 될 때
- `claude doctor` (자가 진단)를 쳐보고, 그래도 막히면 개발팀에 이 문서와 함께 물어보세요.
- 검은 터미널이 부담되면 → **VS Code(위 '방법 B')** 로 채팅창처럼 쓸 수 있어요 (스킬도 그대로 됩니다).
