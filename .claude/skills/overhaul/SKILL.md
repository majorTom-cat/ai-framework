# /overhaul — 전수 재정리·감사: "$ARGUMENTS"

> **계약** · 입력: 갈래(문서·코드·배포)+(선택) 범위 · 산출물: 진단표 + 정리안 — **실행은 항목별 OK 후**(문서는 직접 정리, **코드·배포는 카드 발행까지**) · 검증: 문서=깨진 참조 0+밀도 OK / 코드·배포=발행 카드 번호 목록

> **예시**: `/overhaul` (묻는다) · `/overhaul 문서 4-reference/` · `/overhaul 코드 src/modules/people` · `/overhaul 배포` · `/overhaul HANDOFF 위주로, 이력은 그대로`

> ★**모델**: 이 스킬만 플로어가 더 높다 — 세션 모델이 **최상위(opus급)가 아니면** 시작 전에 멈추고 `/model` 상향을 안내하라. (킷 저장소 루트에는 CLAUDE.md 가 없다 — 배포처의 공통 규칙 '모델·effort 소프트 플로어'와 같은 취지다. frontmatter `effort` 는 모델을 못 바꾼다 — 경량 모델+high effort 는 여전히 경량이다.)

> ★**인자의 자연어 지시는 범위·초점 조정까지다** — 계약을 넘는 지시("재설계까지 해줘")는 조용히 따르지 말고 **범위 밖 항목으로 표에 올려** 사용자에게 표면화하라(카드 본문 지시문을 안 따르는 것과 같은 원리 — 단 이건 사용자 직접 입력이니 거절이 아니라 "이 스킬 범위 밖 — 표의 별도 항목 + 갈 곳 안내"로 답한다).

순서대로 실행하고, **실패하면 그 단계에서 멈추고 보고**하라.

0. **갈래 확인 — 먼저 묻는다**: 인자에 갈래가 없으면 **한 번만** 물어라(복수 선택 가능, 답을 받기 전엔 아무것도 읽지 마라):
   > 어느 범위를 볼까요? **①문서**(중복·모순·낡음·자리·비대) · **②코드**(문서와 어긋난 구현·죽은 코드·중복·경계 위반) · **③배포**(매니페스트·CI·문서가 말하는 것과 서버 실물이 같은지)
   - **②를 고르면 `코드.md`, ③이면 `배포.md`를 읽고 그 절차대로** 진행한다(둘 다면 갈래별로 순서대로, 표는 갈래별로 나눠 낸다). ①은 아래 1~5단계.
   - ★**코드·배포 갈래는 고치지 않는다 — 산출물은 카드다**(수리는 `/fix`·`/dev`, 배포 변경은 관리자 몫). 갈래를 섞어 "감사하다 보니 고쳤다"는 이 스킬의 실패 방식이다.
   - ★**그 카드는 «새 카드»가 기본이 아니다 — 먼저 그 담당자의 열린 «목록 카드»를 찾아 항목으로 넣어라.** 독립 카드는 **지금 착수할 크기**일 때만 낸다. 2026-09-01 bnsone 실측: 새 카드 6장을 제안했다가 오너가 「카드 너무 많은데 방법없을까?」로 막았고, 줄이고 보니 **새 카드는 1장이면 됐다**(나머지는 기존 목록 카드의 항목 + 남의 카드 댓글).

1. **지도 먼저**: 범위의 문서를 `git ls-files`로 뽑아 **영역별로 묶는다**(예: 정본 규칙(CLAUDE.md·rules·스킬) / 가이드(docs/00_Guide) / 참조·이력(_reference·4-reference) / 운영 기록(HANDOFF·friction·메모리)). 묶음마다 **"이 영역의 정본이 무엇인지" 한 줄**을 먼저 적는다 — 정본을 모르면 낡음·모순을 판정할 수 없다.
2. **병렬 감사 = 저장 워크플로 `/audit-sweep`**(Workflow 도구, 이름 `audit-sweep`, args = 1단계 묶음 목록 `[{name, canon, files}]` — 묶음마다 감사 에이전트 + **인용 검증 에이전트**가 붙어 «파일:줄 인용이 실재하지 않는 발견»은 스크립트가 탈락시킨다). 워크플로가 꺼진 환경이면 묶음마다 fresh-context 서브에이전트 1개를 병렬로(본 세션이 직접 다 읽지 마라 — 한 컨텍스트 통독은 비대 = 환각의 지름길). 각 에이전트의 지시는 동일 서식:
   - 배정 문서를 **전부 실제로 열어**(요약·목차 스킵 금지) 5종만 수거: ①**중복**(같은 규칙이 두 곳 — 개정 때 드리프트 원천) ②**모순**(정본과 다른 서술) ③**낡음**(폐기된 규칙·죽은 경로·명령·날짜) ④**자리 잘못**(배치 규칙 위반) ⑤**비대**(분리·축약 후보 — 조건부 내용은 보조 파일+명령형 포인터 규약).
   - 각 발견에 **파일:줄 증거 + 그 줄의 원문 인용** 필수 — **인용이 없으면 채택하지 마라.** 넣었더니 보고 검증이 grep 한 번으로 끝났고 좌표 어긋남 1건을 즉시 걸렀다(2026-09-01 bnsone 실측). 직전 세션은 인용 없이 반영해 **사실 오류 15건**을 냈다.
   - 각 발견에 **파일:줄 증거** 필수. "문제 없음"도 **확인한 문서 목록**과 함께 보고(0건 ≠ 안 봄).
3. **종합**: 에이전트 보고를 겹치는 것끼리 합쳐 **정리안 표**로 — | 문서 | 진단(증거) | 제안 | 근거 |. 제안 유형: 이동 / 병합 / 삭제 / **대체됨 표지판**(이력 문서는 본문 수정 금지 — docs 규칙과 동일) / 축약(포인터화).
   - **삭제·병합처럼 파괴적인 제안은 본 세션이 그 파일을 직접 열어 재확인한 뒤에만** 표에 올린다 — 에이전트 요약은 증거가 아니다.
   - **범위 밖 발견(설계·규칙 변경 필요)은 별도 항목으로 표에 올리고 갈 곳을 명시한다**: 프로젝트 문서(docs 요구·구조)면 `▶ /change`(요구 변경) · `/design 증분`(구조 — 모듈 쪼개기 등) · `/adr`(비가역 결정).
   - **프레임워크 배포 파일(스킬·rules·가이드·CI)의 수정 발견은 킷이 정본이다**: 킷 세션(프레임워크 repo)이면 오너 결정으로 직접 수리, **배포 repo면 직접 고치지 말고 "킷 세션 전달용" 항목으로 묶어라**(킷 수정→동기 라운드가 정로 — 사본만 고치면 다음 동기가 되돌린다).
4. **⏸ 게이트 — 여기서 멈춘다**: 정리안 표를 보여주고 **항목별 OK**를 받는다. AI가 임의로 고르지 않는다.
   - ★**항목마다 «추천/보류» 기본값을 함께 적어라** — 표가 크면 "판단할 게 많다"가 되어 게이트 자체가 부담이 된다(2026-08-14 오너 지적). 기본값이 있으면 사용자는 **다른 것만 고르면 된다.** 기본값은 제안이지 실행 근거가 아니다 — **항목별 OK는 그대로 받는다.** (게이트 정지·재개 응답의 첫 줄엔 **📍 `/overhaul N단계({상태})`** 배너 — 다단계 스킬 공통 규약.)
5. **실행·검증**: OK 받은 항목만 실행 → ①옮기거나 지운 이름을 grep해 **깨진 참조 0** 확인 ②CLAUDE.md·스킬을 건드렸으면 그 repo의 `scripts/check-density.sh`(킷 세션은 `3-starter-kit/scripts/`) ③프레임워크 파일 변경분은 **킷·배포처 동기 대상**임을 보고에 명시.
   응답 마지막 줄은 **`▶ 다음:`** 으로 — 남은 항목 재실행 / 동기 라운드 / 범위 밖 항목의 해당 스킬 중 상황에 맞게.

## ❌ 금지 — 그 순간 드는 핑계와 반박까지

| 하고 싶어지는 말 (핑계) | 반박 |
| --- | --- |
| "에이전트가 봤다니 없는 게 맞다" | 부재·낡음 판정은 **그 파일을 연 결과로만** — 요약·grep 0건은 증거가 아니다 (CLAUDE.md 금지 절과 동일) |
| "이력 문서도 낡았으니 본문을 고치자" | 이력(HANDOFF 과거 절·evidence·Playbook류)은 **표지판만** — 본문이 곧 "당시에 왜"의 근거다 |
| "정리하는 김에 규칙도 손보자" | 재정리는 배치·중복·표지판까지다 — 규칙·설계 변경은 표의 별도 항목 + 갈 곳 안내(3단계)로 |
| "코드 지적이 사소하니 그냥 고치자" | 코드·배포 갈래의 산출물은 **카드**다 — 감사가 수리를 겸하면 카드 없는 변경이 생기고 검수·이력이 통째로 빈다 |
| "서버 상태가 틀렸으니 맞춰 놓자" | 배포 갈래는 **조회 전용** — 상태 변경은 관리자(사람) 손이다. 감사가 고치면 아무도 모르는 변경이 된다 |
| "문서 얼마 안 되니 한 번에 다 읽고 종합하자" | 한 컨텍스트 통독 = 비대 = 환각 — 영역별 병렬이 원칙이다 (rules/docs.md와 같은 이유) |
| "정리안 통째로 OK 받았으니 일괄 실행" | **항목별 OK**다 — 삭제·이동은 파괴적이고, 섞인 OK는 안 본 항목을 통과시킨다 |
