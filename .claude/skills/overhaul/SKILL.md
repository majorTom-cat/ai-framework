# /overhaul — 문서 전수 재정리: "$ARGUMENTS"

> **계약** · 입력: (선택) 범위 경로 · 산출물: 문서 진단표 + 정리안(이동·병합·삭제·표지판·축약) — **실행은 항목별 OK 후** · 검증: 정리 후 깨진 참조 0 + (킷 파일이면) 밀도 OK

1. **모델 확인(소프트 플로어)** — 세션 모델이 최상위(opus급)가 아니면 **시작 전에 보고**하고 올릴지 물어라. 전 문서 횡단 판정은 모델 체급을 탄다. (frontmatter `effort`는 모델을 못 바꾼다 — 경량 모델+high effort는 여전히 경량이다.)
2. **지도 먼저**: 범위의 문서를 `git ls-files`로 뽑아 **영역별로 묶는다**(예: 정본 규칙(CLAUDE.md·rules·스킬) / 가이드(docs/00_Guide) / 참조·이력(_reference·4-reference) / 운영 기록(HANDOFF·friction·메모리)). 묶음마다 **"이 영역의 정본이 무엇인지"를 먼저 한 줄로** 적는다 — 정본을 모르면 낡음·모순을 판정할 수 없다.
3. **병렬 감사** — 묶음마다 **fresh-context 서브에이전트 1개를 병렬로**(본 세션이 직접 다 읽지 마라 — 한 컨텍스트 통독은 비대 = 환각의 지름길). 각 에이전트의 지시는 동일 서식:
   - 배정 문서를 **전부 실제로 열어**(요약·목차 스킵 금지) 다음 5종만 수거: ①**중복**(같은 규칙이 두 곳 — 개정 때 드리프트 원천) ②**모순**(정본과 다른 서술) ③**낡음**(폐기된 규칙·죽은 경로·명령·날짜) ④**자리 잘못**(배치 규칙 위반 — 정본에 있을 것이 참조에, 개인 값이 팀 문서에) ⑤**비대**(분리·축약 후보 — 조건부 내용은 보조 파일+명령형 포인터 규약).
   - 각 발견에 **파일:줄 증거** 필수. "문제 없음"도 **확인한 문서 목록**과 함께 보고(0건 ≠ 안 봄).
4. **종합**: 에이전트 보고를 겹치는 것끼리 합쳐 **정리안 표**로 — | 문서 | 진단(증거) | 제안 | 근거 |. 제안 유형: 이동 / 병합 / 삭제 / **대체됨 표지판**(이력 문서는 본문 수정 금지 — docs 규칙과 동일) / 축약(포인터화). **에이전트 보고만 믿고 판정하지 마라** — 삭제·병합처럼 파괴적인 제안은 본 세션이 그 파일을 직접 열어 재확인 후 표에 올린다.
5. **⏸ 게이트 — 여기서 멈춘다**: 정리안 표를 보여주고 **OK 받은 항목만** 실행. 실행 후 ①옮기거나 지운 이름을 grep해 **깨진 참조 0** 확인 ②킷(3-starter-kit) 파일을 건드렸으면 `bash 3-starter-kit/scripts/check-density.sh` ③킷 파일 변경분은 배포처 동기 대상임을 보고에 명시.

## ❌ 금지
- **에이전트 요약만으로 "없다·낡았다" 판정** — 부재·낡음 주장은 그 파일을 연 결과로만 (CLAUDE.md 금지 절과 동일)
- 이력 문서(HANDOFF 과거 절·evidence·Playbook류) **본문 수정** — 표지판만
- OK 없이 삭제·이동 실행 · 한 에이전트에게 전 영역 통독 배정
- 정리하는 김에 **내용 개정**(규칙 바꾸기)까지 하기 — 재정리는 배치·중복·표지판까지다. 규칙 변경이 필요하면 별도 항목으로 표에 적고 오너 결정을 받아라
