# /overhaul 갈래 C — 배포·서버 실물 감사 (0단계에서 "배포"를 고른 뒤 읽는다)

> **정본**: 저장소의 매니페스트·CI 정의·인프라 문서가 기준이고, **서버 실물은 대조 대상**이다. 어긋나면 어느 쪽이 사실인지 표에 적는다.
> ⚠️⚠️ **조회 전용 갈래다.** `apply`·`patch`·`delete`·`scale`·`restart`·시크릿 변경 등 **상태를 바꾸는 명령은 어떤 이유로도 실행하지 마라** — 관리자(사람) 몫이고, 감사 세션이 고치면 아무도 모르는 변경이 된다. 산출물은 진단표와 **카드**뿐.
> 전제: 사내 서버는 VPN 선행(`vpnon`) — 안 되면 그 자리에서 멈추고 보고. 클러스터 조회는 `ssh <서버> kubectl get ...` 형태(로컬에 kubectl이 없어도 된다).
> ★**절차 근거는 실측**: 2026-08-19 bnsone 첫 전수 감사에서 실제로 나온 것만 아래에 남겼다(최상위 발견이 **CI 변수 마스킹 꺼짐**이었다 — 코드가 아니라 설정에서 나왔다).

## 대조 6쌍 — 묶음마다 fresh-context 서브에이전트(병렬)
1. **매니페스트 ↔ 실물 리소스**: repo의 `k8s/`(배포 디렉터리)에 정의된 Deployment·CronJob·Service·Ingress·ConfigMap·Secret **이름과 개수**를 실물 `kubectl get -o name`과 대조. **정의에만 있는 것**(배포 안 됨)과 **실물에만 있는 것**(손으로 만든 유령)을 양방향으로.
2. **CI 권한(ci-rbac) ↔ 매니페스트가 요구하는 리소스 유형**: 새 유형이 추가됐는데 배포 잡 권한(Role/RoleBinding)이 그 유형을 못 다루면 **배포가 연쇄 실패한다**(2026-08-13 실사고 — CronJob 추가·권한 누락). 매니페스트의 `kind` 집합 ⊆ rbac의 `resources` 확인. 반대로 **권한 과다**(시크릿 create/update까지)도 적어라 — 실사용 근거가 없으면 축소 후보.
3. **자격증명 노출**: `glab api "projects/:id/variables"` 로 CI 변수의 `masked`·`protected` 를 전수 확인하고, **누가 볼 수 있는지**를 멤버 권한(`projects/:id/members` — Maintainer 이상은 평문 열람 가능)과 함께 판정한다. 문서·시드·안내문에 평문 비밀번호가 있는지도(`grep`) 함께. ★**발견을 적을 때 값 자체를 옮기지 마라** — 변수 이름·위치·조치만.
4. **파이프라인 정의 ↔ 실제 실행**: 최근 20~30건(`glab api "projects/:id/pipelines?ref=main"`)에서 **상시 실패·상시 건너뜀 잡**을 찾는다 — 상시 실패는 경보를 마비시켜 진짜 사고를 가린다(8-19 실측: `tamper-check`가 우리 표준 절차를 실패 조건으로 판정해 23건 중 14건 실패, 아무도 안 보게 됐다).
   `allow_failure` 뒤에 숨은 실패, 오래 `manual`로 방치된 잡, **어느 잡에서도 안 돌아가는 테스트 스크립트**도 표적. 낭비(문서만 바뀐 머지에 전량 실행 등)는 별도 줄로.
5. **운영 안전장치 유무**: 롤백 레버(`rollout undo` 경로가 있는가, 없으면 유일 경로와 소요 시간을 적어라) · 기동 예산(`startupProbe` 없이 liveness 예산 안에서 마이그레이션·시드를 끝내야 하는 구조인가) · 백업(정의된 백업이 실제로 도는가 — ADR·문서가 약속한 것과 대조) · 외부 `:latest` 이미지 의존(재현성 없음).
6. **문서 서술 ↔ 실물**: 가이드·README·HANDOFF가 말하는 도메인·URL·계정·경로·**토큰 만료일**이 지금도 사실인지(`curl -sI`로 응답 코드까지, 추측 금지). **배포된 버전이 최신인지**도 여기서(`/api/health` 등 sha 노출 경로 ↔ main 최신 커밋). 사람이 할 일로 적힌 절차가 실제로는 자동인지도(반대도).

각 발견에 **증거(명령 + 출력 요지 한 줄)** 필수. "일치함"도 **대조한 항목 목록**과 함께 보고한다(0건 ≠ 안 봄).

## 종합표 → ⏸ 게이트 → 카드
| 대조쌍 | 진단(증거) | 어느 쪽이 사실인가 | 제안 | 사람 손 필요? |
- **사람 손이 필요한 항목**(관리자 `apply`·시크릿 교체·토큰 재발급·권한 부여·GitLab 설정 화면 클릭)은 별도 묶음으로 **무엇을·어디서·어떤 명령으로**까지 그대로 적는다 — 그게 이 감사의 실제 산출물이다.
- 항목별 OK 후 `/card` 발행(인프라 카드는 화면이 없으니 **셀프 완료 경로** — `/done` 8단계). 여러 건이면 갈래 B와 같은 **추적 카드**(체크박스+증거 인라인) 형태로. 토큰 만료처럼 **기한이 있는 것은 카드 제목에 날짜**를 넣는다.
