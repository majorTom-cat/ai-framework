> **예시**: `/todo` (킷 세션 시작 브리핑)

> ★**이 스킬은 «킷 저장소 세션» 전용이다.** 킷 원격은 GitHub 이고 카드는 사내 GitLab 의 bnsone·파일럿에만 있으므로, 아래 조회는 **`-R` 로 저장소를 못박는다.** 배포처(bnsone·파일럿) 세션에서 쓰는 `/todo` 는 `3-starter-kit/.claude/skills/todo/` 쪽이 정본이고 **이 파일은 그 사본이 아니다** — 동기 대상이 아니다(`AI-CONTEXT.md` §3).

# 현재 상태 (자동 조회됨)

내 담당 카드 — bnsone:
!`glab issue list --assignee=@me -R gitlab.bns.co.kr/bnsone/bnsone 2>&1 | head -25`

내 담당 카드 — 파일럿:
!`glab issue list --assignee=@me -R gitlab.bns.co.kr/yskim/ai-framework-pilot 2>&1 | head -15`

내게 온 To-Do·멘션:
!`glab todo list -P 100 -R gitlab.bns.co.kr/bnsone/bnsone 2>&1 | head -40`

킷 저장소 상태:
!`git status --short --branch 2>&1 | head -10`

# 할 일

★★**잘려도 이 둘은 지켜라** ①**각 선택지는 «무엇이 달라지나»를 한 줄로 적는다 — 내부 분류명 단독 금지** ②**착수 결정은 사용자가 한다 — 네가 골라서 시작하지 마라.**

**1. 킷 마찰 확인** — 안 닫힌 줄을 세라:
`grep -E '^[0-9]{4}-' 3-starter-kit/docs/friction.md | grep -v '\[닫힘:'`
- 결과가 있으면 **「안 닫힌 줄 {N}건 — 가장 오래된 {날짜}」** 한 줄과 선택지 하나를 올려라. **킷 개선은 카드가 아니다** — friction 한 줄 + 커밋으로 그 자리에서 고친다.
- ⚠️`^2026-` 처럼 연도를 고정하지 마라 — 해가 바뀌면 «0건»이라는 거짓 안심이 된다.

**2. 킷 저장소 동기 확인** — 위 자동 조회의 `--branch` 줄에 `ahead`·`behind` 가 있으면 그것부터 알려라. 변경 파일이 남아 있으면 «미완 작업»으로 취급하고 무엇인지 먼저 보여라.

**3. 배포 3곳 어긋남 확인** — 킷 HEAD 와 배포처 main 이 갈렸는지는 **묻기 전에는 조회하지 마라**(무거운 조회다). 사용자가 «동기 상태»를 물을 때만 `git log origin/main -1` 과 배포처 `glab api` 로 확인한다.

**4. 담당 구분** — 위 카드 목록 중 **다른 세션(bnsone·파일럿 세션) 몫**이 대부분이다. 킷 세션이 손댈 것은 ⑴킷 저장소 파일 ⑵킷 마찰 ⑶사용자가 명시적으로 시킨 것뿐이다. **남의 카드를 열어 ㉠ 결정거리를 만들지 마라.**

**5. 번호 선택지로 제시** — 3~5개, 각 줄에 «무엇이 달라지나». 마지막 줄은 `▶ 다음: …` 로 사람 몫으로 끝낸다.

**보고 서식**: 3구획(㉠지금 정할 것 ㉡나중에 ㉢알아만 둘 것) — **빈 칸도 "없음"**. 존댓말. 표·군더더기 금지, 5줄 이내.
