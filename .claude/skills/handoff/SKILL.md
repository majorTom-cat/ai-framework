# /handoff — 세션 인수인계

> ★**이 파일은 킷 원본 `3-starter-kit/.claude/skills/handoff/SKILL.md` 의 «사본»이다**(킷 세션이 실제로 읽는 자리는 루트 `.claude/skills/` 뿐이다). **원본을 고치면 같은 커밋에서 이 사본도 맞춰라** — `/overhaul` 과 같은 부류다(`AI-CONTEXT.md` §3). 내용이 갈리면 킷 세션만 옛 절차로 인계하게 된다.

목적: 다음 세션(같은 사람의 새 컨텍스트)이 5분 안에 이어갈 수 있게. **GitLab엔 아무것도 남기지 않는다**(조회만).

★**새 파일을 만들지 마라.** 인계는 **①다음 세션에 직접 밀어 넣기 ②`CLAUDE.local.md` 머리 절 갱신** 둘로 끝낸다.
경위: 2026-08-26 오너 지적 — *"파일을 만들 필요도 없고 쓸데없는 파일 늘리기 싫은데 계속 만드네. 그냥 알아서 다른 세션이 인계만 하면 되는 거잖아."*
`~/orca/projects/`에 `*-인수인계-*.md`가 15개 넘게 쌓였고 읽히는 건 늘 최신 하나뿐이었다. **옛 파일은 지우지 마라**(과거 기록) — 새로 만들지 않을 뿐이다.

1. **사실 수집(조회만)**: `git log origin/main --oneline -8` · `git status --short` · `glab mr list` · 내 열린 카드(`glab issue list --assignee=@me`)의 진척(`task_completion_status`) · 이 세션에서 머지한 MR 번호·파이프라인 상태 · 로컬 잔재(`docker ps`, `lsof -ti tcp:3000`, `git worktree list`).
   - ★★**옛 머리 절을 «자료»가 아니라 «검사 대상»으로 읽어라.** `CLAUDE.local.md` 의 `## 🔴 세션 시작 시` 를 먼저 열고, **거기 적힌 사실 주장을 하나씩 지금 다시 조회한다**(숫자·해시·«열린 MR 0건»·«미완 없음»·카드 진척 전부). **다시 조회해서 맞은 것만 새 절로 옮기고, 조회가 안 되거나 틀린 줄은 옮기지 말고 버려라.**
     경위: 2026-09-10 오너 지적 — *"이상한 옛날 판정을 그대로 인계해서 새 세션도 망가지는 일 많이 겪었어."* 그날 실측: 옛 머리 절의 마찰 건수·열린 MR 건수·카드 남은 항목이 **셋 다** 이미 틀려 있었다. 「추정 금지」라는 **금지어는 이미 있었는데도** 그랬다 — 금지어는 안 지켜지고 **절차만 지켜진다.** 그래서 «다시 재라»를 단계로 박는다.
   - ★★**«다른 세션·다른 폴더가 이미 했다»는 주장도 사실 주장이다 — 그 폴더에서 직접 재라.** 2026-09-10 실측: 인계문은 배포처 작업 폴더가 「`!457` 까지 감겼다」고 했으나 실제로는 **16커밋 뒤져** 있었고, 그날 머지한 확인 창 완화 4건이 **하나도 도달하지 않은 채** 두 세션이 옛 장치로 일하고 있었다. 남의 진행 상황을 옮겨 적을 땐 `git -C <그 폴더> rev-list --left-right --count HEAD...origin/main` 처럼 **그 자리에서 값이 나오는 명령**을 함께 적어라.
   - ★★**세는 잣대는 «손으로 칠 수 있는 명령 통째로» 적어라 — 정규식 조각만 넘기면 다음 사람이 거짓 0 을 본다.** 2026-09-10: 인계문의 `grep -c '\?"'` 를 그대로 쳤더니 **실물 27건이 0** 으로 나왔고(`-E` 가 없어 BRE 에서 `?` 가 리터럴), 그 0 을 믿고 오너에게 「탈날 것 없다」고 오보했다. 정본 = `grep -cE '\\?"' <설정파일>`(`_reference/asks.md`).

2. **내용 정리(머릿속·초안은 스크래치패드에만)** — 절 4개.
   ★★**모든 사실 문장 끝에 근거를 붙인다 — 두 형태뿐이다**: `[확인: {무엇으로}]`(명령·URL·파일:줄) 또는 `[미확인]`.
   - **`[미확인]` 은 §2 «당장 할 일» 에 «확인할 것»으로 자동 승격**한다 — 인계에 남되 **사실 행세를 못 한다.**
   - 근거를 못 붙이겠으면 **그 문장을 쓰지 마라.** 「아마」·「~일 것이다」·「됐을 것」은 `[미확인]` 도 아니다 — 삭제 대상이다.
   - 왜 표기까지 강제하나: 지금까지 **틀린 문장과 맞는 문장이 똑같이 생겨서** 다음 세션이 구분할 방법이 없었다. 다음 사람이 의심할 자리를 **글자로** 남기는 것이 이 규약의 전부다.
   - §1 지금 상태(미완 작업 유무를 첫 줄에 굵게 · main 해시 · 머지 MR **링크** · 카드 진척 · 로컬 잔재)
   - §2 당장 할 일(번호 순 · **사람이 해야 하는 것**을 맨 위에 · 화면 제안 금지 같은 상시 제약 병기)
   - §3 함정(**이번 세션에서 실제로 밟은 것만** — 추측 금지. 무엇을 하다·무엇이 났고·정본 위치)
   - §4 결정·대기(오너 결정은 날짜+근거 위치 · 기획자 회신 대기 목록)

3. **직접 전달(1순위)**: `ListAgents`로 같은 프로젝트의 **켜진 세션**(예: `bnsone-f2 [ref]`)을 찾아 `SendMessage`로 §1~§4를 보낸다 — 요약이 아니라 그대로 밀어 넣는다.
   ★**수신자를 이름 유사성으로 고르지 마라** — 최근 그 주제로 주고받은 세션의 `from`을 쓴다(실측: 이름으로 골라 2회 오배송). 켜진 세션이 없으면 4단계만.

4. **`CLAUDE.local.md` 머리 절 갱신**: `## 🔴 세션 시작 시` 절의 «최신 상태·함정» 요지를 **덮어쓴다**(누적 금지 — 파일 하나가 늘 현재를 가리킨다). 8~12줄. 새 파일 만들기 금지.

5. **메모리 후보**: §3 함정 중 **다음 프로젝트에서도 반복될 것**만 `~/.claude/projects/.../memory/`에 1건씩(있으면 갱신). 이번 세션 한정 사실은 넣지 않는다.

6. 보고: **어느 세션에 보냈는지** + §2 첫 3줄만 채팅에. 마지막 줄 `▶ 다음: 새 세션에서 /todo`.

7. **자기점검 — 보내기·저장 «전»에 한 번**: 새로 쓴 §1~§4 와 머리 절을 훑어 **근거 표시(`[확인:` 또는 `[미확인]`)가 없는 사실 문장이 하나라도 있으면 그 줄을 다시 써라.** 하나도 없어야 통과다. ★이 점검을 «보낸 뒤»에 하지 마라 — 이미 남의 컨텍스트에 들어간 뒤다.

금지: **새 인수인계 파일 생성** · GitLab 링크 대신 번호만 쓰기(링크 필수) · "아마 됐을 것"류 추정 · 이전 내용 통째 복사.
★**옛 머리 절의 사실 문장을 재조회 없이 «한 글자도» 옮기지 마라** — 문장을 손질해 옮기는 것도 복사다(1단계). 옮길 근거가 없으면 **버리는 것이 맞다**: 다음 세션은 «없는 정보»보다 «틀린 정보»에 훨씬 크게 다친다.
